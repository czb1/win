## 维护规则

- 后续业务代码、游戏配置或策略变更，必须同步更新对应模块的设计和变更记录。
- 变更记录保留“策略、设定、原因、经验教训、验证”五项；区分计划、实现事实与验证结果。
- 已有设计与测试只在 [1.0 版本设计文档](../1.0版本设计文档/README.md) 中追溯；继承策略必须对照 v2.0 规范核验后再写入本阶段结论。
- 不新增四模块以外的分散设计文档。目录 README 只负责导航、版本说明和状态。
- 发布包从 `v2.0.0` 起编号；发布编号本身不证明新功能已经实现或验证。
