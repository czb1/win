# 经济模块设计（v2.0 / 32进16）

状态：新赛制适配仍有待办；2026-10-10 改为第一天先建齐三炮、余款只买BOSS，第二天起升级炮塔；机器人采购取消防御完工门槛。尚未完成多日对战或完整 v2.0 适配验证。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 经济设计](../1.0版本设计文档/经济.md)。

## 目标与边界

梳理矿石、价格、采购与召唤使用的变化；统一白天防御采购预留和余款使用。建设与回防见防御模块，可控机器人攻击见战斗模块。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 矿区元素新增 `remain`，范围1～10，其他中立元素为null | 解析与选矿依据、耗尽后的目标失效处理 |
| 矿区按左下到右上的分界线分半区 | 核对矿区划分和刷新数据，不能使用基地朝向代替半区规则 |
| 捣乱鬼 `destroy` 连续4回合，每回合执行；未执行即清零 | 破坏目标、进度与中断；成功后该半区该类矿10回合不补刷 |
| 围墙修复包15，眩晕法宝与范围炸弹50，任务用品10 | 核对预算、采购门槛和历史成本记录；实际采购继续核对商店报文 |
| 四档召唤令价格15/20/70/120，生成本方可控机器人 | 第一日三炮建齐后余款只买BOSS；第二日起按已安排防御采购后的余款以 BOSS→大→中→小选择，按报文现价采购，无防御完成门槛 |
| 召唤令 `use` 必须指定合法 `targetPos`，每天最多10张 | 位置限制、重复待生成位置、旁移和夜间统一生成的边界 |

## 关键设定与原因

- 批量卖矿、保留施工石料、升级券交付等1.0策略先保留为继承候选；新价格和矿区机制可能影响其门槛，需要逐项核验。
- 捣乱鬼无背包，不能套用工人的采矿、交易或物品运输职责。
- 第一日先保留三座配置炮塔的施工资金；三炮建齐后普通采购暂停，余款只买BOSS，炮塔升级券的购买和使用推迟至第二日。第二日起按可执行防御采购预留资金，再消费余款；机器人购买只要求可用动作、可达商店、商品现价和背包空间，不检查墙/炮等级、缺口重建、夜修库存、人物健康或买后回防期限。升级券等普通配送继续核验交付与回防时限。

### 2026-10-10 - 取消机器人采购门槛，第一天三炮之后全部余款买BOSS

- 策略：按用户要求，取消机器人购买的炮塔/围墙等级、规划围墙完整、缺口重建、夜修备包和人物健康门槛；不再因无法买后回防或找不到召唤落点而拒绝购买。白天、每日召唤名额和已持有召唤令只影响部署，不能挡住合法采购；夜间先安排炮手攻击，再允许空闲角色购物。
- 设定：默认三座炮塔全部建成后，第一日BOSS采购排在普通任务续接和回防之前。第一日不买或使用炮塔升级券，三炮建齐后暂停其他普通采购，剩余金币只买BOSS，不足一张BOSS的钱留存；第二日起恢复炮塔升级和实际可执行防御预算后的余款消费。自定义较少炮塔的配置以配置数量为准。
- 设定：BOSS批量数量由当前余款和买手空位决定，不再按召唤名额或剩余白天裁剪；每天最多10次约束仅用于逐张 `use`，未使用的召唤令留在背包供后续部署。默认120单价下，668金币可以买5张、剩68。已有购物任务继续保留商店和数量上限，移动时按整批成本预留，不重复支出同一批款。
- 原因：用户将第一天进攻提前到三炮建成之后，并明确要求防御尚未升级也使用余钱购买机器人。仅删除 `defenses_ready` 检查仍会被已有任务、采购预留、人物健康或回防期限挡住，因此需一并调整购买入口和第一天调度顺序。
- 经验教训：购买召唤令与部署机器人是不同动作；每日使用上限与召唤位置合法性不应阻止囤积合法购买的召唤令。第一日禁止升级需覆盖新采购、旧采购任务以及背包已有券的使用。
- 验证：与最新main（c2c5c92，首日正面墙防护）整合后，默认快速检查911项全部通过，耗时36秒，10项仿真未运行；新增第一日三炮施工优先、禁买/禁用升级券、旧任务与回防让位、宝藏不挤占BOSS余款和第二日起恢复升级等检查。当前环境只有Python 3.12.14，使用仓库`.venv`，Python 3.11验收交由CI。不运行多日仿真、独立策略基准或官方对战，快速通过不代表多日策略表现。

### 2026-10-10 - 余款BOSS批量采购，逐张召唤仍保留回防时间

- 策略：沿用三炮满级、迎敌墙三级、其余规划墙至少二级、缺口重建及夜修备包完成的余款准入条件。先预留可执行防御采购和急救资金，再按当前商店价格选择可负担的最高档机器人。BOSS可一次购买多张；其他档位保留既有单张回退。背面落点及夜间攻击策略见战斗模块同日记录。
- 设定：BOSS数量同时受余款、背包空格、当天十次召唤剩余名额和完整往返期限限制。采购一回合，每张召唤令单独使用一回合，全部使用及实际夜间岗位返程后仍保留配置安全余量；免费商品同样受上限约束。默认120金币且没有其他预留、容量和时间限制时，492金币可一次买4张，留下12金币；这不是现场492金币必然全可支配的断言。
- 设定：去商店的移动计划按整批成本预留金币，续接时保持同一商品、商店和数量上限；新的防御需求、余额、空间或时间变化可缩小数量，不扩大已接受采购批次。持有召唤令先逐张使用，已预约位置不重复使用。采购日志新增数量、单价和总价以供现场核对。
- 原因：逐次购买单张召唤令会增加购物往返或购买动作，不能充分利用较早出现的余额；把批量购买视为一回合内批量召唤又会错误低估时间。当前附件只有单位决策，缺少 `spending_plan`、原始建筑等级、商店与背包快照，因此尚不能确定现场未采购的门槛。
- 经验教训：余额、可消费余款和能及时部署的战力是不同条件。保留已有防御、备包和回防限制，避免为清空余额牺牲生存；异常、临时堵路或新增急救可能打断已经购买的部署，实战仍需观测。
- 验证：新增快速检查覆盖492金币四张BOSS、实际价格、防御预留、容量、每日名额、逐张使用时间、免费商品、整批行程预留和续接缩量；与战斗模块共新增14项。纳入最新主分支日志功能后，`.venv/bin/python tools/run_checks.py` 默认快速模式通过870项，失败／错误为0，耗时33.23秒，省略10项仿真；`git diff --check`通过。本地无Python 3.11，使用项目 `.venv` 的Python 3.12.14；不增加依赖，GitHub CI仍使用3.11.10。未运行多日仿真、独立策略基准或官方对战。

### 2026-10-09 - 提前备包与交付，避免白天结束积压可用金币

- 原因：现场第六天售矿后金币达到581，后续未再采购。备用修墙包使普通买手被排除；墙券交付直到固定 tick 60 才改用近处目标，部分批量预算把别的工人的旧券交付也计入新买手路线；健康基地和非 BOSS 召唤被硬门槛挡住。低于500才白天修墙又忽略了一批已经明显受损的三级墙。余额只是这些条件共同阻断的结果，不能单靠降低一个阈值解决。
- 策略：取消普通买手的“持有任意 WallFixer 即排除”条件；背包容量、夜修角色、已接受工作、失败冷却、道具需求和共享金币仍统一校验。已有券在所有工人间去重，但只有本买手自己的已付墙券才计入其后续交付路线，同回合移动采购与原地购买均声明商品占用，避免双工人重复买同批道具。
- 策略：火力达到三级后立即启动有钱且赶得及返回的备包行程；备包目标继续使用原有夜间自适应函数，第六天至少9包。另加可达三级墙的白天预防修复用量，受到背包容量和防御预算约束；夜间库存不得被普通白天预防修复消耗。已足额备包的守墙工人按真实回家时间释放白天工作，临近夜晚仍回内侧墙位。
- 设定：第4天起，火力已全三级时提前使用同阶段最近的可交付墙券批量预算，保持前墙二级、全墙二级、前墙三级、其他墙三级的实际使用顺序。采购量取需求、空位、资金与完整交付时限共同允许的数量，不能因排在前面的远墙单独挡住同阶段近墙。炮手必须返回分配的确切炮位；完整围墙内无炮位职责的运输工返回可达、安全且避开炮位的内圈；稀疏布局沿用原回防目的地。不得以火力全三级为由免除真实炮手返岗。
- 设定：白天预防修复限定第4天起且火力全三级，墙血量低于该级上限80%且缺血至少300；低于500的原有紧急修复继续保留。升级券能够合法使用或采购时优先升级回血，三级墙和不能升级的墙才用包。夜间风险阈值和既有自适应库存学习不变。
- 策略：健康基地在完整围墙已建成、无待恢复缺口且火力全三级后可升级，不再等待每面墙全三级。机器人准备前计算真正可执行的墙、基地等下一批采购资金；同商品备选只预留最大批量一次，急救药预算只扣一次，已经移动或购买的道具沿用账本预留。机器人采购续接每回合重新检查防御预算，并排在普通采购/施工续接之后，资金条件变化即释放旧采购任务。
- 设定：召唤准备要求计划围墙完整且均至少二级、前墙三级、计划炮塔齐全且全三级、没有待恢复缺口、夜间备包已持有或有可执行资金预留；允许侧后墙尚未全三级。余款按 BOSS→大→中→小选可负担且未失败的商品，使用已持有的最高档令牌优先；每次购买一张。仍检查合法生成位置、待生成去重、每天10张上限、先锋任务、急救、空间、移动退避及买后使用/返岗时限，固定商店与商品的采购任务连续性保留。
- 经验教训：要把资金转成战力，必须同时解除错误的买手排除、提前启动可完成的行程并保留真实岗位；不能为了清空余额取消夜间防御。预算不能重复扣急救款或同商品备选，也不能把别人的配送当成本人的路线。新增 spending_plan 日志记录可用钱、可执行预留、余款、商品、买手、最终账本余额与无法采购原因，便于区分没钱、无路、已被占用和来不及返回。
- 验证：新增聚焦单回合与边界检查，覆盖备用修墙包买手、外来券去重与路线隔离、同阶段近墙、炮手/内圈返程、早间备包与白天修复追加量、足额备包解除早期锁定、80%与缺血边界、夜包保护、升级代替回血、基地放行、前墙/缺口/库存召唤门槛、双工人重复采购、预算去重、机器人续接让位防御、四档价格边界及日志/重复请求一致性。同步 main 的日志精简改动后，使用本地现有 Python 3.12 的 .venv 执行 tools/run_checks.py 默认快速模式，832项通过、0失败、0错误，省略10项仿真；远端 Python 3.11 CI 结果见本次 PR。未运行完整回放、经济基准、多日模拟或真实对战，不能据此声称581一定花完或实战收益已经验证。

### 2026-10-09 - 夜间身份不抢白天工作，区分暂时堵路与回防期限

- 策略：默认双火箭/加特林配置保留存活炮手和另一工人的夜间分工，白天仍执行原任务优先级和连续任务协议。岗位属于谁不再随白天路径和距离变化；进入回防/备包阶段仍按实际行程预算判断，不能把“白天自由生产”解释为取消夜前准备。
- 设定：守墙工人实际无回家路径时，仅在 economy_rounds 之前、移开友方英雄后存在结构路径且剩余白天大于该路程加两倍 return_margin 时解除本回合的回防锁，不释放岗位。障碍物/敌人造成的永久无路及晚期无路仍走原来的保守处理。
- 设定：早间售矿和任务续接预算的最后一段返程可按友方英雄会让路估算；去商店/矿点/施工点的第一段仍检查当前占用，真实移动从不穿过占据格，现有返程安全余量保留。到 economy_rounds 后不使用该估算豁免，避免临近夜晚承诺不可完成行程。
- 原因：固定岗位后，原售矿工人的炮位仍可能被开拓者暂时占住；若把该瞬时占位当成未来整段返程永久不可达，仍会取消售矿并改派采矿，重现来回走。
- 经验教训：未来返程预算和本回合移动合法性必须分开；让路协调不能靠给人物下发穿人指令。仅解除锁定不足以保证任务连续，还要核对后续任务的返程判定。
- 验证：新增“外出售矿持续、开拓者离开通道后内圈施工恢复”的连续请求检查，以及早晚边界、真实墙阻挡和未来返程估算不放行受阻去程的检查；按现场快照核对390～393回合的分工和指令。采用 Python 3.11 快速校验；未运行多日模拟，不能据此断言实战收益。

### 2026-10-09 - 白天任务续接与零散售矿往返约束

- 策略：基于最新 main（含双火箭、加特林与 BOSS 召唤），在普通黄昏清算、BOSS 采购、recovery 和买手/建造手重分配之前续接上一回合实际提交的工人任务。固定当前矿点、售矿点、采购物品与商店、交付建筑或施工格；价格评分、另一工人变得更近、tick 60 的最近升级目标排序，不再独自打断仍可完成的任务。守墙工人的回防/备包仍先做完整期限判断，其采购路线也优先续接当前商店。
- 设定：采石达到本次施工批量即释放，经济采矿达到售矿批量或准备阶段期限即释放，短途备用采矿完成一次采集即释放；采购、建造、道具使用完成后不留下职业锁。每回合重新核对库存、钱、目标类别/级别、矿石 remain、失败冷却、站位预约和返程；目标失效或路线/期限不再可行时同回合回到原调度与本地生产降级。仅保存实际被账本接受的动作对应任务，死亡、跨日和夜间清理续接状态。
- 策略：急救、危急基地的已有升级券、受损墙的已有修复/升级道具、真实围墙缺口与已锁定回防可以抢占普通工作；既有补墙工人继续当前采料/施工目标，避免补墙模块每回合再次选格。续接采购先预留批量金币，再续接施工，防止建炮支出与采购中的缺炮预留重复计算。夜间角色、炮火与修墙阈值不作调整。
