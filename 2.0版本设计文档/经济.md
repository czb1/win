状态：新赛制适配仍有待办；2026-10-08 已修复白天空动作冲突，并实现敌方半区矿石破坏调度。尚未完成多日对战或完整 v2.0 适配验证。

## 目标与边界

梳理矿石、价格、采购与召唤使用的变化。建设与回防见防御模块，可控机器人攻击见战斗模块；本次不调整采购顺序和资金分配。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 矿区元素新增 `remain`，范围1～10，其他中立元素为null | 解析与选矿依据、耗尽后的目标失效处理 |
| 矿区按左下到右上的分界线分半区 | 核对矿区划分和刷新数据，不能使用基地朝向代替半区规则 |
| 捣乱鬼 `destroy` 连续4回合，每回合执行；未执行即清零 | 破坏目标、进度与中断；成功后该半区该类矿10回合不补刷 |
| 围墙修复包15，眩晕法宝与范围炸弹50，任务用品10 | 核对预算、采购门槛和历史成本记录；实际采购继续核对商店报文 |
| 四档召唤令价格15/20/70/120，生成本方可控机器人 | 不沿用初赛的增加对方浪潮语义；采购价值和使用时机待设计 |
| 召唤令 `use` 必须指定合法 `targetPos`，每天最多10张 | 位置限制、重复待生成位置、旁移和夜间统一生成的边界 |

## 关键设定与原因

- 批量卖矿、保留施工石料、升级券交付等1.0策略先保留为继承候选；新价格和矿区机制可能影响其门槛，需要逐项核验。
- 捣乱鬼无背包，不能套用工人的采矿、交易或物品运输职责。
- 破坏和抓捕的优先级尚未确定；本次不预设新角色策略，也不修改旧采购预算。

## 变更记录

### 2026-10-08 - 仅破坏对方半区矿石

- 策略：捣乱鬼独立前往安全、可达的敌方半区矿石；优先缩短安全路线，同等路程优先破坏剩余矿量较大的矿石。锁定安全目标直到矿石消失、类型变化、路线失效或威胁接近，连续四回合逐次提交 `destroy`，不参与采矿、交易、施工或道具使用。
- 设定：按地图左下角 `(0,0)` 至右上角 `(width-1,height-1)` 的对角线计算 `y*(width-1)-x*(height-1)`，以实际基地 2×2 占地的中心所在半区判定本方，严格相反符号才允许破坏。选矿和最终指令账本均执行该限制；缺少基地、基地落在分界线上、矿石落在分界线上或 `remain<=0` 时拒绝破坏，不用阵营名、X轴左右或最近基地距离替代矿区规则。缺失 `remain` 的旧夹具仅表示矿量未知，不改变半区约束。
- 设定：上回合反馈为合法、同一位置与同类目标矿石仍存在且回合连续时才记录引导回合数；不把合法性反馈当成成功毁矿。任一回合没发破坏、反馈非法、移动、跳回合、死亡或目标失效均清零。本次只依据下一回合矿区报文发现目标消失，不在本地伪造十回合不补刷规则；补刷由判题器负责。白天新引导必须能在天黑前完成，已有引导按剩余回合检查。
- 原因：双方矿区分别补刷，误毁本方矿石会直接损害本方采集和经济；捣乱鬼没有背包，也不应消耗原有采购或建设预算。
- 经验教训：矿区归属需要处理矩形比例和双方换边；矿点坐标沿用、矿种变化和合法动作反馈都不能单独证明同一矿已被破坏。危险出现时撤离优先，不能强制补足四次指令。
- 待确认：任务书 §4.1 未说明恰好处于分界线上的矿格归属或判题器的格点取整实现；本次保守排除这些格点，并保留原始规范，未猜测边界归属。
- 验证：新增最终账本拒绝本方／边界矿、矩形与镜像换边、缺少／对角线基地、矿剩余量、连续四回合、失败清零、耗尽换矿、死亡复活、黄昏截止和旧炮手独立调度检查。使用 Python 3.11.17 的默认快速校验，540项通过，失败与错误均为0，跳过10项仿真；未将历史回放结果作为新赛制收益证明，未执行经济基准或真实比赛。

- 设定：保留接口矿石 `remain` 和角色 `isDriving` 原始字段；记录采矿评分及0.65目标保留阈值、出售数量／价格／是否赶得及回防，以及动作预留金币。接收原始新字段不等于现有算法已经使用这些字段。
- 原因：录像看到未采矿／未卖矿或目标切换时，需要区分路线、背包、售价、期限、回防和动作校验的原因。

### 2026-10-08 - 白天无效锁定与空动作降级

- 策略：保留原采购、建设、补墙和回防顺序，在它们都未发出动作时才尝试短途储矿；当天已卖矿和 tick 40 不再单独禁止空手工人利用剩余白天。已有晚期库存且无法按时出售时仍先带回防区，不重新开启远距离采矿行程；强制出售失败不转采矿。
- 设定：备用矿目标距工人最多三格，前往采集站位最多两步，逐一检查真实采集站位到实际分配炮位/回防区的完整返程；移动、一次采集、返程和五回合安全余量必须全部装入剩余白天。持有晚期库存或已锁定回防的工人只尝试邻接采集，避免返回后又外出。矿点失败、移动退避、背包预留、本回合站位预约和敌对机器人危险区域仍会限制候选。
- 策略：修理工无路时保留职责，允许不改变站位的邻接工作；空包无钱而已经回到内圈时可做能按时返回的内圈短任务。未完成的短途储矿逐回合重验，不被空手召回打断；采集无法继续时返回内侧墙位。持包就位的修理工维持合理待命，不扩大普通生产。最后检查与升级券就地交付不依赖 recovery 的连续空闲次数、模型回包或先锋任务状态。
- 设定：回血包购买/移动指令被账本拒绝时，本回合不再预留对应金币和背包格。只有可执行的备包计划保留槽位；有金币但无可行商店路线时，不用原始总金币推定采购空间需求。当天守墙寻路只避让当前有效共享炮位，不避让失效的历史炮位。
- 原因：旧 prepare_watch 的锁定返回值不保证已有动作，后续 workers/recovery 又排除 returning；每日售矿和准备状态配合 tick 40 禁采会令工人无事可做；失败采购还可能在资金和容量两处排除其他工作。
- 经验教训：保留职责不等于禁止本地动作；“已经出售”“处于准备阶段”“已分配回防”不能替代本回合任务可执行性检查。临时无路时不能用另一次长途任务制造往返，真正有包待命和无法生产的空动作必须分别解释。
- 日志：未行动或使用最终降级的工人记录 daytime_role、lock_reason/reason、idle_reason/fallback、day_left、return_steps，以及持包/空间。普通主流程已发出的动作不被覆盖；没有安全候选时明确记录原因，不能声称每回合必有动作。
- 验证：新增单回合与边界检查，覆盖镜像空包守墙、连续两回合堵路不游走、拒绝备包的资金/容量释放、邻接道具优先、实际炮位返程、39/40 和返程截止、强制出售失败、准备记忆残留、危险区域、有效炮位、最后白天回合和夜间无降级。既有“tick 40 强制停止备用采矿”断言改为实际返程截止；已有库存回家/次日销售断言保留。使用 Python 3.11 的 tools/run_checks.py 快速模式；详细数量与最终结果随提交交付。未执行整场回放或策略基准，历史夹具仍非完整 v2.0 对战验证。
- 范围：本次只改白天调度和生产降级，不调整夜间炮手/修理工分配、夜修阈值和备包目标，不加入捣乱鬼、小车或召唤策略。
