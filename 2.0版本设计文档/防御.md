# 防御模块设计（v2.0 / 32进16）

状态：围墙布局与升级顺序已按 v2.0 调整，其余新规则适配及实战表现仍需逐项验证。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 防御设计](../1.0版本设计文档/防御.md)。

## 目标与边界

默认以完整围墙保护基地、保留正对炮塔的唯一通行口，并维护迎敌侧优先的墙体升级顺序。开拓者每晚轮流操作三座火箭；捣乱鬼黄昏在缺口旁待命，夜晚守口并为工人进出及炮手回防让路。工人继续采矿与第四天起的守墙策略。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 每队四角色，开拓者、工人、捣乱鬼血量均500 | 单位枚举、治疗门槛、职责分配与炮手补位的历史假设 |
| 阵亡后下一个游戏日白天第1回合复活，背包保留 | 死亡状态、次日补位与回防记忆 |
| 捣乱鬼破坏引导期间全图可见，其余时间按视野规则 | 接收敌方可见单位、近距离抓捕与移动占位 |
| 小车作为 `challengerVehicle` / `defenderVehicle` 下发，角色带 `isDriving` | 小车归属、驾驶状态及任务奖励生成时间 |

| 敌方小车格不可驶入，任何小车格不可建造 | 寻路占位与建设合法性 |

## 关键设定与原因

- 默认围墙覆盖距基地完整 2×2 占地两格的矩形周界：二十格周界中建十九格，侧后方留一格入口。迎敌六格及原两翼六格坐标保持原位，补齐两侧翼格与后方五格；入口不占用旧十二格墙，布局不随人物或建筑占位漂移。
- 普通墙体先升迎敌侧二级，再升其他侧二级；完整周界建成且所有墙达到二级后，按原有迎敌侧中心向两端顺序升三级，随后侧面与后方升三级。所有侧墙等级上限统一为三级；重建、采购、使用、恢复动作和基地升级判断使用同一上限与阶段约束。
- 侧面入口不进入建设、缺口识别和补墙计划，临时经过的角色（包括捣乱鬼）不构成永久封路。守墙巡逻范围以蓝图的四边为界，不通过入口或后方缺口巡逻到墙外；人物占住公共操控格时允许先经唯一入口退让，再离开回防通路，目标预约使炮手等待，避免换位与争抢同格。
- 三座火箭使用同一公共操控格，存活开拓者每回合按实际冷却轮射其中一座，避免每座炮都占用工人。开拓者阵亡时沿用已有存活工人补位；第四晚起从空闲工人中保留固定守墙身份。
- 唯一入口采用局部坐标 `(-2, 1)`，内侧第一格 `(-1, 1)` 是第三座火箭，公共操控格为 `(-1, 0)`；不因人物占位改变炮位或增加缺口。捣乱鬼夜间占口吸收伤害，实际机器人攻击对象仍由对方指令和判题器决定。
- 捣乱鬼黄昏回程包含实际步行与余量，最后白天回合在外侧斜邻格待命；夜间让路根据英雄真实失败寻路与本回合已接受的移动决定。只临时移除守口捣乱鬼占位核对连通性，不移除其他障碍或危险区，不把假设路线作为合法移动提交；本回合先让路，下回合观测空口后通行，经过者未离开时不抢回缺口。
- 显式混合阵型继续保留固定加特林工人、独立站位与弹道修复回归。显式布局坐标保持配置权威，只有唯一且正对炮塔的入口才启用捣乱鬼守口；建造区域仍待官方核验。
- 1.0的围墙、后角炮台和修墙设计仅作为继承记录；新角色和血量变化不自动授权修改建设顺序或防守职责。
- 小车移动和步行需要区分，不能无条件把每次移动按两格计算。
- 任务书第二格碰撞后的实际停留位置存在原文歧义，见 [本阶段待确认事项](../比赛文档/v2.0-32进16/README.md)。核实前不写入确定的移动结算方案。

## 变更记录

### 2026-10-09 - 白天守口与破坏矿场切换导致的往返堵塞

- 策略：白天是否接管捣乱鬼统一依据剩余时间、实际返程步数与回防状态判断；站在唯一入口也必须经过同一返程期限检查，白天初始不因当前位置在入口就转入守口。
- 设定：本日尚未结束的 `yield_until` 在准备守口阶段同样生效，让路等待时不再交给破坏调度抢回入口。临时让路保留目标矿石，实际回防／夜间守口才清除目标；任何让路或回防中断仍清零连续破坏进度，遵守 v2.0 连续四回合规则。临时白天让路单独记录为 `imp_daytime_gate_yield`，黄昏站位与夜间守口继续沿用原日志原因。
- 原因：第780～782回合捣乱鬼在 `(33,10)` 与 `(34,9)` 间交替执行 `imp_dusk_staging` 和 `imp_approach_enemy_mine`。原返程判断只覆盖“不在入口”的角色，在入口时立即清空目标并侧移，侧移后又释放到破坏调度。入口在占位与下一回合移动预约间持续不可达，墙内工人不能补货，墙外工人无法验证返程而空闲。
- 经验教训：职责切换必须以时间和持续状态判断，经过入口不代表开始回防；让路记忆需要在准备阶段与最终移动阶段共同检查。临时让路保留的是任务目标，不能保存被打断的连续破坏进度；实际移动仍使用当前占位与预约，不放宽碰撞校验。
- 验证：新增四项默认快速检查，覆盖早晨在入口／旁侧的职责释放、现场快照中三次有限请求不往返、捣乱鬼离口后两工人恢复动作、白天让路等待／目标保留／进度清零与等待到期。现场回归夹具仅取第780回合必要请求字段并去除队名和原队伍标识。验证命令为 `python tools/run_checks.py`，由仓库既有 Python 3.11.10 GitHub CI 执行，结果见本次提交检查；本地仅提供 Python 3.12，未替代仓库规定的3.11运行环境。未执行完整多日仿真、独立基准或官方对战。

### 2026-10-09 - 相邻敌方捣乱鬼顺手抓捕，不追击

- 策略：正常动作分配后，仅空闲工人／开拓者或正在普通采矿的工人，向当前可见的八邻格敌方捣乱鬼提交一次 `catch`。不为抓捕移动、寻路或保留追击目标；敌人跑开、消失或死亡后继续己方工作。
- 设定：同一敌人与己方英雄持续相邻期间全队最多尝试一次；两次抓捕至少间隔5回合，每回合最多一名角色抓捕，优先空闲角色。普通采矿最多暂停一个回合并保留原矿点与工作记录；采墙材、建造、交易、用药／交付、任务、回防、操炮、守口退让及明确持有动作不被替换。已有守墙修复指令优先，空闲守墙人可以顺手抓捕。己方捣乱鬼保持原有生存与守口调度，避免互抓同归于尽。
- 原因：用户要求遇到身旁敌方捣乱鬼时顺手抓一下，但不能因反复抓捕或追击浪费生产、防守回合。v2.0任务书 §4.4 与接口 §2.3 规定 `catch` 作用于八邻格，成功获20金币，目标阵亡；下发动作不能作为成功证据，本次不预支抓捕收益。
- 经验教训：视野内、引导全图可见与实际相邻是不同条件。抓捕前必须使用本回合位置，不能沿用历史敌人坐标；持续扑空时恢复采矿，接触重置仍受全队间隔约束。必须保留被暂停的采矿任务，且上回合 `catch` 不能计作成功采集。
- 验证：18项新增聚焦检查通过，覆盖八邻格、逃离／视野消失、单次接触与间隔、多人去重、采矿续接、关键动作保护、同回合缓存和正常夜间轮射。项目 `.venv` 的 Python 3.12.14 执行 `.venv/bin/python tools/run_checks.py` 通过757项快速检查，失败／错误为0，耗时24.38秒；本地未提供Python 3.11，既有GitHub CI使用3.11.10。省略10项仿真与独立策略基准，未进行真实对战或多日策略验证。

### 2026-10-09 - 三火箭共享开拓者与捣乱鬼守口让路

- 策略：默认配置恢复三座火箭，由开拓者在公共格按冷却轮射；十九格围墙仅保留原侧口，向内第一格为第三炮塔。捣乱鬼按回程预算提前回防，最后白天回合站在缺口外侧斜邻格，夜间占口承伤；工人采矿、修墙回城和开拓者回炮位时先让路。
- 设定：守口角色先从破坏调度中保留，待工人决策结束再决定移动。失败寻路仅为识别捣乱鬼占位而临时移除其格，返回值和真实移动校验保持原占位约束；所有临时修改均恢复。侧移格排除规划建筑、操控岗位和预约，重新验证等待者通路；两回合让路记忆、当前缺口占位与移动预约共同防止提前归位或互换碰撞。通行先于守口，外侧等待格若也阻断队友路线，同样继续退让；校验的是本回合实际落脚格。正常情况下优先外侧斜邻格，受矿石或NPC挤压时才选其他外侧空格。预算耗尽时保留合法的相邻退让作为回退。不额外拆墙，不覆盖显式坐标；没有唯一朝炮塔缺口的显式阵型沿用原捣乱鬼行为。
- 原因：加特林在封闭围墙下受基地、城墙与角色弹道阻挡，且占用额外工人。三火箭共用开拓者能释放工人；缺口朝炮塔提供内侧建筑承伤位，捣乱鬼守口补充角色承伤，但必须让出唯一交通口。
- 经验教训：等待者可能远离缺口，整条路径不可达时不会先走近入口，因此让路不能只检查相邻工人或记忆矿点。守口允许承受机器人伤害，不能复用普通破坏策略的机器人避险；敌方抓捕仍需逃避。完成本地寻路和合法性检查不能保证敌方可控机器人一定优先攻击炮塔。
- 验证：新增21项聚焦回归，含默认三火箭建造、开拓者轮射与两工人采矿、四角唯一朝炮塔缺口、黄昏与首夜切换、提前回防、远近工人出城、守墙回城、炮手回防、让路等待、外侧等待格也需退让、预约冲突、危险区不移除、预算耗尽恢复、显式布局与次日释放；原混合阵型测试改为显式选择旧配置，保留原断言，无单缺口的独立破坏回归使用显式布局。本地项目 `.venv` 的 Python 3.12.14 执行 `.venv/bin/python tools/run_checks.py` 通过739项快速检查，失败／错误为0，耗时25.27秒；省略10项仿真与独立策略基准。本地无Python 3.11，既有GitHub CI使用3.11.10；未进行真实对战或多日防守验证。

### 2026-10-09 - 合并固定夜间岗位与加特林换位修复

- 策略：整合固定炮手／守墙身份与按有效弹道调整操控格的两项修复；固定岗位由 `fixed_gatling_crew` 统一分配，站位规划失败、队友堵路或入口退让不清空炮手身份。仍保留清敌夜采、死亡补位和白天工作调度。
- 设定：保留完整主分支修改及两边原设计记录；未来站位规划可以暂时移除队友占位，实际移动继续校验当前占位。保留 `operator_yields` 与 `pioneer_wait_post` 两份独立记忆；弹道格遍历继续来自独立模块，不恢复同名旧副本；日志同时包含 `night_role` 和 `targeting`。

### 2026-10-09 - 加特林入口射界与炮手临时退让

- 策略：默认双火箭／加特林布局在继承的三个武器格内比较入口射界和不占火箭公共格的独立站位，已建武器限制类型与坐标，不引入未经核验的新建造格。站位按当回合可命中目标评价，原盲区站位可换位；仍保留十九格周界及唯一入口。
- 设定：可开火站位优先，有效旧站位保持稳定，同等选择避开入口。对已经完整建成的单入口周界，炮手占入口且相邻队友需要回到操控格或前往记忆矿点、当前路径被入口阻断时，先选墙外合法空格退让；按当前机器人攻击范围比较风险，不把退让位置宣称绝对安全。等待下一次观测后通行，后续两个回合入口不作为该炮手的目标或途经格；墙外临时等待时保留工人身份，即使波次消失也不抢入口。开拓者回防走廊先于加特林回位预约，实际移动仍逐格检查占位，不同回合不能交换指令绕过碰撞。
- 原因：原后角布局的正面弹道穿过基地，距离最短的 `(31,11)` 操控格还会遮住唯一可用落点；移到 `(33,10)` 能解开人物遮挡，但该格也是全周界唯一入口。只修弹道站位会使采矿工人或回防开拓者被炮手堵在入口两侧。
- 经验教训：连通性、独立操控格和有效射界需要一起检查；全包围墙内的加特林无法承担隔墙正面输出，默认承担入口防守。退让后的临时离岗需要独立记忆，不能因本回合没有可达操控格就清除身份。官方建造区未确认前，在已继承格内评价及支持显式布局，不猜测新的合法前排建筑坐标。
- 验证：本次20项新增回归含独立入口站位、三次有限请求中的退让／清敌后留岗／队友通过入口、禁用入口途经格、开拓者走廊预约、显式坐标权威与四角镜像；与既有回归一起，本地 Python 3.12.14 的 `.venv/bin/python tools/run_checks.py` 通过673项，失败／错误为0，耗时20.75秒；省略10项仿真与独立基准。本地没有 Python 3.11，GitHub CI 使用3.11.10；未验证多日防守、正式建造区或真实入口战斗。

### 2026-10-09 - 固定夜间工人岗位，避免白天堵路换岗

- 策略：默认双火箭/加特林阵型确定一名工人作为加特林炮手；只要该工人仍存活，跨白天、夜晚、日期均保留身份，不因离炮远、临时堵路、回血动作或炮台被毁而换人。首次分配优先保留已有守墙人和持包者，再比较可达路程；炮手死亡/从本方存活角色中消失时才改派。原炮手次日复活后不抢回已接替者的岗位，而是补上修墙职责。
- 设定：第四天起另一名存活工人负责守墙；炮位规划失败不清空炮手身份，常规共享模式失效后的降级也使用同一身份。仅剩一名工人时炮手优先、守墙岗位空缺，不能声称一人同时承担两项完整夜间工作。现有清敌后短途采矿仍保留炮手身份，回防后继续操作同一类武器。
- 策略：夜间身份用于备包和实际返程期限，不把人提前加入白天动作排除集合。两名工人的白天任务仍按已有急救、续接、补墙、采购、交付、施工和生产规则执行；不会每回合按最近炮台重新选择职业。
- 策略：白天无任务且未到回防期限的开拓者选择后墙外待命点，距基地3～5格、避开规划建筑/操控格/机器人危险区。保留待命目标，核算出入两段路程和两倍回防余量；不打断任务或已提交动作。待命格须保持周围可通行格之间的连通，不能在矿与墙之间的单格通道停车。行进经过入口后继续离开，而非将入口作为终点。
