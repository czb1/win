# 防御模块设计（v2.0 / 32进16）

状态：围墙布局与升级顺序已按 v2.0 调整，其余新规则适配及实战表现仍需逐项验证。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 防御设计](../1.0版本设计文档/防御.md)。

## 目标与边界

默认以完整围墙保护基地、保留正对炮塔的唯一通行口，并维护迎敌侧优先的墙体升级顺序。开拓者每晚轮流操作三座火箭；实际围墙只剩唯一入口时，捣乱鬼黄昏在缺口旁待命，夜晚附近有机器人时守口并为工人进出及炮手回防让路。墙未齐或夜间附近清敌后，捣乱鬼去对方矿区破坏。工人继续采矿与第四天起的守墙策略。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |

| 阵亡后下一个游戏日白天第1回合复活，背包保留 | 死亡状态、次日补位与回防记忆 |

| 小车只在白天存在，驾驶时可移动2格；移动1格为下车步行 | 路程与回防时间估计、留车、夜间消失和碰撞边界 |
| 敌方小车格不可驶入，任何小车格不可建造 | 寻路占位与建设合法性 |

## 关键设定与原因

- 默认围墙覆盖距基地完整 2×2 占地两格的矩形周界：二十格周界中建十九格，侧后方留一格入口。迎敌六格及原两翼六格坐标保持原位，补齐两侧翼格与后方五格；入口不占用旧十二格墙，布局不随人物或建筑占位漂移。
- 普通墙券采购保留迎敌侧二级、其他侧二级、迎敌侧三级、侧后三级的需求顺序；已携带的券按目标实际等级使用，不再等待完整周界或其他一级墙。可完成的持券目标之间优先补二级、迎敌面及迎敌中心，前序目标无匹配券、不可达或来不及交付时继续使用其他目标。所有侧墙上限统一为三级，重建恢复优先级及基地升级的实际完工判断继续保留。
- 默认 `return_margin=0`，移除五回合回防余量，仍核算移动、逐次施工／使用和真实夜间岗位返程；默认 `economy_rounds=35`，经济阶段比原40回合提前五回合结束，长路线可更早准备。守墙人持有足额夜修包时，能完成并返回内圈的持券交付和补墙优先于普通售矿。
- 侧面入口不进入建设、缺口识别和补墙计划，临时经过的角色（包括捣乱鬼）不构成永久封路。守墙巡逻范围以蓝图的四边为界，不通过入口或后方缺口巡逻到墙外；人物占住公共操控格时允许先经唯一入口退让，再离开回防通路，目标预约使炮手等待，避免换位与争抢同格。
- 三座火箭使用同一公共操控格，存活开拓者每回合按实际冷却轮射其中一座，避免每座炮都占用工人。开拓者阵亡时沿用已有存活工人补位；第四晚起从空闲工人中保留固定守墙身份。
- 唯一入口采用局部坐标 `(-2, 1)`，内侧第一格 `(-1, 1)` 是第三座火箭，公共操控格为 `(-1, 0)`；不因人物占位改变炮位或增加缺口。守口需要所有规划墙格都有本方存活围墙，且入口未被围墙封闭；夜间还需要基地或入口附近有非本方可控机器人。捣乱鬼守口时吸收伤害，实际机器人攻击对象仍由对方指令和判题器决定。
- 捣乱鬼黄昏回程包含实际步行与余量，最后白天回合在外侧斜邻格待命；夜间让路根据英雄真实失败寻路与本回合已接受的移动决定。只临时移除守口捣乱鬼占位核对连通性，不移除其他障碍或危险区，不把假设路线作为合法移动提交；本回合先让路，下回合观测空口后通行，经过者未离开时不抢回缺口。
- 显式混合阵型继续保留固定加特林工人、独立站位与弹道修复回归。显式布局坐标保持配置权威，只有唯一且正对炮塔的入口才启用捣乱鬼守口；建造区域仍待官方核验。
- 1.0的围墙、后角炮台和修墙设计仅作为继承记录；新角色和血量变化不自动授权修改建设顺序或防守职责。
- 小车移动和步行需要区分，不能无条件把每次移动按两格计算。
- 任务书第二格碰撞后的实际停留位置存在原文歧义，见 [本阶段待确认事项](../比赛文档/v2.0-32进16/README.md)。核实前不写入确定的移动结算方案。

## 变更记录

### 2026-10-10 - 用完已有墙券，提前施工并去除五回合回防余量

- 策略：已携带的墙券按目标当前等级匹配使用；一级墙或尚未建成的蓝图格不再禁止其他二级墙升三级。迎敌／中心顺序改为可完成的持券目标之间的偏好，紧急重建仍优先；配送及批量预算遇到不可达或时间不足的前序墙时使用其他可完成墙。原地商店补买下一档和已接受的墙券采购让位已有券交付，普通收入任务也让位已持有且可交付的墙券。
- 设定：默认回防余量从5改为0，配置加载允许非负整数；默认经济截止从40改为35，同步普通采矿、余量采矿、售矿扫尾和任务续接的阶段判断。尚有建设／升级需求时，收入任务到截止回合释放；施工石料采集继续按材料目标完成。真实去程、逐张使用、建造与夜间岗位返程仍核算，原有合法性、占位、预约及失败退避继续生效。
- 策略：足额备包的守墙人先交付已有券，再续接可完成的补墙，随后处理普通售矿。不能及时完成的墙工不抢占回防，紧急治疗、破墙修复及必需夜修备包继续先处理；守墙人的墙券配送使用内圈施工位置，避免末回合仍要求回到无炮手职责的炮台。
- 原因：第七天末快照显示14张二升三级券、15面二级墙、两面一级墙及两格缺墙；全周界前置条件阻止全部普通三级使用。第822回合足额备包且金币882的施工者被9块多余石料的18金币售矿行程抢占，之后未完成售矿也未补墙。代码允许先购三级券、后新建／重建一级墙，但现有片段没有购券当时的墙体状态，不能确认这一局的采购先后。
- 经验教训：采购规划与已付物品交付应分开；其他目标尚未具备前置条件不能让已经可用的库存失效。阶段阈值必须同时约束新增分配和持续收入任务，足额备包不能被当作停止白天施工的理由。
- 验证：新增15项单回合、状态切换及边界回归，覆盖零余量配置、持券跨过一级／缺墙、正确券级及满级拒绝、不可达前序墙、持券中断采购／收入、35回合收入释放与石料任务保留、长路线提前准备、足额备包施工／交付优先售矿、末白天使用及不可完成施工拒绝；保留明确配置5回合余量的既有边界检查。同步最新主分支的首日施工保护后，项目 `.venv` 的 Python 3.11.17 执行 `.venv/bin/python tools/run_checks.py` 通过912项默认快速检查，失败／错误为0，耗时37.44秒，省略10项仿真；设计文档门禁及 `git diff --check` 通过。提供的819～822及849共5个快照分别核对动作合法性，849快照两工人各可提交一张二升三级券使用；这是有限请求检查，不是整日回放。未运行完整多日仿真、独立策略基准或官方对战。

### 2026-10-09 - 夜间仅在实际单缺口且附近有怪时守口

- 策略：实际城墙未建齐、墙体被摧毁形成额外缺口、入口被围墙补上时，不接管捣乱鬼守口或黄昏回防；夜间城墙已齐但附近机器人清空时同样释放，继续前往对方矿区并按原安全约束连续破坏。附近出现新机器人后重新判断守口资格。
- 设定：保留蓝图的唯一朝炮塔入口识别，并核对全部规划墙格均由本方存活围墙覆盖、入口无围墙。夜间每回合检查非本方可控机器人到入口或基地任一格的切比雪夫距离，阈值为 `max(task_danger_radius, attack_range + 2)`，默认6格；远处或死亡机器人不触发守口。本方 `summonRobotList` 的机器人不触发守口；其他机器人即使指向对方或暂时眩晕，仍可能攻击挡路人物或恢复行动，保留守口。释放时删除旧 `recalling`／`yield_until` 状态，不清除仍有效的矿点和已确认连续破坏进度；实际动作仍经过原占位、预约、避险和抓捕检查。
- 原因：原判断只看规划围墙能否识别唯一入口，因此围墙尚未完成或已出现破洞时仍会召回捣乱鬼；夜间没有附近机器人时也会继续占口或让路待命，浪费破坏回合。用户要求只有能堵住实际唯一缺口且附近仍有怪时才守口。
- 经验教训：建设蓝图、实际墙体和本回合防守需求必须分开核对；保留的回防与让路记忆不能覆盖新的职责判断。解除守口应复用原破坏调度，不能丢失合法的连续四回合进度或放宽危险区与移动碰撞约束。
- 验证：新增10项聚焦回归，覆盖19个规划墙格分别未建／摧毁、未建墙的黄昏释放、封死入口、空场／死怪／远怪释放、距离边界与长射程、敌方目标阵营与眩晕、本方召唤机器人、清敌后离岗与新怪回防、旧回防／让路记忆清理、夜间连续四回合破坏；更新原交通场景以区分有怪守口和清敌出城，保留四角工人通行与合法占位断言。项目 `.venv` 的 Python 3.12.14 下35项守口聚焦检查通过；`.venv/bin/python tools/run_checks.py` 通过796项默认快速检查，失败／错误为0，耗时26.43秒，省略10项仿真。本地无Python 3.11，既有GitHub CI使用3.11.10；未执行完整多日仿真、独立策略基准或官方对战。

### 2026-10-09 - 白天守口与破坏矿场切换导致的往返堵塞

- 策略：白天是否接管捣乱鬼统一依据剩余时间、实际返程步数与回防状态判断；站在唯一入口也必须经过同一返程期限检查，白天初始不因当前位置在入口就转入守口。
- 设定：本日尚未结束的 `yield_until` 在准备守口阶段同样生效，让路等待时不再交给破坏调度抢回入口。临时让路保留目标矿石，实际回防／夜间守口才清除目标；任何让路或回防中断仍清零连续破坏进度，遵守 v2.0 连续四回合规则。临时白天让路单独记录为 `imp_daytime_gate_yield`，黄昏站位与夜间守口继续沿用原日志原因。
- 原因：第780～782回合捣乱鬼在 `(33,10)` 与 `(34,9)` 间交替执行 `imp_dusk_staging` 和 `imp_approach_enemy_mine`。原返程判断只覆盖“不在入口”的角色，在入口时立即清空目标并侧移，侧移后又释放到破坏调度。入口在占位与下一回合移动预约间持续不可达，墙内工人不能补货，墙外工人无法验证返程而空闲。
- 经验教训：职责切换必须以时间和持续状态判断，经过入口不代表开始回防；让路记忆需要在准备阶段与最终移动阶段共同检查。临时让路保留的是任务目标，不能保存被打断的连续破坏进度；实际移动仍使用当前占位与预约，不放宽碰撞校验。
- 验证：新增四项默认快速检查，覆盖早晨在入口／旁侧的职责释放、现场快照中三次有限请求不往返、捣乱鬼离口后两工人恢复动作、白天让路等待／目标保留／进度清零与等待到期。现场回归夹具仅取第780回合必要请求字段并去除队名和原队伍标识。验证命令为 `python tools/run_checks.py`，由仓库既有 Python 3.11.10 GitHub CI 执行，结果见本次提交检查；本地仅提供 Python 3.12，未替代仓库规定的3.11运行环境。未执行完整多日仿真、独立基准或官方对战。

### 2026-10-09 - 相邻敌方捣乱鬼顺手抓捕，不追击

- 策略：正常动作分配后，仅空闲工人／开拓者或正在普通采矿的工人，向当前可见的八邻格敌方捣乱鬼提交一次 `catch`。不为抓捕移动、寻路或保留追击目标；敌人跑开、消失或死亡后继续己方工作。
- 设定：同一敌人与己方英雄持续相邻期间全队最多尝试一次；两次抓捕至少间隔5回合，每回合最多一名角色抓捕，优先空闲角色。普通采矿最多暂停一个回合并保留原矿点与工作记录；采墙材、建造、交易、用药／交付、任务、回防、操炮、守口退让及明确持有动作不被替换。已有守墙修复指令优先，空闲守墙人可以顺手抓捕。己方捣乱鬼保持原有生存与守口调度，避免互抓同归于尽。
- 原因：用户要求遇到身旁敌方捣乱鬼时顺手抓一下，但不能因反复抓捕或追击浪费生产、防守回合。v2.0任务书 §4.4 与接口 §2.3 规定 `catch` 作用于八邻格，成功获20金币，目标阵亡；下发动作不能作为成功证据，本次不预支抓捕收益。
- 经验教训：视野内、引导全图可见与实际相邻是不同条件。抓捕前必须使用本回合位置，不能沿用历史敌人坐标；持续扑空时恢复采矿，接触重置仍受全队间隔约束。必须保留被暂停的采矿任务，且上回合 `catch` 不能计作成功采集。
- 验证：18项新增聚焦检查通过，覆盖八邻格、逃离／视野消失、单次接触与间隔、多人去重、采矿续接、关键动作保护、同回合缓存和正常夜间轮射。项目 `.venv` 的 Python 3.12.14 执行 `.venv/bin/python tools/run_checks.py` 通过757项快速检查，失败／错误为0，耗时24.38秒；本地未提供Python 3.11，既有GitHub CI使用3.11.10。省略10项仿真与独立策略基准，未进行真实对战或多日策略验证。

### 2026-10-09 - 三火箭共享开拓者与捣乱鬼守口让路

- 策略：默认配置恢复三座火箭，由开拓者在公共格按冷却轮射；十九格围墙仅保留原侧口，向内第一格为第三炮塔。捣乱鬼按回程预算提前回防，最后白天回合站在缺口外侧斜邻格，夜间占口承伤；工人采矿、修墙回城和开拓者回炮位时先让路。
