# 防御模块设计（v2.0 / 32进16）

状态：围墙布局与升级顺序已按 v2.0 调整，其余新规则适配及实战表现仍需逐项验证。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 防御设计](../1.0版本设计文档/防御.md)。

## 目标与边界

默认以完整围墙保护基地、保留侧面通行口，并维护迎敌侧优先的墙体升级顺序。开拓者每晚操作双火箭，工人操作侧入口旁的加特林；保留回血、通路退让和另一名工人的守墙策略。

## 关键设定与原因

- 默认围墙覆盖距基地完整 2×2 占地两格的矩形周界：二十格周界中建十九格，侧后方留一格入口。迎敌六格及原两翼六格坐标保持原位，补齐两侧翼格与后方五格；入口不占用旧十二格墙，布局不随人物或建筑占位漂移。
- 普通墙体先升迎敌侧二级，再升其他侧二级；完整周界建成且所有墙达到二级后，按原有迎敌侧中心向两端顺序升三级，随后侧面与后方升三级。所有侧墙等级上限统一为三级；重建、采购、使用、恢复动作和基地升级判断使用同一上限与阶段约束。
- 侧面入口不进入建设、缺口识别和补墙计划，临时经过的角色（包括捣乱鬼）不构成永久封路。守墙巡逻范围以蓝图的四边为界，不通过入口或后方缺口巡逻到墙外；人物占住公共操控格时允许先经唯一入口退让，再离开回防通路，目标预约使炮手等待，避免换位与争抢同格。
- 两座火箭使用原公共格，加特林工人选用与其不同、避开建墙蓝图的操控格；固定工人身份与回防站位，死亡后改派存活工人，回血占用本回合时保持原岗位。工人离开加特林采矿后仍保留其职责，第四晚起不因清敌释放而抢占另一名工人的守墙角色。
- 1.0的围墙、后角炮台和修墙设计仅作为继承记录；新角色和血量变化不自动授权修改建设顺序或防守职责。
- 小车移动和步行需要区分，不能无条件把每次移动按两格计算。
- 任务书第二格碰撞后的实际停留位置存在原文歧义，见 [本阶段待确认事项](../比赛文档/v2.0-32进16/README.md)。核实前不写入确定的移动结算方案。

## 变更记录

### 2026-10-08 - 双操控格与加特林工人离岗／回防

- 策略：十九格围墙与侧入口保持原坐标；原第三个火箭格改为加特林，开拓者与工人分别使用公共格和独立格。夜间清敌后加特林工人安全采矿，附近威胁再次出现则回防；另一名工人沿用既有采矿／守墙调度。
- 设定：公共格从两座火箭邻接格交集中选取，加特林站位排除公共格和全部墙体蓝图。回防距离包含当前角色堵塞与预留安全余量；阻塞公共格的角色先退让，开拓者等待观测到目标格空出，避免同回合交换位置。加特林工人的待命分配也从守墙候选中排除，清敌后不被改派为修理工。
- 原因：三座后角武器全共用一个格时无法同时安置两名独立操控者；清敌后只移除攻击指令而不移除回防锁或守墙候选，会继续阻止工人外出采矿。
- 经验教训：保存岗位身份与本回合锁定角色是两个状态，工人回血应保持岗位，工人清敌则应释放动作。通路退让可能先消耗工人的一次移动，本回合无法同时射击，必须保持单角色动作约束。
- 验证：新增混合武器22项针对性检查，包含四角完整周界的双操控格、清敌后夜采、新敌回防、死亡补位与回血不抢矿工；更新既有公共格退让与第三晚回防断言。`.venv/bin/python tools/run_checks.py` 在本地 Python 3.12.14 下通过569项快速检查，失败／错误为0；省略10项仿真和独立基准。未运行完整多日仿真、Python 3.11 本地检查或真实比赛。

### 2026-10-08 - 环绕围墙、侧面入口与全周界三级升级

- 策略：默认由迎敌面和两翼的开放防线改为围住基地的十九格周界，在侧后方墙面保留一格入口；迎敌侧二级、其他侧二级、迎敌侧三级、其他侧三级依次推进，迎敌三级继续从中心向两端扩展。
- 设定：沿用距基地占地两格的墙体环及墙内后角火箭／公共操控格；入口采用局部坐标 `(-2, 1)`，随左右与上下阵营镜像，利用任务书 §4.5.4 第 2 条允许的对角移动同时连通公共操控格与墙内通道。显式布局保持配置坐标。普通三级升级等待蓝图墙全部建成并达到二级，重建墙保留已有恢复优先级；侧墙不再封顶二级。
- 原因：v2.0 任务书 §4.6.3 允许在双方建造区及 NPC 之外指定召唤位置，敌方能从侧后方向进攻；旧后方开放布局无法覆盖这些来袭方向。升级上限若仍限制侧墙二级，无法执行其他侧三级升级。
- 经验教训：补全蓝图时需要同时核对通行口、动态占位、守墙范围、采购配送、恢复等级和普通升级前置阶段；只保留远离炮手的侧墙入口会将原公共操控格封在炮台与后墙之间，因此入口须连通该格及其余墙内通道。携带升级券、同回合预约及旧配送目标都不能替代观测到的墙体完工和等级。建筑区域绝对坐标仍沿用既有 demo 推导，内网建造区图片待核验，不将其写成新增已确认规则。
- 验证：新增四角唯一入口与墙内外可达性、入口不补洞、角色经过入口时封后墙、迎敌二级优先、未建墙阻止普通三级、侧墙三级采购／使用／恢复及守墙后界检查；补充单格入口分两步退让、同格预约拒绝和长路线售矿返程截止检查，更新原布局和侧墙等级相关断言。`.venv/bin/python tools/run_checks.py` 通过 547 项快速检查，失败／错误均为 0；省略 10 项仿真回放及独立基准。当前本地环境仅有 Python 3.12，使用项目 `.venv` 的 Python 3.12.14 完成检查；Python 3.11.10 由既有 GitHub CI 核验。未执行完整仿真、多日防守或首日建满十九格的回放验证。

### 2026-10-08 - 回防与寻路诊断

- 策略：为已有回防和守墙调度记录角色目标炮台／站位、预计步数、剩余白天与安全余量；保留最新白天空动作修复的状态与回退行为。
- 设定：日志区分操控炮台、守墙准备、策略持有、路径不可达和无可用动作；寻路只记录现有搜索的结果计数、阻挡／预约／临时避让数量，不额外运行BFS。
- 原因：人物在录像中停留可能是正常待命，也可能是路线失败或错误持有，需要把实际动作与调度原因一起分析。
- 经验教训：某次候选路线不可达不代表整个回合无路；候选失败与最终选择分别记录，临时阻挡不当作永久建筑。
- 验证：现有工人空动作和回防回归继续纳入默认快速检查，补充现场与人物区间提取；64次基线响应对照一致，完整检查结果见自进化模块本次记录，未执行多日防御仿真。
