## 目标与边界

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 任务点2的任务完成会奖励小车，每队同时至多1辆 | 区分任务完成、部分得分和动作合法性，不补造成功信号 |
| 夜间或白天最后一回合完成时，小车顺延至次日出现 | 奖励状态与后续角色调度的交接，不把暂未下发小车当成任务失败 |
| `lastCmdResult` 的状态头后固定增加 `[durationMs:N]` | 沙盒输出解析、最终答案提取、超时/异常和截断处理 |
| `errors` 中3为网络错误，4为指令错误，5为LLM额度超限 | 核对错误路由、修复与降级，保留具体错误证据 |
| 原文异常分类与计数口径仍有待确认表述 | 结合比赛资料中的待确认事项，不能把动作执行失败直接等同异常次数 |
| 本阶段任务用品价格降至10 | 宝藏用品与采购预算对照经济模块核对，原45金币等预算不自动改为新策略 |

## 关键设定与原因

- 历史任务工具和经验库需要针对新结果格式与任务环境核验；旧任务成功记录不等于本阶段已完成验证。
- 接口仍规定每日3次LLM调用，执行自进化任务期间豁免并不计入该额度；核对新错误处理时保留这个边界。
- 网络故障、任务判错、动作非法与沙盒执行状态分开核对，具体处理流程在后续代码适配时确定。

## 待验证

- 正常退出、失败退出、超时、判题器异常、空输出及64KB截断下的耗时头和答案解析。

- 网络错误、新指令错误码和LLM额度错误对状态机的影响。
- 原任务闭环、工作目录、工具、分页和跨任务经验的回归；真实题目成功率另行验证。
