状态：自进化执行链已完成v2.0输出格式、当前输入检查与独立checker适配；离线验证记录见变更日志，真实任务成功率仍需新对局验证。

## 目标与边界

按当前规范维护任务执行、提交证据和方法复用，减少弱模型对目录、输入结构与日志格式的猜测。修改限定任务点自进化链路；战斗、采矿、建筑、经济调度及新闻／宝藏处理保持原逻辑。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 任务点2的任务完成会奖励小车，每队同时至多1辆 | 区分任务完成、部分得分和动作合法性，不补造成功信号 |
| 夜间或白天最后一回合完成时，小车顺延至次日出现 | 奖励状态与后续角色调度的交接，不把暂未下发小车当成任务失败 |
| `lastCmdResult` 的状态头后固定增加 `[durationMs:N]` | 沙盒输出解析、最终答案提取、超时/异常和截断处理 |
| `errors` 中3为网络错误，4为指令错误，5为LLM额度超限 | 核对错误路由、修复与降级，保留具体错误证据 |
| 原文异常分类与计数口径仍有待确认表述 | 结合比赛资料中的待确认事项，不能把动作执行失败直接等同异常次数 |
| 本阶段任务用品价格降至10 | 宝藏用品与采购预算对照经济模块核对，原45金币等预算不自动改为新策略 |

## 关键设定与原因

- 历史任务工具和经验库需要针对新结果格式与任务环境核验；旧任务成功记录不等于本阶段已完成验证。
- 接口仍规定每日3次LLM调用，执行自进化任务期间豁免并不计入该额度；核对新错误处理时保留这个边界。
- 网络故障、任务判错、动作非法与沙盒执行状态分开核对，具体处理流程在后续代码适配时确定。

### 2026-10-09 - 日志题解析方法复用与计算证据绑定

- 原因：最新对局 L-3 把 gateway 的 4xx 当故障、漏掉后勤故障信号，后续又猜测泛化关键词；沙盒计算 21 个事件后漏写最终标记，最终模型提交 15。日志不足以确定正确事件数，本次不硬编码比赛答案或故障规则。
- 策略：成功任务除 `parse_line` 外，也提取实际调用过的 `parse_*_log`、依赖函数、必要字面量常量和允许的导入；去掉说明字符串，排除固定输入路径、日期、顶层数据/聚合及无法独立解析的依赖。只有合法提交后在截止前观察到完成才提升方法，并保存题目中有界的故障定义/格式文字。同任务点、同题目族且当前明确说明沿用格式时，在官方沙盒加载方法，绑定同名解析函数及 `task_parse(system,current_path)`；不继承旧数据或执行旧聚合。声明格式变化、不同题目族或方法被停用时不自动复用。
- 设定：日志统计答案在模型接收和最终提交两处与本题成功计算结果核对，允许有证据的字段子集，禁止模型改变数值。`task_result(result)`负责最终标记；仅成功、未截断、输出全文为一个符合当前契约的有限JSON对象时兼容漏标记，拒绝调试文字、多个对象、重复键、NaN/Infinity及校验器token。
- 诊断：日志任务沙盒记录 `.log` 文件读取行数/是否读完、解析函数调用及返回记录数、`parse_line` 按系统匹配/故障/未匹配样例、事件计数和少量首末时间。通用 `task_events` 对当前故障时间排序，按相邻间隔和调用者提供的阈值合并；不推断哪些行属于故障。文件级解析器的返回条数不冒充匹配成功数；`merge_*event*`函数也记录聚合调用数。缺文件、未完整读取、已预览文件被遗漏、逐行解析未匹配、解析函数吞掉OSError/ValueError均阻止提交；完整读取并实际解析的零故障保留。无进展/判错后优先把这些诊断传回模型，不另花回合重复相同预览。
