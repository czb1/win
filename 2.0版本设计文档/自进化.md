# 自进化模块设计（v2.0 / 32进16）

状态：自进化执行链已完成v2.0输出格式、当前输入检查与独立checker适配；离线验证记录见变更日志，真实任务成功率仍需新对局验证。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 自进化设计](../1.0版本设计文档/自进化.md)。

## 目标与边界

按当前规范维护任务执行、提交证据和方法复用，减少弱模型对目录、输入结构与日志格式的猜测。修改限定任务点自进化链路；战斗、采矿、建筑、经济调度及新闻／宝藏处理保持原逻辑。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 任务点2的任务完成会奖励小车，每队同时至多1辆 | 区分任务完成、部分得分和动作合法性，不补造成功信号 |
| 夜间或白天最后一回合完成时，小车顺延至次日出现 | 奖励状态与后续角色调度的交接，不把暂未下发小车当成任务失败 |
| `lastCmdResult` 的状态头后固定增加 `[durationMs:N]` | 沙盒输出解析、最终答案提取、超时/异常和截断处理 |
| `errors` 中3为网络错误，4为指令错误，5为LLM额度超限 | 核对错误路由、修复与降级，保留具体错误证据 |
| 原文异常分类与计数口径仍有待确认表述 | 结合比赛资料中的待确认事项，不能把动作执行失败直接等同异常次数 |
| 本阶段任务用品价格降至10 | 宝藏用品与采购预算对照经济模块核对，原45金币等预算不自动改为新策略 |

## 关键设定与原因

- 历史任务工具和经验库需要针对新结果格式与任务环境核验；旧任务成功记录不等于本阶段已完成验证。
- 接口仍规定每日3次LLM调用，执行自进化任务期间豁免并不计入该额度；核对新错误处理时保留这个边界。
- 网络故障、任务判错、动作非法与沙盒执行状态分开核对，具体处理流程在后续代码适配时确定。

## 待验证

- 网络错误、新指令错误码和LLM额度错误对状态机的影响。
- 原任务闭环、工作目录、工具、分页和跨任务经验的回归；真实题目成功率另行验证。

### 2026-10-09 - 四种日志筛选方式

- 策略：单文件提取器增加自进化、长上下文，以及指定天数白天／黑夜普通日志的筛选；使用 `--mode evolution`、`--mode long-context` 和 `--mode non-task --day N --phase day/night`。
- 设定：任务类别优先采用明确的 `category`，旧 `task_` 事件补作自进化；筛选应用于每条导出记录，`--context` 不越过显式天数／昼夜／任务编号边界。筛选模式将场次元数据和完整性报告放入 `meta.json`，正文只保留选中类型。普通模式排除任务类别、模型／沙盒原文、开拓者决策和含任务内容的反馈／响应，保留同回合工人、武器等普通日志；默认 `all` 继续用于完整问题区间。
- 原因：仅以任务回合范围截取会混入其他任务与普通记录，按回合扩展上下文还可能混入相邻日期或昼夜，需要独立的内容筛选和时间边界。
- 经验教训：全局任务编号可能被同回合普通决策继承，不能据此删除工人等日志；接口规定 `lastSummonTreasureResult=0` 表示未探测，不应将正常反馈误判为宝藏结果。显式长上下文类别优先于 `task_` 事件名，避免跨类归档。
- 验证：新增隔离目录 CLI 混合日志检查，覆盖两种任务模式、两种昼夜普通模式、同回合类别隔离、跨天／昼夜边界、运行／场次／队伍隔离、区间外原文补齐、零结果反馈、列表筛选、任务编号上下文、空结果和非法天数。Python 3.11.17 `.venv` 默认快速校验通过621项、0失败、0错误，排除10项仿真；单文件和 UTF-8／UTF-16 检查保持通过。未执行多日仿真、独立策略基准或真实平台对局。

### 2026-10-08 - 自进化执行闭环修复

- 策略：先解析平台状态头和可选`durationMs`，再移除`TASK_RUNTIME`，最后识别严格的`FINAL_ANSWER`。兼容旧测试报文，失败退出、超时、判题器异常及截断仍不授权提交；原始平台输出继续完整用于诊断日志。
- 设定：读取题目首段时同步、有界地检查本题目录及文档明确指定的JSON／日志文件，展示顶层类型、键、首个样例、后续读取路径和日志样例。只读取当前题目目录内文件，执行目录从已解析的文档路径或本题合法`cd`确定，不扫描`/`或继承旧工作区。
- 策略：从token提交规则及唯一明确的`./check`或`./check_<name>`识别checker任务。原部署题继续使用spec修复SOP；转换题先由模型处理当前输入，再由程序独立运行本题checker。只有退出码0、输出未超限且唯一TOKEN时提交；不修改题目或checker，不接受模型生成的占位token。
- 设定：日志脚本使用自包含`parse_line`解析函数，沙盒记录调用数、匹配数和少量未匹配样例。全零结果没有成功解析证据时阻止提交并读取当前输入进行诊断；解析正常且实际无故障允许零答案。判错或同一无进展输出重复时转入有界输入检查；Python提案按AST计数，改注释／空白不视为新尝试。
- 策略：合法提交后、在超时前观察任务完成，才保存方法。保存自包含解析函数及其依赖，排除顶层旧输入、旧答案和不可解析的外部全局依赖。同任务点、同题目族的解析方法可作为新答案结构的提示；可执行完整recipe仍要求答案结构一致并重新绑定当前参数，禁止直接执行旧聚合。
- 原因：本局S2/S3多次相对路径及样例包装错误；L1/L2/L3未观察真实格式，L3的最终标记被耗时头阻断；S2提交示例token。固定程序负责目录、输入证据、checker及重复诊断，减少模型负担。
- 经验教训：执行成功只证明程序正常退出，不代表统计正确；解析器没有匹配到记录不能等同于零故障；答案结构变化不代表底层日志格式变化。题目明确要求四舍五入时，沙盒作用域的`round`使用Decimal的`ROUND_HALF_UP`；其他任务保留默认round语义，并提示模型按当前要求计算，避免Python的偶数舍入。
- 验证：新增v2.0耗时头／元数据／失败状态／截断、从`/`读取真实文件题并写入结果、cases／expected包装预览、独立具名checker与错误／多token输出、零故障与零匹配区分、AST重试及不同代码重复输出、确认完成后解析方法跨答案结构复用与旧数据隔离、2.5分钟四舍五入边界检查。默认快速校验通过504项、0失败、0错误，排除10项仿真；新闻／宝藏入口与基线AST一致，改动文件范围限定自进化。本机`.venv`为可用Python3.12，提交后由Python3.11.10 CI复核。未执行多日仿真、策略基准或真实模型比赛，不预先宣称成功率提升。

### 2026-10-09 - 日志题解析方法复用与计算证据绑定

- 原因：最新对局 L-3 把 gateway 的 4xx 当故障、漏掉后勤故障信号，后续又猜测泛化关键词；沙盒计算 21 个事件后漏写最终标记，最终模型提交 15。日志不足以确定正确事件数，本次不硬编码比赛答案或故障规则。
- 策略：成功任务除 `parse_line` 外，也提取实际调用过的 `parse_*_log`、依赖函数、必要字面量常量和允许的导入；去掉说明字符串，排除固定输入路径、日期、顶层数据/聚合及无法独立解析的依赖。只有合法提交后在截止前观察到完成才提升方法，并保存题目中有界的故障定义/格式文字。同任务点、同题目族且当前明确说明沿用格式时，在官方沙盒加载方法，绑定同名解析函数及 `task_parse(system,current_path)`；不继承旧数据或执行旧聚合。声明格式变化、不同题目族或方法被停用时不自动复用。
- 设定：日志统计答案在模型接收和最终提交两处与本题成功计算结果核对，允许有证据的字段子集，禁止模型改变数值。`task_result(result)`负责最终标记；仅成功、未截断、输出全文为一个符合当前契约的有限JSON对象时兼容漏标记，拒绝调试文字、多个对象、重复键、NaN/Infinity及校验器token。
- 诊断：日志任务沙盒记录 `.log` 文件读取行数/是否读完、解析函数调用及返回记录数、`parse_line` 按系统匹配/故障/未匹配样例、事件计数和少量首末时间。通用 `task_events` 对当前故障时间排序，按相邻间隔和调用者提供的阈值合并；不推断哪些行属于故障。文件级解析器的返回条数不冒充匹配成功数；`merge_*event*`函数也记录聚合调用数。缺文件、未完整读取、已预览文件被遗漏、逐行解析未匹配、解析函数吞掉OSError/ValueError均阻止提交；完整读取并实际解析的零故障保留。无进展/判错后优先把这些诊断传回模型，不另花回合重复相同预览。
- 弱模型适配：日志题使用单独的简短提示，保留规则、当前输入、解析/合并助手和裁判反馈，去除无关HTTP、部署修复与复杂skill输出格式。模型负责当前任务聚合，程序负责复用、输出协议和证据检查。
- 范围：仅自进化模块、测试及本文档；不修改经济、战斗、围墙、开拓者调度、新闻或宝藏行为。不增加依赖。文件审计是诊断质量检查，不是执行任意模型代码的安全隔离；代码仍仅由官方沙盒运行。
- 验证：新增乱序及5分钟边界、多种故障及正常干扰词、文件级解析器跨题确认提升/新路径绑定/输出结构变化、缺文件/部分读取/漏系统/吞异常、真实零故障、漏标记、重复JSON键及非有限数字、21改15拦截等聚焦回归。最终快速回归653项通过、0失败、0错误，排除10项仿真；新闻/宝藏入口AST与基线一致，其余游戏模块未改动。本地为Python3.12，Python3.11由CI复核。未运行多日仿真或真实模型比赛，不能以离线通过承诺实战成功率。

- 经验教训：正常退出不等于解析正确，字段数相同不等于数值有依据；规则继承、数据读取、计算结果和提交内容需要分别留证，不能让弱模型用新猜测覆盖已验证方法。
