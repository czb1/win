## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 任务点2的任务完成会奖励小车，每队同时至多1辆 | 区分任务完成、部分得分和动作合法性，不补造成功信号 |
| 夜间或白天最后一回合完成时，小车顺延至次日出现 | 奖励状态与后续角色调度的交接，不把暂未下发小车当成任务失败 |
| `lastCmdResult` 的状态头后固定增加 `[durationMs:N]` | 沙盒输出解析、最终答案提取、超时/异常和截断处理 |
| `errors` 中3为网络错误，4为指令错误，5为LLM额度超限 | 核对错误路由、修复与降级，保留具体错误证据 |
| 原文异常分类与计数口径仍有待确认表述 | 结合比赛资料中的待确认事项，不能把动作执行失败直接等同异常次数 |
| 本阶段任务用品价格降至10 | 宝藏用品与采购预算对照经济模块核对，原45金币等预算不自动改为新策略 |

## 关键设定与原因

- 历史任务工具和经验库需要针对新结果格式与任务环境核验；旧任务成功记录不等于本阶段已完成验证。
- 接口仍规定每日3次LLM调用，执行自进化任务期间豁免并不计入该额度；核对新错误处理时保留这个边界。
- 网络故障、任务判错、动作非法与沙盒执行状态分开核对，具体处理流程在后续代码适配时确定。

## 变更记录

### 2026-10-08 - 单txt诊断与任务导出

- 策略：将日志用于录像回合定位后的原因分析，统一 stderr 的 `FWLOG` 结构化记录，不增加HTML查看器；提取脚本默认生成 `issue.txt`、独立的 `tasks.txt` 和完整性元数据，可按场次、回合、人物或任务筛选并按需拆分。
- 设定：每回合保留完整原始地图观测、决策来源及条件、前回合动作与实际状态变化。题目、prompt、LLM回复和沙盒结果保存全文并按内容引用；提取时自动补齐区间外引用及运行配置。长记录分段带哈希，缺失／错误显式报告。沙盒状态头、`durationMs`及截断标记仅用于诊断，不改变任务解析和动作选择。
- 原因：平台只允许下载一个txt，人通过录像发现异常后，需要把一段日志交给智能体分析；仅有指令不能解释为什么选择／放弃任务，截断题目和沙盒输出可能遗漏关键证据。
- 经验教训：动作合法、实际生效、任务结束和确认完成分开记录；断续回合不关联旧反馈，失去视野不当作死亡，机器人目标阵营不代表所有权。日志数据不进入模型提示；写盘及诊断元数据失败不使有效动作失败。
- 验证：增加原始v2.0字段、视野消失、反馈与跳回合、缓存与请求身份、校验拒绝、采矿条件、HTTP锁竞争、上下文释放、中文长文本分段／缺段／校验、WARNING等级、输出故障和任务／人物提取检查。两版接口样例及采矿／任务转移的64次聚焦请求与基线动作、prompt、executeCmd完全一致；本机INFO日志平均6.40ms、基线5.74ms，合计约1.09MB日志，属于局部日志开销检查，不代表极端状态或真实比赛耗时。默认快速校验结果见本次PR；本地 `.venv` 为可用的Python3.12，Python3.11由CI核验。未运行多日仿真、独立策略基准或真实模型任务。

### 2026-10-08 - 昼夜与任务日志检索

- 策略：统一回合诊断上下文，将任务点自进化闭环归入 `evolution`，新闻／民间传闻／宝藏链路归入 `long_context`，保留原有文本消息和任务内容边界。
- 设定：按已有 `Turn` 的 `round_origin`、130回合一天、70回合白天计算游戏天数和阶段内回合；场次、队伍、任务编号贯穿模型、沙盒、提交和结束。旧任务的结束与 outcome 先记在旧编号下，再切换到新编号；跨日不切断任务链。附加记录仅用于诊断，不进入模型提示或动作选择。
- 原因：单凭全局回合号难以定位第几天白天／黑夜，分散的任务消息难以串联同一次执行；长上下文是累计新闻宝藏任务，不能误标为任务点的自进化类2。
- 经验教训：动作合法、提交、任务结束和确认完成必须分别呈现；领取失败不能留下任务编号，线程内上下文必须在返回及异常时释放，题目中出现日志标记不能改变任务类别。
- 验证：新增昼夜边界（含0/1回合起点）、任务起止与跨夜关联、不同队伍及回合倒退后的场次隔离、异常单行 JSON、组合筛选和损坏行跳过检查；默认快速校验通过：464项、0失败、0错误，排除10项仿真；离线回放确认 stderr 与持久化日志不混入响应 JSON。未执行多日仿真或真实模型任务。本环境只有 Python 3.12，创建仓库 `.venv` 后验证；Python 3.11 需由仓库 CI 补充确认。
