# 战斗模块设计（v2.0 / 32进16）

状态：已实现捣乱鬼白天破坏与夜间守口、开拓者三火箭轮射，以及满级防线后的BOSS召唤与薄弱点进攻；验证范围见变更记录。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 战斗设计](../1.0版本设计文档/战斗.md)。

## 目标与边界

默认采用三座火箭：开拓者每晚在公共格按实际冷却轮流操作，每回合至多开火一座。工人继续安全采矿与守墙；捣乱鬼在唯一朝炮塔缺口守口承伤，有队友通行时侧移让路。附近威胁清除后满级火箭继续攻击敌方墙。按经济模块的防线、备包及可执行预算门槛消费余款，优先批量购买BOSS召唤令；召唤落点优先敌方背面薄弱入口，生成后的机器人朝敌方基地推进，逐回合先清除攻击路径上的最近敌方阻挡物。

## 关键设定与原因

- 继承1.0的火箭轮射、操控者分配和阵营隔离时，先核对四角色及新机器人集合，避免沿用“所有机器人均是系统浪潮”的假设。
- 新攻击数值以v2.0任务书为依据；接口中实际下发的状态与规范冲突时记录证据，不凭历史参数补造。
- 加特林伤害估算已按任务书 §4.5.4 调整为每颗25；排序使用当前血量，先检查射程、建筑阻挡、最近机器人命中及90°扇形约束。同回合已安排的伤害仅用于避免无效重复打击，不将被其他子弹覆盖的存活机器人当作已经消失的弹道障碍。
- 直射占位与移动占位分别维护；默认弹道起点为武器格，人物仍阻挡弹道。依据当回合目标评价相邻操控格，用投影位置计算换位后是否可命中，不修改原始地图观测；无有效弹道的固定格允许替换，有效固定格保持稳定。规则歧义及可配置边界见本阶段比赛资料说明。
- 三座火箭按平台实际冷却轮射，每回合最多由开拓者操控其中一座，不假设三炮能在同一回合由同一角色开火。捣乱鬼守口与通行细节见防御模块的最新记录；显式混合阵型保留已有加特林控制和弹道校验。

## 变更记录

### 2026-10-10 - 机器人朝基地清障与失败换位

- 策略：按用户要求，以敌方基地为持续进攻方向，每回合重新检查机器人到基地占用格的路径。最近的敌方炮塔、围墙或角色挡住路径时先攻击该单位；超过射程则先接近，下一次观测再决定阻挡物是否仍在。不能按预计伤害提前越过活墙或炮塔，也不为远处、偏离当前进攻路径的弱墙改道。召唤位置继续使用背面薄弱入口排序。
- 设定：沿用现有 `line_cells` 的保守格子遍历，角点擦碰也纳入检查；人物阻挡是本次用户明确要求的机器人进攻策略，与炮台 `projectile_characters_block` 配置独立。机器人射程保留任务书的三格。友方单位、归属未知的公共机器人、矿石和NPC不成为攻击目标，改找可达且射界畅通的站位；无可达站位时保留路径受阻诊断。不可攻击障碍封住入口时允许通过其他墙位绕行清障。
- 设定：机器人模块独立记录曾实际观测的敌方炮塔，失去视野后保留其固定位置；明确死亡、重新进入普通己方共享视野却未出现、或基地变更时移除。历史人物位置不用于攻击。历史炮塔通过机器人专用目标列表参与本地校验，日志标记 `last_seen_building`，不改写当前敌方可见列表，不声称历史血量仍为当前血量。攻击是否合法与伤害／拆除是否成功仍须区分。
- 设定：同一隐藏炮塔在两个不同站位攻击均非法、且至少一次落在两格以内时，暂停把旧记录当成可攻击目标，保留其占位并尝试绕行；重新看见炮塔后恢复清障。此处理防止炮塔已不存在却仍持续攻击旧坐标，不把非法反馈视为确认死亡。
- 设定：只关联紧邻上一回合的机器人指令与反馈；明确 `false` 时禁止该机器人在相同站位重复攻击同一目标落点，重新寻找不同站位，该失败记录在机器人消失、换日或基地变更时清理。移动后位置未到达则暂避该落点四回合。机器人寻路目标必须有畅通射界并排除失败站位，避免简单重寻路仍返回“已在攻击位置”。
- 原因：所提供日志里三个BOSS在71～98回合分别连续28次攻击非法；其到基地连线经过历史炮塔 `(8,20)`／`(8,22)`，原分支只检查距离且不消费机器人攻击失败反馈。本次实现用户指定的清障方式，不能据此宣称已确认平台拒绝原因。
- 经验教训：建筑失去视野不等于已拆除，角色旧位置也不等于当前障碍；本地接受指令不等于服务器允许或实际命中。官方文字未明确可控机器人攻击路径的完整碰撞口径，本次沿用保守遍历并记录策略选择，不把角点规则改写成已确认的官方规则。
- 验证：新增18项快速检查覆盖七类敌方阻挡物、最近阻挡优先、逐层清障后继续攻击基地、偏离路径的弱墙、四向镜像、友方／NPC／公共机器人绕行、超射程接近、隐藏炮塔及明确死亡／视野证据、历史人物失效、三个日志位置与友方遮挡、Agent连续请求、过期隐藏目标绕行／重新观测、非法攻击换位、缺失／跨回合反馈、移动碰撞和换日清理；旧NPC入口检查改为先换位再攻墙。Python 3.11.17 的 `.venv/bin/python tools/run_checks.py` 默认快速模式通过935项，失败／错误均为0，耗时47.52秒。省略10项仿真及独立策略基准，实际判题器攻击、角点碰撞与清障效果仍需后续对战反馈。

### 2026-10-10 - 余款BOSS背面部署与持续进攻

- 策略：召唤优先选敌方迎敌方向的背面。在背面内按缺口、墙等级、墙当前血量选择突破口；背面没有合法可用落点时才回退到其他入口。背面生成的机器人沿背面薄弱入口进攻，避免生成后立即绕向正面较弱城墙；仍先破墙，下一次实际观测确认墙消失后持续攻击基地。旁移到正面的机器人沿用原薄弱入口策略。
- 设定：迎敌方向取敌方基地中心指向本方基地中心的向量，背面取反向半平面；本方基地缺失时使用地图中心作参考。采用双倍中心坐标处理2×2基地，横纵换边保持一致。这是可见基地的几何偏好，不证明敌方背面没有隐藏炮台或角色。地图边界、双方建造禁区、NPC、占用、待生成位置和决策截止预算仍须满足。
- 原因：用户提供的第三天299～329回合单位决策节选中，出现的预算字段均为492金币；原代码已有余款机器人采购和薄弱入口进攻，但未明确优先背面，背面部署后也可能因正面墙更弱而重新绕向正面。金币数本身不能证明存在可用买手、完整防线或可完成的采购行程。
- 经验教训：不能把几何背面等同安全位置，也不能把购买或合法召唤反馈当作生成、命中、破墙或胜利证据。所有召唤位置继续在双方建造区之外，生成数量、旁移和攻击效果需按夜间原始报文确认。
- 验证：新增快速边界检查覆盖背面与正面弱墙的取舍、背面内部缺口／等级／血量优先级、双轴四向镜像、无背面合法落点时回退、预算截止、四张召唤令逐回合使用且落点不重复，以及观察到背面墙消失后转攻基地。最终快速检查结果见同日经济模块记录；未运行完整仿真或官方对战。

### 2026-10-09 - 默认三火箭与夜间捣乱鬼守口

### 2026-10-09 - 夜间加特林换位、弹道模型与不射击诊断

- 策略：给直射武器按可实际命中目标的站位分配炮手；不再因为炮手已经邻接武器而永久停在无射界格。保持工人加特林与开拓者火箭分工、单角色单动作和清敌后夜采；自定义非公共格布局也按选定站位执行夜间移动。
- 设定：新增 `projectile_origin`（默认 `weapon`，可选 `controller`）和 `projectile_characters_block`（默认 `true`），默认保留旧假设；配置改变仅影响直射弹道，射程与加特林扇形仍以武器格校验。建筑／中立物、最近机器人、电磁能量、火箭溅射、受保护机器人及同回合伤害结算保留。候选站位以投影人物占位调用同一目标选择器；只复用已计算结果做日志，不为诊断增加目标搜索。记录操控者、射程内目标数、畅通弹道数、阻挡类别数量与每类限量样本，区分换位、路径不可达、入口退让、忙碌、冷却、无人操控、无目标和弹道受阻。
- 原因：用户提供的第98／99回合各有12个射程内目标，第100回合有8个；原模型分别将11／11／7条弹道判为基地遮挡，余下一条到机器人31027的弹道被工人20012所在的 `(31,11)` 遮挡。原站位计划只看邻接与距离，执行分支也存在忽略选定站位的情况，因此加特林20020一直不发攻击指令。改用 `(33,10)` 后，原模型可以选择 `(31,12)` 作为落点。
- 经验教训：炮手被分配、已经回防、攻击指令合法与实际命中是不同状态；人物的移动障碍清单不能证明人物也阻挡子弹。缺少官方结算证据时保留默认并暴露明确选项，不能通过直接删除人物障碍宣称修好了官方弹道规则。当前换位仅证明程序能发出原模型下的攻击，实战伤害仍需后续观测。
- 验证：新增20项快速检查，使用去除原请求标识的98～100回合相关节选，覆盖阻挡数量／人物样本、三次有限请求中的两步换位后攻击、四角镜像、非公共格显式布局、投影不修改观测、替代规则配置、受保护机器人、无人操控、截止预算恢复占位及入口协作。`.venv/bin/python tools/run_checks.py` 在本地 Python 3.12.14 下通过673项，失败／错误为0，耗时20.75秒；本地没有 Python 3.11，既有 GitHub CI 使用3.11.10。省略10项仿真与独立基准，未验证官方判题器伤害、多日生存或胜率。

### 2026-10-09 - 满级防线后的BOSS召唤与薄弱点突破

- 策略：己方规划墙位和配置炮塔全部建成、所有现有墙和炮塔达到三级后启用进攻，不要求基地也达到三级。仅购买和使用最高级 `BossRobotSummonOrder`，不因金币不足降级购买其他机器人。选择突破口时严格按无墙、墙等级升序、同等级墙当前血量升序排序；从合法召唤位置接近该突破口，先攻击选定墙，确认墙消失后转向敌方基地。已有缺口时直接进攻基地。
- 设定：BOSS召唤令价格以当回合 `weaponShopList` 为准，任务书默认120金币；每回合最多安排一名空闲角色采购或召唤。防线满级后为BOSS积攒金币，修墙和低血量角色恢复仍优先。白天使用召唤令以等待夜间首回合生成，每天最多十次，不重复预约己方待生成位置；上回合明确非法时释放对应计数和位置，重复请求复用响应而不重复计数。机器人归属仅以 `summonRobotList` 为依据，使用机器人ID发送一格移动或单目标攻击；缺少射程字段时按任务书取三格。
- 设定：禁止在双方基地及建造区、NPC处召唤，同时保守避开当前占用格。当前接口没有数值化的建造区定义，采用仓库现有布局的基地周边两格范围推导；该边界属于实现假设，需要官方地图或判题器核验。敌方基地与墙由接口全图下发，可直接用于薄弱点选择；不推测隐藏英雄或炮塔的位置。
- 原因：旧实现没有购买机器人召唤令，也未把本方可控机器人接入动作账本；机器人无指令会原地待命，不能依赖浪潮AI替本方攻墙或攻基地。只按距离或血量选墙会违背先缺口、再等级、最后血量的优先级。
- 经验教训：`targetTeam` 表示攻击目的阵营，不代表机器人所有权；同一机器人可同时出现在公共列表和己方列表。攻击合法性不等于墙已被摧毁，必须依据下一回合墙观测切换阶段，不能按预计伤害提前转向基地。召唤位置有禁区，无法把机器人直接生成在墙格或基地格；进攻路线需要与其他单位的移动预约共享。
- 验证：新增43项满级门槛、BOSS采购与资金预留、每日限额／失败回滚／缓存、机器人归属、召唤位置与镜像、缺口／等级／血量排序、NPC占位、同等弱墙距离、破墙后持续攻基地以及截止预算检查。项目 `.venv` 的 Python 3.12.14 运行 `tools/run_checks.py` 默认快速模式，612项通过，失败／错误为0，耗时19.92秒；本地没有 Python 3.11，GitHub CI 使用3.11。`git diff --check` 通过。省略10项仿真及独立基准；这些检查覆盖协议、合法性、排序和有限状态转换，不代表真实判题器对战或多日胜率验证。

### 2026-10-08 - 加特林与双火箭分工、血量优先和清敌采矿

- 策略：默认配置由三火箭改为 `["rocket", "rocket", "gatling"]`。开拓者所有夜晚回到两座火箭的公共格轮射，删除第三晚起敌方卡位以及黄昏提前赶往敌方的入口；白天任务的回程预算恢复指向己方武器。工人在独立站位操作加特林，附近敌人清除后立即进入现有安全夜采流程，敌人重新逼近时按回程距离与安全余量召回。
- 设定：加特林位于原第三个武器格，靠侧面入口；火箭保留原前两个武器格。加特林按实际首个命中机器人的观测血量降序选择，伤害25/颗，保持等级数量、90°扇形、建筑弹道阻挡及阵营隔离校验；先安排加特林伤害，再选火箭目标。两座三级火箭在本地防守半径内无存活威胁时攻击射程内敌方墙，不再要求加特林也为三级；仅剩一两面墙时重复合法落点补齐三级目标数量。开拓者每回合仅操控一座火箭，未绕过接口的单角色单动作限制。
- 原因：三火箭专用的公共格、整组三级检查和第三晚人员切换会阻止混合武器正常调度；直接沿用原威胁分数不能满足最高血量优先。加特林清敌后仍绑定工人会损失夜间采矿机会。
- 经验教训：武器组合变更须同时检查建造类型、独立操控格、轮射筛选、攻墙前置条件与守墙角色选择。瞄准被小机器人挡住的高血量目标并不代表命中了它；全部伤害在回合结束结算，待下一次观测确认清敌后才释放工人。加特林受城墙阻挡，仅能射击实际畅通弹道上的敌人；本次未改变围墙或猜测判题器的弹道结算。显式非公共格布局回退为开拓者／工人的分开操控，不能交换两者岗位。

### 2026-10-08 - 捣乱鬼独立调度与生存优先

- 策略：识别 `imp` 并在每回合常规任务、经济和防守寻路之前调度。捣乱鬼不加入原工人／开拓者炮手集合；危险时优先中断破坏并移动，安全时前往对方半区矿石的邻接空格，逐回合发送 `destroy`，没有安全目标时待命或安全回撤。
- 设定：切比雪夫距离下，对可见工人、开拓者、捣乱鬼均保留抓捕一格加下一回合移动的余量；白天驾驶敌人按两格移动评估。敌方角色失去视野后保留三回合观测，并按离开视野时间扩大可达范围；明确死亡或次日复活边界清理旧观测。夜间全部下发机器人均纳入避险，不用 `targetTeam` 推定安全；缺少射程／攻击力时依据任务书 §4.7.2，射程下限为三格，按类型取伤害。眩晕无剩余时长字段，不据此放行危险站位。
- 设定：行进路线屏蔽攻击／抓捕范围加一步移动余量；破坏站位还必须避开剩余引导回合内的潜在可达范围。逃离时先拒绝占用格和本回合预约格，优先降低即时抓捕风险，再降低潜在机器人伤害，最后增加与威胁的距离；一步走不出危险区域时按累计风险寻路绕开障碍，搜索超时仍保留局部逃离判断。无法发出有效逃离动作时记录 `imp_no_safe_escape`，移动尚未离开危险范围时记录 `safe_exit=false`，不能误报为保证存活。
- 原因：旧模型仅把 `worker`／`pioneer` 视为可调度角色，指令账本不支持 `imp` 和 `destroy`；现有基地防守的机器人目标阵营筛选不适用于深入敌方矿区的捣乱鬼。
- 经验教训：破坏期间全图暴露，不能用单回合静态安全判断覆盖四回合站桩；抓捕会立即致死，不能为了保住破坏进度继续原地执行。局部视野、未来机器人生成位置及无路可逃场景无法由策略保证绝对不死，真实对战需要继续观察。
- 验证：新增36项快速指令、半区镜像、连续引导、中断、死亡复活、驾驶抓捕范围（包括黄昏失去车辆前的可达距离）、敌方视野记忆、全类型机器人、默认射程、绕墙路径／预约格和预算截止边界检查；保留原工人／开拓者防守回归。使用 `.venv` 的 Python 3.11.17 运行 `tools/run_checks.py` 默认快速模式，540项通过，失败与错误均为0，跳过10项仿真，独立基准未运行；未运行完整多日仿真或真实判题器对战。
