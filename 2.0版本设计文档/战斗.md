# 战斗模块设计（v2.0 / 32进16）

状态：已实现捣乱鬼白天破坏与夜间守口、开拓者三火箭轮射、BOSS召唤与基地优先进攻，以及夜间单工人侦察和机器人共享清障；验证范围见变更记录。

依据：[v2.1 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.1%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 战斗设计](../1.0版本设计文档/战斗.md)。

## 目标与边界

默认采用三座火箭：开拓者每晚在公共格按实际冷却轮流操作，每回合至多开火一座。敌方基地存活时，每晚派一名工人到敌基地附近维护进攻方向的共享视野，另一名继续原有采矿与守墙调度；捣乱鬼在唯一朝炮塔缺口守口承伤，有队友通行时侧移让路。附近威胁清除后满级火箭继续攻击敌方墙。机器人采购沿用经济模块的首日及后续预算规则；首日工人占墙位与召唤共用上下侧炮塔判定，优先选择没有已知炮塔的一侧，召唤衔接已选缺口，第67回合前等待实际占位；首张召唤提交后，后续坐标限制在首张位置两格内。末段尚无首张预约且没有可用缺口时，结合无炮塔侧偏好选择薄弱入口，其他天沿用背面薄弱入口。机器人进入射程且有畅通落点就持续集火基地；否则先绕到可攻击基地的空闲站位，确认没有可行绕路后才清除挡路的人物、炮塔、围墙。受阻机器人优先原地集火或换位加入共享清障，移动避开队友已安排的射线；不为旁边未挡路的炮手改道。

## 关键设定与原因

- 继承1.0的火箭轮射、操控者分配和阵营隔离时，先核对四角色及新机器人集合，避免沿用“所有机器人均是系统浪潮”的假设。
- 攻击数值以v2.1任务书为依据（与v2.0一致）；接口中实际下发的状态与规范冲突时记录证据，不凭历史参数补造。
- 加特林伤害估算已按任务书 §4.5.4 调整为每颗25；排序使用当前血量，先检查射程、建筑阻挡、最近机器人命中及90°扇形约束。同回合已安排的伤害仅用于避免无效重复打击，不将被其他子弹覆盖的存活机器人当作已经消失的弹道障碍。
- 直射占位与移动占位分别维护；默认弹道起点为武器格，人物仍阻挡弹道。依据当回合目标评价相邻操控格，用投影位置计算换位后是否可命中，不修改原始地图观测；无有效弹道的固定格允许替换，有效固定格保持稳定。规则歧义及可配置边界见本阶段比赛资料说明。
- 三座火箭按平台实际冷却轮射，每回合最多由开拓者操控其中一座，不假设三炮能在同一回合由同一角色开火。捣乱鬼守口与通行细节见防御模块的最新记录；显式混合阵型保留已有加特林控制和弹道校验。
- 捣乱鬼破坏目标限于敌基地所在角落，横纵坐标各取靠该角落的外侧40%，留出中央20%的缓冲带；中部、左下和右上共享采矿区域不纳入破坏候选。范围同时约束目标缓存、行进选择与最终 `destroy` 校验，安全逃离和夜间守口仍按原调度执行。
- 机器人召唤令采购以当回合存在存活敌方基地为前提；敌方基地全图可见，血量归零或从报文移除后立即停止所有等级采购、取消在途采购任务，并释放采购角色与金币预算。

### 2026-10-13 - 占位与攻击失败关联、停滞后的提前协同清障

- 策略：保留当前可执行的基地攻击；其余机器人在移动未刷新距敌基地的最近距离或基地攻击被明确拒绝时累计停滞，计数达到三次后优先共同清除基地方向上的已观察敌方障碍，再尝试绕行。有可见工人挡路且多台机器人能攻击时集中攻击该工人；已有基地射手不加入清障。移动实际刷新最近距离、基地攻击获得匹配的合法反馈后解除停滞；工人离开攻击通道或障碍实际消失后重新选择目标，不按预计伤害提前判死。
- 设定：匹配上一回合实际下发的机器人ID、动作、目标格、当前位置及占位错误，保留八回合内的占位观测。只有基地攻击同时获得明确失败反馈且其路径经过该观测格时，才共享四回合的基地攻击路线暂避，其他机器人不再重复换用经过同格的基地落点。占位错误与射击反馈先分别收集，再关联，避免命令顺序影响结果。暂避到期、普通共享视野确认格子已空、实际移入该格、换日或敌基地变化时释放证据；已接受的原站位原落点仍须通过当前真实射线校验，但不因别人的失败推测而被停用。新日志字段 `approach_stalls`、`failed_base_lane_count` 用于解释切换。
- 原因：本次第95回合机器人31035移入 `(8,21)` 被明确占位拒绝，第98回合 `(8,23)` 同样被拒绝；第100～102回合31036从 `(7,21)` 更换三个基地落点，反馈全部为false，其当前模型下的路径均经过 `(8,21)`。原逻辑仅按单个落点保存射击失败，且始终先寻找基地路线，再共享清障，导致折返和重复试射。工人10010的最后可见记录停在第73回合，后续报文只有基地与墙，不能由旧坐标断言它当前仍在那里。
- 经验教训：找到理论路线不能证明进攻有进展；移动碰撞也不能单独证明弹道被阻挡。两类反馈结合仅支持短期策略避让，不能补造占位者的身份、血量或当前可见性。此次保持指令账本对攻击目标的约束，未知格不被当成可攻击敌人；角色不可见时只能清除已观察到的墙、记忆中的固定炮塔或继续合法行进，不能宣称已实现盲打隐藏工人。true仍只代表指令合法，不证明伤害、死亡或通道已释放。

### 2026-10-12 - 保留基地攻击与统一缺口进攻寻路

- 策略：可控机器人先沿用必要的协同让路，再为所有剩余机器人分配当前可执行的基地攻击，最后统一寻找到基地畅通射界的可达站位。侦察缺口只作为真实通路，不再作为必须经过的移动目标；删除独立进缺口／清缺口移动分支，避免已能攻击的机器人被拉走或两套寻路交替折返。
- 设定：原有内侧协同让路判断同时覆盖站在相关入口上的前车，仍以队友通路和内侧空间改善为依据；保护其他机器人的射线，使用当前占位和移动预约，不提前释放前车所在格。保留入口穿越的实际观测记忆供协同让路选入口使用，但不以未穿越为由强制移动。机器人没有可执行攻击或可达攻击站位时，仅在观测到侦察工人占据入口、且假设工人离开后确有可达攻击站位时等待；假设腾空只用于等待判断，不授权移动，也不修改观测。真实移动和该等待判断共享射线保护及失败落点避让。
- 原因：本次首夜71～75回合中，已攻击基地的机器人被 `robot_enter_scout_gap`／`robot_clear_scout_gap` 改派移动，另一台在攻击位置寻路与缺口寻路之间折返。根因是独立缺口分支先于直接攻击，并非机器人移动速度变慢。通用规则不绑定日志坐标、单位ID、阵营或固定回合。
- 经验教训：入口是到达攻击位置的手段，不能成为打断输出的额外目标；同时不能取消真实堵路时的前车让位。命令合法仅能帮助选落点，不证明命中；日志中的双方基地掉血也不能等同单台机器人的伤害归因。采购、召唤位置、工人侦察、炮台、防御、自进化与模型提示保持原逻辑。
- 验证：新增6项快速检查覆盖首夜两台直接攻击后下一次观测三台可攻击、四向镜像与变更ID、已观察旁移后继续攻击路线而不折返、侦察工人占口时保留其他射线／替代路线、工人离开后仍无攻击通路时不误报等待。保留窄门让位、失败让位不提前放行及原有射线保护检查；原先要求能直接攻击的单台机器人仍先进入缺口的断言更新为原地攻击。相关55项快速检查通过。Python 3.11.17 的 `.venv/bin/python tools/run_checks.py` 默认快速套件通过1351项，失败／错误为0，省略11项仿真及独立基准；未运行完整仿真或官方对战。

### 2026-10-12 - 基地角落横移解除内侧射线卡位

- 策略：有受阻队友时，内侧机器人除继续深入外，还可在相同通道深度横移一格。横移不得恶化任何已可达队友的路径或减少可用内侧空间，且必须让队友到内侧攻击站位的可达路径出现或缩短，或者严格减少本方位置与基地射线在可用内侧格上的占用；没有收益的等深度移动仍被拒绝。先比较队友路径改善数，再比较释放的内侧格数，最后使用原通道深度与ID排序，避免无关前排持续深入而延迟真正堵住入口的机器人让位。
- 设定：沿用既有八邻域、2×2基地、真实占位、失败避让、射程与弹道判断。候选新格须保持基地攻击能力并避开其他已可攻击队友的射线；路径对照只投影候选让位机器人的一步，其他人物、建筑、机器人、NPC和预约均保留。每回合最多额外让位一台，受阻队友在该回合等待，下一回合以实际坐标恢复通行。日志增加 `ingress_routes_improved` 和 `inner_space_gain` 说明让位收益。
