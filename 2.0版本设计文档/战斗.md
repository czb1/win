# 战斗模块设计（v2.0 / 32进16）

状态：已实现捣乱鬼独立破坏与避险调度、工人加特林与开拓者双火箭分工；其他新战斗规则仍有待办，验证范围见变更记录。

依据：[v2.0 任务书](../比赛文档/v2.0-32进16/《未来战争》v2.0%20任务书.md)、[v2.0 接口文档](../比赛文档/v2.0-32进16/《未来战争》v2.0%20接口文档.md)。历史实现见 [1.0 战斗设计](../1.0版本设计文档/战斗.md)。

## 目标与边界

默认采用一座加特林与两座火箭：工人操作加特林，开拓者每晚轮流操作两座火箭。加特林优先攻击可实际命中的最高当前血量敌人，附近威胁清除后工人恢复安全采矿，三级火箭继续攻击敌方墙。继续梳理可控机器人等其余 v2.0 指令约束。

## 新规则与待适配事项

| 规则或接口变化 | 需要核对和适配的事项 |
|---|---|
| 新增 `imp`，所有角色可 `catch`，成功获得20金币并使目标阵亡 | 单位分类、8邻域目标、动作互斥以及同回合互抓的结算边界 |
| 加特林每颗伤害25，电磁炮能量为20×等级 | 伤害估算、目标排序与原有武器校验的数值依据 |
| `teamOur.summonRobotList` 下发本方可控机器人 | 归属以己方列表为依据，区分可控单位、敌方单位与系统浪潮 |
| `roleCommandMap` 和动作结果映射可包含可控机器人ID | 为本方可控机器人核对 `move`、`attack` 通道，不将其当作炮台操控者 |
| 可控机器人无指令时待命，次日清除 | 指令调度、存活集合更新与跨日状态清理 |

## 关键设定与原因

- 继承1.0的火箭轮射、操控者分配和阵营隔离时，先核对四角色及新机器人集合，避免沿用“所有机器人均是系统浪潮”的假设。
- 新攻击数值以v2.0任务书为依据；接口中实际下发的状态与规范冲突时记录证据，不凭历史参数补造。
- 加特林伤害估算已按任务书 §4.5.4 调整为每颗25；排序使用当前血量，先检查射程、建筑阻挡、最近机器人命中及90°扇形约束。同回合已安排的伤害仅用于避免无效重复打击，不将被其他子弹覆盖的存活机器人当作已经消失的弹道障碍。
- 两座火箭仍按平台实际冷却轮射，每回合最多由开拓者操控其中一座；工人与开拓者的动作锁各自独立。可控机器人等其余适配待逐项核验。

## 待验证

- 武器等级与新伤害数值、目标数量、射程及冷却边界。
- 抓捕距离、目标失效、动作冲突和同时互抓。
- 本方可控机器人移动与攻击、敌方ID拒绝、次日清除。
- 保留原炮手轮射与回防的回归覆盖；真实对战表现另行验证。

## 变更记录

### 2026-10-08 - 加特林与双火箭分工、血量优先和清敌采矿

- 策略：默认配置由三火箭改为 `["rocket", "rocket", "gatling"]`。开拓者所有夜晚回到两座火箭的公共格轮射，删除第三晚起敌方卡位以及黄昏提前赶往敌方的入口；白天任务的回程预算恢复指向己方武器。工人在独立站位操作加特林，附近敌人清除后立即进入现有安全夜采流程，敌人重新逼近时按回程距离与安全余量召回。
- 设定：加特林位于原第三个武器格，靠侧面入口；火箭保留原前两个武器格。加特林按实际首个命中机器人的观测血量降序选择，伤害25/颗，保持等级数量、90°扇形、建筑弹道阻挡及阵营隔离校验；先安排加特林伤害，再选火箭目标。两座三级火箭在本地防守半径内无存活威胁时攻击射程内敌方墙，不再要求加特林也为三级；仅剩一两面墙时重复合法落点补齐三级目标数量。开拓者每回合仅操控一座火箭，未绕过接口的单角色单动作限制。
- 原因：三火箭专用的公共格、整组三级检查和第三晚人员切换会阻止混合武器正常调度；直接沿用原威胁分数不能满足最高血量优先。加特林清敌后仍绑定工人会损失夜间采矿机会。
- 经验教训：武器组合变更须同时检查建造类型、独立操控格、轮射筛选、攻墙前置条件与守墙角色选择。瞄准被小机器人挡住的高血量目标并不代表命中了它；全部伤害在回合结束结算，待下一次观测确认清敌后才释放工人。加特林受城墙阻挡，仅能射击实际畅通弹道上的敌人；本次未改变围墙或猜测判题器的弹道结算。显式非公共格布局回退为开拓者／工人的分开操控，不能交换两者岗位。
- 验证：新增22项默认建造、所有夜晚分工、双火箭冷却轮射、四角完整周界、清敌采矿／重新回防、工人阵亡补位／回血、开拓者阵亡、攻墙与单墙落点、弹道阻挡、最高血量、阵营和扇形检查；更新旧第三晚卡位断言。项目 `.venv` 的 Python 3.12.14 运行 `tools/run_checks.py` 默认快速模式，569项通过，失败／错误为0；本地没有 Python 3.11。省略10项仿真回放及独立基准，未执行真实对战或多日收益验证。

### 2026-10-08 - 捣乱鬼独立调度与生存优先

- 策略：识别 `imp` 并在每回合常规任务、经济和防守寻路之前调度。捣乱鬼不加入原工人／开拓者炮手集合；危险时优先中断破坏并移动，安全时前往对方半区矿石的邻接空格，逐回合发送 `destroy`，没有安全目标时待命或安全回撤。
- 设定：切比雪夫距离下，对可见工人、开拓者、捣乱鬼均保留抓捕一格加下一回合移动的余量；白天驾驶敌人按两格移动评估。敌方角色失去视野后保留三回合观测，并按离开视野时间扩大可达范围；明确死亡或次日复活边界清理旧观测。夜间全部下发机器人均纳入避险，不用 `targetTeam` 推定安全；缺少射程／攻击力时依据任务书 §4.7.2，射程下限为三格，按类型取伤害。眩晕无剩余时长字段，不据此放行危险站位。
- 设定：行进路线屏蔽攻击／抓捕范围加一步移动余量；破坏站位还必须避开剩余引导回合内的潜在可达范围。逃离时先拒绝占用格和本回合预约格，优先降低即时抓捕风险，再降低潜在机器人伤害，最后增加与威胁的距离；一步走不出危险区域时按累计风险寻路绕开障碍，搜索超时仍保留局部逃离判断。无法发出有效逃离动作时记录 `imp_no_safe_escape`，移动尚未离开危险范围时记录 `safe_exit=false`，不能误报为保证存活。
- 原因：旧模型仅把 `worker`／`pioneer` 视为可调度角色，指令账本不支持 `imp` 和 `destroy`；现有基地防守的机器人目标阵营筛选不适用于深入敌方矿区的捣乱鬼。
- 经验教训：破坏期间全图暴露，不能用单回合静态安全判断覆盖四回合站桩；抓捕会立即致死，不能为了保住破坏进度继续原地执行。局部视野、未来机器人生成位置及无路可逃场景无法由策略保证绝对不死，真实对战需要继续观察。
- 验证：新增36项快速指令、半区镜像、连续引导、中断、死亡复活、驾驶抓捕范围（包括黄昏失去车辆前的可达距离）、敌方视野记忆、全类型机器人、默认射程、绕墙路径／预约格和预算截止边界检查；保留原工人／开拓者防守回归。使用 `.venv` 的 Python 3.11.17 运行 `tools/run_checks.py` 默认快速模式，540项通过，失败与错误均为0，跳过10项仿真，独立基准未运行；未运行完整多日仿真或真实判题器对战。

### 2026-10-08 - 战斗观测与动作诊断

- 策略：为每回合记录所有下发机器人、可见敌方单位和己方单位，保留原战斗算法；记录炮台动作、操控者、冷却、射程、目标距离与校验拒绝原因。
- 设定：快照从原始报文保存，己方可控机器人依据 `summonRobotList` 标识；其他机器人归属保持未知。失去视野的敌方位置放在独立历史观测字段，带最后可见回合。
- 原因：原夜间摘要仅列出附近部分机器人，难以对照录像还原完整局面；合法反馈不能证明命中或移动成功。
- 经验教训：攻击目标阵营不是所有权，消失不是死亡，状态变化不是伤害来源证明；未支持的新角色／机器人在诊断中明确标记，不借日志改动宣称v2.0调度已经适配。
- 验证：增加机器人／捣乱鬼／死亡原始字段保存、视野变化和反馈证据检查；快速校验及64次基线响应对照见自进化模块本次记录，未执行真实对战和多日仿真。
