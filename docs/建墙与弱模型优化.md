# 建墙与弱模型适配

## 问题与改动

原策略存在几个可以从代码直接确认的限制：

- 每天围墙总数限制为 `4 + day * 2`，首日即使资源足够也最多造 6 面墙。
- 只有编号排序第一的工人建墙；已有墙只按总数统计，偏离计划的旧墙也会抵消缺口。
- 赶路仅预留下一步坐标，两名工人可能认领同一个远处建筑点。
- 默认按距地图中心的距离排序后删除前两格作为入口，入口位置和炮台集中布局均依赖绝对坐标的排序。
- 新闻模型推测的停矿会直接禁止采集，错误推断可能让工人停工；任务模型必须在 JSON 字符串中转义整段 Python。

现在按如下方式运行：

1. **两名工人协作补缺口。** 取消日墙数上限，按布局中尚未建成的格子计算需求。已有石料足够覆盖缺口时，另一名工人继续经济活动。赶路与施工均认领目标，命令仍共用金币与占位校验。
2. **固定对齐的外围。** 以基地完整 2×2 占地为锚，墙始终落在距离占地 2 格的同一矩形边界；换边后镜像。临时占位与建造失败不会把墙向外挪一格。默认完整外围 20 格，扣除后侧两格通道和默认两座直射炮各一格射击口，剩余 16 个计划墙位。
3. **保留火力与通路。** 三座默认炮台分散在朝向地图中心的两侧；加特林和电磁炮预留朝外的射击口，火箭无须开射击口。自定义斜角直射炮会同时预留弹道擦过的两侧角格。建墙同时检查基地、各炮台、商贩、武器店及各类现有矿区的原有可达路线；第二名工人也会考虑本回合第一面新墙。经过通道的角色不会被误判为永久障碍。
4. **临近夜晚使用已有材料。** 附近继续采满一批通常更划算，但白天剩余时间不足时，会优先带现有石料回去建墙。保留原有提前回防逻辑。
5. **减少重复寻路。** 同一角色、相同占位快照共享 BFS 结果；墙、移动预留等占位变化会自动使用新的结果，超时后仍返回已校验的动作。
6. **弱模型使用简单协议。** 任务优先使用 `ANSWER\n答案` 或 `PYTHON\n代码`，不用把 Python 塞入 JSON 字符串；仍兼容原 JSON 和纯 Python 代码块。单个 JSON 外的解释文字可以恢复，但相互冲突的多个对象、同时给代码与答案、无效 Python 会被拒绝。
7. **限制无进展循环。** 仅保留最近四条任务上下文，每条至多 6000 字符；完整任务保留原有上限。同一答案或代码最多采纳两次，连续三次无效／重复提案后离开任务、返回基地。新任务会重置计数。矿区停工预测只降低优先级，以实际可见状态和采集失败反馈为准。

经济、建墙、寻路和战斗始终由确定性代码执行，不要求比赛模型理解地图或控制工人。

## 验证方法

```bash
python3 -m unittest discover -s tests -v
python3 tools/fortification_benchmark.py
python3 tools/fortification_benchmark.py --agent-root /path/to/old-checkout
```

新增回归覆盖首日超过六面墙、双工人同回合建墙与目标认领、换边镜像、矩形边界、射击口、联合建墙后的可达性、缓存占位变化、黄昏材料调度、弱模型格式恢复及退出循环。CI 使用 Python 3.11.10。

`fortification_benchmark.py` 固定回放首日 70 回合，包含移动占位、每次一块石料、每矿采集十次后按固定位置循环刷新、石料／金币消耗和建造。分别报告第一面墙的回合、30／50／70 回合的墙数、两名工人的建墙数、无效动作数和单次决策耗时。固定资源布局让版本间对比可复现。

## 本次实测

Python 3.11.10、GitHub Actions。首轮代码提交 `36c5679` 的 75 项测试通过；随后补充斜角自定义电磁炮射击口回归。完整运行结果以 PR 的最终 CI 为准。

同一受控首日回放，对比优化前 `11e8404`：

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 第一面墙出现回合 | 15 | 13 |
| 第 30 回合墙数 | 6 | 15 |
| 第 50 回合墙数 | 6 | 16 |
| 首日结束墙数 | 6 | 16 |
| 两名工人分别建墙数 | 6 / 0 | 8 / 8 |
| 无效动作 | 0 | 0 |

首轮测试里的 1300 个静态状态协议回合最慢约 2.01 ms；独立首日回放最慢约 26.86 ms。这些是该 runner、该场景的观测值，不是所有地图的耗时上界。首日墙数增加约 167%，仅指上述固定资源回放。

## 边界

- 官方建造区域仍只出现在无法访问的内网图片中。默认矩形沿用 demo 的距离假设；这次修正的是坐标稳定性与策略执行，并未证明与正式判题器的黄色／蓝色区域完全一致。已确认的地图应继续使用 `layout_mode: "explicit"` 配置合法绝对坐标。
- 显式坐标视为用户提供的完整白名单，不额外移动坐标或自动删除射击口；自定义布局需自行预留通道及直射弹道。
- 默认射击口只保证指定朝外方向畅通，不等于 360° 无遮挡。后侧入口也不是封闭城墙。
- 不自动拆除已有错位墙。修正会用于后续建造及新对局，避免主动拆掉现有防线。
- 受控回放不是官方比赛引擎，不模拟机器人攻击、计分、随机地图、任务奖励或升级。更多墙和更少无效决策不等同于已经验证胜率或十天生存。
