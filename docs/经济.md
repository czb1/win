# 经济模块设计

本文是经济模块唯一的长期设计文档。以后采矿、交易、采购、升级、资源预留与回防调度的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 建立可持续收入，并在炮塔、基地、防线、药剂和升级之间分配共享金币。
- 经济动作必须服从背包容量、商品库存、商店邻接、共享预算和黄昏回防时间。
- 防线几何归入防御模块；任务和知识复用归入自进化模块。

## 当前策略

- 矿石按可达性、实际价格和交付成本选择，不硬编码单一矿种。
- 两名工人中保留一人维持收入，另一人可承担建造或采购；初始炮塔阶段允许共同施工。
- 优先处理已持有物品和必要采购，再继续低优先级建墙；背包满且当日尚未卖过时集中卖矿；卖后新采矿留到次日。
- 采购顺序为生存补给、关键武器升级、围墙升级、健康基地升级；危急基地回血和重建墙补级可提前插入。
- 为尚未建好的炮塔和下一阶段升级预留金币，失败购买设置退避，避免每回合重复无效请求。
- 根据剩余白天回合、路径长度和 `return_margin` 决定继续采集还是携带现有资源返程。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| `stone_batch` | 默认 10，临近夜晚按正面缺口缩减 | 在运输摊销和尽快形成防线之间取平衡 |
| 卖矿频次 | 每名工人每白天一次访问 | 混合矿在同次访问中逐项卖完，避免反复往返 |
| `return_margin` | 5 | 为未知占位、路径变化和黄昏切换保留缓冲 |
| 购买失败退避 | 5 回合 | 防止库存、资金或路径暂时不满足时持续发送同一无效动作 |
| 药剂携带 | 每名角色最多一瓶 | 保留应急能力，同时避免挤占矿石和任务用品容量 |

## 已知风险与验证

- 默认费用与合法建造区仍可能来自 demo 推导，正式环境应优先使用已确认配置。
- 固定价格、无限矿藏的回放不能代表真实随机地图、库存和对局胜率。
- 更早升级会降低短期现金和采矿时间，必须同时比较存活、输出和动作失败率。
- 回归应覆盖多工人预算竞争、满背包、断矿、价格变化、购买失败、升级闭环、黄昏返程与镜像地图。

### 2026-09-16 - 武器升级与墙体采购顺序

- 策略：武器先升到二级，再优先完成三级升级；受威胁墙体在武器升级之后获得加固优先级。
- 设定：武器升级排序为 0/1，暴露墙体为 1.25；仍有一级武器时不启用紧急墙体采购例外。物品使用与采购共用含墙体受击信息的排序。
- 原因：避免墙体升级券抢占关键火力升级资金，同时兼顾第三夜的三面防护。
- 经验教训：只考虑墙体风险会挤压火力建设；采购优先级必须结合已有武器等级与共享预算。
- 验证：PR #13 的 Python strategy checks（run 35053714092）已通过，包括武器等级 1、2、3 时采购顺序的回归以及经济进度回放；未据此推断实战胜率。
- 策略：采矿目标变化或实际采集时保留 INFO 日志，普通移动和逐回合耗时改为 DEBUG，减少诊断噪声。

### 2026-09-16 - 每日集中卖矿与安全夜间采矿

- 策略：建墙保留尚未建成炮台的短施工通路，避免采购与建墙工人绕行争道。每工人每白天最多集中卖一批资源，通常在建设采购前进行；背包满或无矿可采可提前用掉当日机会。混合矿连续多次 sell 属于同次访问，失败可重试，执行其他动作后不再重开访问，次日重置。
- 设定：保留建墙石料；卖后新矿和夜间采矿留到次日。夜间无临近可见威胁则恢复采矿，路径避开机器人攻击范围加两格缓冲，并根据远处来袭怪和回塔路程预留时间；白天卖后仅就地采矿并检查返程预算，夜间安全时再恢复外出采矿。
- 原因：旧的批量阈值或凑够升级费用就出售会反复打断采矿；无怪夜晚固定站岗浪费生产时间。
- 经验教训：策略必须由确定性代码和队伍会话状态执行，不依赖弱模型记忆。进程重启会丢失当日卖矿记录。合并保留不可达炮台恢复、就近顺手采矿和目标变化诊断。
- 验证：覆盖混合矿同次出售、失败重试、禁止同日二次访问、次日重置、怪清完立即采矿、重新接敌回防、无炮台避险及完整采矿路径安全。离线回放不代表完整比赛胜率。


### 2026-09-17 - 首夜经济回放校准

- 策略：调整离线仿真输入与验收口径；原有策略和理想场景断言保留，以显式 `controlled` 档运行。默认 `sample` 档复用仓库接口样例的地图、矿点及价格，重新初始化 75 金币、空背包和无炮塔开局；`random` 档增加固定种子的随机初始矿点与可配置密度。
- 设定：样例矿点为石/铁/铜各 2 个，售价分别为 1/3/5；旧夹具为近基地循环刷新、售价 1/6/10。新档每矿 10 次采集、耗尽后下一回合跨地图换位，避开双方推导建造区、角色、中立单位和现存矿点，保留末份矿石同回合共享规则。新档从第 0 回合开始，覆盖 70 个白天回合。入夜对比统一取第 69 回合结算后。
- 原因：真实截图的首夜余额约 60/85，用户反馈通常至多有一座二级塔；旧测试预期三座二级塔，把有利几何与翻倍售价混入了实战预期。截图也出现任务奖励，不能只用最终金币反推采矿收益。
- 经验教训：接口样例是夜间快照，不是实战开局记录；每种矿 2 个和固定售价只是可复现基线，不是截图中所有对局的精确资源数量。矿点密度、初始坐标、地图刷新与任务收入应分别校准，不得添加硬性炮塔等级上限来迎合结果。矿产收入、已花金币、库存与到位火力必须一起比较。
- 验证：新增八组样例/随机种子左右镜像首夜回放，检查金币守恒、矿点数量、资源余量、刷新禁区、三座塔与三名操控者到位，并检查整体二级及以上炮塔数量中位数不超过 1。新增末份矿石并发采集、下一回合刷新可见、固定种子复现、镜像初始图和密度配置测试；完整验收同时保留原三日重建、五日升级与独立策略基准。结果写入 `artifacts/calibration/first-night.json`；未模拟战斗、敌方抢矿、任务奖励、价格新闻，不据此宣称完整比赛一致性。


### 2026-09-18 - 单炮手下的夜间采矿

- 策略：公共炮位布局仅保留一名炮手，另一工人夜间使用现有选矿及库存积累流程，矿石仍留至白天出售。
- 设定：专职夜间采矿不再受基地附近威胁或炮台返程时间限制；自身及路径的危险检查保持。炮手死亡后采矿者立即转为补位者，补位期间停止采矿。
- 原因：火箭轮射无需三名角色同时守炮，释放工人增加夜间产出。
- 经验教训：仅删除上层召回判断不够，底层 stockpile 仍可能因 wave_budget 为负拒绝采矿；该例外仅作用于新分工的夜间工人。
- 验证：同一夜间请求断言一名工人开炮、另一名采矿，并验证个人危险及死亡补位；原日间交易、采购和升级逻辑不变。

### 2026-09-21 - 工人异常恢复、库存配送与备战消费

- 策略：离开商店且持有适用基地升级券的工人先完成配送，再进入卖矿流程；配送目标保持到使用、不可达或失效，受损基地和重建墙补级仍可抢占。连续八次移动只覆盖不超过四格时，释放并短暂避开原配送目标。卖过矿的工人无邻接矿时，允许现有返程校验下的两步内补采。备战阶段一旦进入就不退回采矿阶段。
- 设定：武器已满级后，备战预算增加基地升级的商店与基地行程；有武器待升级时保持原备战预算；进入 economy_rounds 后，买不起优先升级券可检查更便宜且来得及配送的升级/修理用品，始终保留未建炮塔资金。商店批量购买、每日一批卖矿和作战策略保持原流程。
- 原因：升级券配送之前的卖矿分支会延迟已支付物品的使用；只计算炮塔的采购预算遗漏基地；卖后就地采矿失败直接返回会绕过原有就近补采；单项升级价格超出预算会阻塞后续可负担商品。
- 经验教训：弱模型只适合在规则已经验证过的少量候选中选编号。连续两轮未发指令或识别到移动循环才启动异常恢复，最多三个候选（使用已有升级券或附近采矿），有机器人、正在任务、已被回防锁定或工人正承担修墙任务时不介入。先执行确定性候选，模型通过现有 prompt/llmResp 异步通道返回 choice；禁止模型生成动作、坐标或代码。下一回合重新检查库存、目标、路径、动作冲突和从实际操作格返程的时间；方案最多保持八回合。与新闻共享每日最多三次额度，新闻先行，恢复调用冷却十二回合。错误、缺失、跳回合或过期回复不能阻塞工人。
- 验证：新增升级券与卖矿优先级、可负担替代采购与建炮资金保留、基地备战行程、卖后补采、配送目标保持与循环释放、模型异步接入、无效回复、目标失效、回防锁定、限额与冷却、重复请求幂等测试；完整验收保留全部多日回放及独立策略基准。本地仅有 Python 3.12，使用仓库 .venv 且未新增依赖；CI 继续使用 Python 3.11。离线测试不等于实战胜率，实际模型输出质量仍需对局日志观察。

### 2026-09-21 - 卖矿后离开商人

- 策略：工人完成当天唯一一次出售后，仍可按原规则顺手采集附近可返程矿点；若附近没有合适矿点，则离开商人并返回已分配炮位附近或基地，而不是保持无指令原地等待。
- 设定：`sold_workers` 仍禁止当天再次开启卖矿行程；回基地兜底不受 `allow_spare` 限制，因此备战阶段关闭额外采矿时也不会把工人锁在商人旁。夜间库存积累逻辑保持不变。
- 原因：原分支把“禁止第二次出售”与“禁止任何重新定位”绑定在一起；卖完后附近无矿时 `earn()` 直接返回 `False`，导致工人在 vendor 邻格连续没有指令。
- 经验教训：交易次数约束应落在交易状态上，而不是用空闲来隐式实现；完成交易后的角色必须有明确的下一落点，否则恢复器在有机器人、无附近矿或备战锁定时无法保证接管。
- 验证：将原“卖过矿后白天无指令”回归改为“保持 `sold_workers` 且不追远矿，同时发出返回基地的移动指令”；夜间仍允许远程 stockpile 行程，完整 Python 3.11 验收由仓库 CI 执行。

### 2026-09-22 - 入夜前资源兑现与三级城墙

- 策略：保留原有前期采矿、卖矿、建炮流程；每天白天 `tick >= 60` 增加确定性资源兜底，先交付已有物品，再用可支配金币采购能在入夜前用掉的升级券；`tick >= 65` 在紧急基地回血、重建墙补级之后优先就近用券，不再固守更远的旧配送目标。
- 设定：用 `Turn.tick` 判断每日窗口，兼容 `round_origin`；兜底放在卖矿、异常恢复及回防动作之前，已执行动作与正在进行任务的开拓者不被抢占。购物和用券都枚举实际站立格，核算行走、购买、使用及返回已分配炮位的真实路径，有行走时留一回合拥堵余量；已站在炮位且可原地使用时允许用到白天最后一回合。晚期只买一张、先交付再采购，不购买来不及兑现的整批券；缺炮建造资金、共享预算、容量、购买失败退避、重复升级认领继续生效。修墙工人不被购物抢走。
- 设定：健康城墙允许正常批量采购并从一级逐级升至三级，优先于健康基地；急救、危急基地回血、重建墙补级及武器升级维持优先。第 60 回合前仍为武器存钱；第 60 回合后买不起或来不及配送武器券时，允许购买更便宜且可及时使用的城墙券。只有城墙待升级时也会进入备战，不会一直采矿到入夜。
- 原因：旧批量采购条件直接跳过健康墙，且基地未满级时普通墙券一直被过滤；用券可能排在卖矿和回防之后；旧采购返程预估以最近炮塔而非角色分配炮位为终点，末段固定余量也会拒绝安全的就近升级。
- 经验教训：目标是把闲置资源转成当夜实际防御，不能机械要求金币归零或一回合使用所有券。每角色每回合只能执行一个动作，满级、无合法目标、商店不可达、时间不足时保留资源；炮位安全与任务进行状态仍需校验。全部规则在 Python 中完成，不新增依赖、模型提示或模型调用。
- 验证：新增每日窗口/回合起点、健康墙两级采购、危急基地、廉价替代、旧目标切换、用券压过卖矿、返岗绕行、实际炮位、远近同类目标、建炮预留、满背包、无商店、失败退避、任务隔离、双工人认领和左右镜像十回合采购交付回放。五日回放改为验证城墙确实升到三级，并把用于墙体的资金计入经济保有量，避免旧断言奖励囤币。最终结果见本次 PR 的验证记录；离线回放不模拟完整夜战，不能直接证明胜率提升。本地仅提供 Python 3.12.14，使用仓库 `.venv` 且未安装依赖，Python 3.11 由仓库 CI 验证。

### 2026-09-22 - 基地紧急升级阈值

- 策略：入夜前仍优先把可交付金币换成补墙和墙体升级；基地只有在墙体全部恢复并达到三级后，且当前血量低于满血四分之一（1500 的基准为 375）时，才购买对应基地升级券。
- 原因：固定使用 750 作为基地紧急阈值会让基地券插入补墙流程；墙体未完成时，基地券不能把本可延长防线的现金转成防御。
- 经验教训：紧急规则要与资源兑现顺序绑定，血量阈值也要对应规则中的满血值；仍保留购买路径、背包容量、金币和入夜前可使用时间检查。
- 验证：新增低血量基地与未完成墙体的优先级回归；墙体升到三级后，同一笔可用金币才允许购买基地升级券。

### 2026-09-22 - 第四天才启用黄昏余钱批量墙券

- 策略：第 1 至第 3 天沿用原有武器优先流程，先把武器升级到三级；第 4 天起才启用本次黄昏余钱扫尾。扫尾仍先检查武器升级，只有武器券买不起或已经来不及完成配送时，才将可在入夜前完整交付的余钱批量换成墙券。
- 设定：第 4 天起，墙券批量数量同时受背包、金币、每面墙使用动作、返回实际炮位路径和剩余白天回合约束；基地券继续放在补洞、重建墙补级和普通墙升级之后，低于满血四分之一只作为紧急基地升级条件。
- 原因：过早把现金分给普通墙会拖慢武器三级；原有黄昏逐张采购又可能在入夜时留下超过一张墙券成本的余钱。
- 经验教训：策略切换日必须显式固定，不能让“临近入夜”隐式改变前三天的武器建设节奏；批量采购必须按完整配送链路核算，避免用券数量超过可交付数量。
- 验证：新增前三天单张墙券与第四天批量墙券回归；完整验收 345 项测试通过，0 失败、0 错误、0 跳过，独立策略基准 PASS。

### 2026-09-23 - 三级武器后的黄昏墙体兑现

- 策略：第 4 天及以后，若武器已经全部三级而墙仍有二级升级空间，黄昏扫尾允许优先完成墙券购买和使用，不因工人无法在同一小段白昼内返回远处炮位而放弃整次防御强化。
- 原因：第五天第 60 回合只剩十个白天回合，原路径同时要求商店、墙体、炮位三段都完成，导致工人即使有金币和墙券目标也可能整段不动作，资源保持不变直到入夜。
- 经验教训：在武器已经满级的后期，墙体强化本身是夜间生存收益；返岗检查仍用于前三天、武器未满级和非黄昏流程，后期放宽只作用于合法且能在入夜前使用的墙券。
- 验证：新增第四天三级武器、远炮位仍可购买二级墙券的回归；保持前三天单张购买和原有返岗安全检查。

### 2026-09-23 - 备战截止回合不再让工人原地空转

- 策略：工人被分配到备战阶段但在当前截止回合前无法完成销售往返时，不再停在墙边等待；先尝试把附近矿石带回基地作为下一次销售库存，仍不可行时向基地移动。
- 原因：原收入规划器会因为销售和返岗无法在截止回合前完成而拒绝所有采矿候选，建设函数随后没有备用动作，造成工人从约第 38 回合一直无指令到入夜。
- 经验教训：阶段截止时间只能限制远距离销售准备，不能让角色进入无动作状态；每个白天回合都应保留可执行的采集或回基地动作。
- 验证：新增第 38 回合、无石料且墙体建设暂不可行的工人回归；完整门禁保留原有多日回放和策略基准。

### 2026-09-22 - 全墙三级采购门槛与先交付后补货

- 策略：把城墙优先从排序改为采购硬门槛：只要存在未满三级的现存墙，或已识别的破墙重建/补级任务，就不购买基地升级券。库存里的券、其他工人的配送认领、本回合尚未结算的升级指令均不算墙已升级。已拥有的基地券仍可用于回血，不再为受损基地绕过门槛购券。
- 设定：普通墙先全部升到二级，再把正面墙升到三级，最后升级侧墙；此阶段约束同时作用于购买、正常使用、黄昏就近用券和异常恢复候选。重建墙补级优先于普通升级，可连续追平其记忆中的目标等级；不凭别的工人持有低级墙券提前购买下一等级墙券。
- 设定：工人持有可用券时，即使仍在商店旁，也先配送使用，再考虑卖矿、追加采购及一般施工。保留同等级多目标批量采购，配送预算覆盖逐个目标和最后一次用券后返回实际分配炮位的完整路程。武器满级后的备战预算补入待升级墙的商店、墙位路线及操作次数。重建墙出现后借用一名采购工人提前补级，不必等普通采矿阶段结束；其他工人的阶段分配保持原流程。
- 原因：排序允许在墙券不可买、已被携带或路线不合适时继续选基地券；旧商店分支会先买另一批券，卖矿分支也只优先配送基地券；批量路线曾用第一面墙到最近炮台的估计代替最后一面墙到分配炮位的实际返程。
- 经验教训：购买完成不等于防御形成，后续阶段只能由服务端回传的实际建筑等级解锁。阶段优先级不能被“就近用券”或弱模型恢复绕过。资金、路线和时间不足时不承诺所有墙必定满级，但不主动采购无法按预算完成配送的升级批次。本次不新增模型调用或依赖。
- 验证：新增采购受库存/认领/价格/失败退避/缺货/不可达影响时仍不买基地券、全部二级后正面三级、镜像朝向、黄昏旧目标、禁止虚拟墙级、异常恢复阶段约束、商店用券优先于销售采购、重建早期补级、独立等级记忆、批量最终返程，以及重建墙购买并使用两级券后入夜无余券的镜像连续回放。五日验收增加每夜升级券剩余数为零、全墙三级前基地券采购数为零的断言。完整验收结果随提交交付；本地使用已有 Python 3.12 `.venv`，Python 3.11 继续由 CI 验证。

### 2026-09-23 - 入夜前卖矿收尾与两档墙券同次采购

- 策略：白天 tick 40 起在回防锁定前处理可出售的工人库存；已经完成当日出售的工人可以再次出售后来采到的矿石。持有可用升级券时仍优先完成配送，未携带券的工人先清仓再购物。

- 设定：普通墙在武器满级后可预购后续阶段券，重建墙保留提前补级；已持有一级升二级券的工人在商店可接着购买二级升三级券，完整配送预算覆盖已购前置券。实际用券继续遵守真实等级和正面中间向两侧的顺序。
