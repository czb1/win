# 经济模块设计

本文是经济模块唯一的长期设计文档。以后采矿、交易、采购、升级、资源预留与回防调度的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 建立可持续收入，并在炮塔、基地、防线、药剂和升级之间分配共享金币。
- 经济动作必须服从背包容量、商品库存、商店邻接、共享预算和黄昏回防时间。
- 防线几何归入防御模块；任务和知识复用归入自进化模块。

## 当前策略

- 矿石按可达性、实际价格和交付成本选择，不硬编码单一矿种。
- 两名工人中保留一人维持收入，另一人可承担建造或采购；初始炮塔阶段允许共同施工。
- 优先处理已持有物品和必要采购，再继续低优先级建墙；每名工人每白天集中卖矿一次，卖后新采矿留到次日。
- 采购顺序为生存补给、三座武器二级、基地二级、武器三级和围墙升级；基地低于 750 生命时提前升级。
- 为尚未建好的炮塔和下一阶段升级预留金币，失败购买设置退避，避免每回合重复无效请求。
- 根据剩余白天回合、路径长度和 `return_margin` 决定继续采集还是携带现有资源返程。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| `stone_batch` | 默认 10，临近夜晚或已有迎敌缺口时缩减 | 在运输摊销和尽快形成防线之间取平衡 |
| 卖矿频次 | 每名工人每白天一次访问 | 混合矿在同次访问中逐项卖完，避免反复往返 |
| `sell_batch` | 20 | 基准中维持首夜升级并减少交易往返；黄昏清算不受此阈值限制 |
| `sell_batch_max` | 40 | 限制单次采销周期，给升级交付和回防留出时间 |
| `night_economy_enabled` | true | 共享火箭操控与安全夜间出售；关闭后沿用普通操控分配及已有安全夜间采矿 |
| `return_margin` | 5 | 为未知占位、路径变化和黄昏切换保留缓冲 |
| 购买失败退避 | 5 回合 | 防止库存、资金或路径暂时不满足时持续发送同一无效动作 |
| 药剂携带 | 每名角色最多一瓶 | 保留应急能力，同时避免挤占矿石和任务用品容量 |

## 已知风险与验证

- 默认费用与合法建造区仍可能来自 demo 推导，正式环境应优先使用已确认配置。
- 固定价格、无限矿藏的回放不能代表真实随机地图、库存和对局胜率。
- 更早升级会降低短期现金和采矿时间，必须同时比较存活、输出和动作失败率。
- 回归应覆盖多工人预算竞争、满背包、断矿、价格变化、购买失败、升级闭环、黄昏返程与镜像地图。

## 变更记录

### 2026-09-16 - 合并最新 main 的经济与共享操控策略

- 策略：保留 main 的十二格连续城墙、武器和基地升级里程碑、每工人每白天一次出售访问及已有安全夜间采矿；三炮共享交接完成后才启用新增夜间出售。
- 设定：沿用 main 的出售批次 20、最大批次 40；迎敌面完整后才安排白天共享回防站位。临近夜晚施工从实际施工格复核完整回防路线，共享角色已到位时保留两回合余量。
- 原因：最新 main 已独立改进经济策略；直接切换共享站位会让镜像地图上的施工工人提前离开最后一格迎敌缺口。
- 经验教训：共享操控不能挤占核心防线施工；夜间出售与白天每日一次访问应分别核对，不能把允许的夜间经济动作算作白天重复出售。关闭共享开关后仍保留 main 已有的安全夜间采矿。
- 策略：共享交接时角色可能站在队友的回防位置，若自己的路线被堵，仍核对当前站位是否阻断队友并主动让行；保留已到位操作员的原有让行检查。
- 设定：第三炮没有当前防守需求时沿用 main 的空闲工人释放，不强留一名工人在无敌夜晚驻守；共享采销工人继续检查独立回防预算，另一名工人沿用已有安全囤矿逻辑。
- 验证：合并最新 main 后，Python 3.11 `.venv` 全套 234 项测试通过，其中夜间专项 17 项；默认及镜像三日回放迎敌六墙完整、三名操作员夜前到位、零非法动作，白天出售均满足每工人每日一次访问。建设基准完成十二格连续墙、零断连；升级基准完成三炮及基地三级、零非法动作；740 个静态机器人的战斗基准保持三炮开火、最慢决策 36.14 毫秒。下方 208 项与约 54% 收益为合并前旧基线的验证记录，不能据此推断相对当前 main 的收益。

### 2026-09-16 - 火箭共享操控释放夜间采矿工人

- 策略：两名操控者到位后，第三名工人在夜间执行安全采集与批量出售；每次出发按矿点实际采集格或小贩实际交易格计算往返，不套用白天第 70 回合的交易截止时间，清场后的矿石可继续留到次日。
- 设定：沿用实际收购价格、背包容量、施工石料预留、销售批量、采矿目标保持与失败退避。出发和逐回合继续采矿均核对行走、一次采集或出售、回防、敌人攻击距离及默认 `return_margin=5`；受击或破墙后至少保留五回合召回期，没有安全经济路线时恢复第三名操控者。
- 原因：当前夜间工人在冷却或清场后仍驻守，限制了资源获取；程序根据可观察威胁释放人力，避免依赖任务模型调度。
- 经验教训：资源收入不能仅以日末金币衡量；需要同时比较夜间采集与出售、可开火次数、返程延迟及基地受损。夜间不建造、不额外采购，采矿路径不能穿过仍驻守的操控者。
- 设定：共享回防角色全部距独立站位至多一步时，允许用两回合站位余量完成经过通路复核的本地侧墙施工；其他侧墙仍保留默认五回合缓冲。
- 原因：夜间新增收入会使次日承担更多升级交付，不能让已到位的施工工人带着石料空等最后五回合；保持既有补洞、侧墙扩建与夜前操控准备。
- 设定：共享操控启用时，准备预算额外计入在武器资金预留后实际买得起的基地升级券采购与使用动作；夜间经济规划最多占用七成决策预算，超出时恢复第三名操控者，剩余时间优先生成开火指令。
- 经验教训：新增收入使采购工人携带更多升级券，施工工人不能把采购工人的石料当作当前可用施工库存；发生迎敌墙缺口时先采足修补该缺口的材料，再恢复普通侧墙批次，避免因为准备满批材料延误补洞。
- 验证：使用 `.venv` 的全套 208 项测试通过，包含 16 项新增回归；既有建设与升级基准保持零非法动作。有限矿量、固定价格且无敌人及任务收入的三日受控对比中，采集动作由 135 增至 235，第三夜夜前累计售矿收入由 1130 增至 1740（约 54%），第二夜夜前已完成三炮三级升级；默认与镜像回放迎敌墙完整、三名角色到位、零非法动作。该收益只描述安全空窗回放；规则正文和本地账本未限制夜间采集，尚未使用正式引擎验证夜间采集或实战收益。

### 2026-09-16 - 武器升级与墙体采购顺序

- 策略：武器先升到二级，再优先完成三级升级；受威胁墙体在武器升级之后获得加固优先级。
- 设定：武器升级排序为 0/1，暴露墙体为 1.25；仍有一级武器时不启用紧急墙体采购例外。物品使用与采购共用含墙体受击信息的排序。
- 原因：避免墙体升级券抢占关键火力升级资金，同时兼顾第三夜的三面防护。
- 经验教训：只考虑墙体风险会挤压火力建设；采购优先级必须结合已有武器等级与共享预算。
- 验证：PR #13 的 Python strategy checks（run 35053714092）已通过，包括武器等级 1、2、3 时采购顺序的回归以及经济进度回放；未据此推断实战胜率。
- 策略：采矿目标变化或实际采集时保留 INFO 日志，普通移动和逐回合耗时改为 DEBUG，减少诊断噪声。

### 2026-09-16 - 每日集中卖矿与安全夜间采矿

- 策略：建墙保留尚未建成炮台的短施工通路，避免采购与建墙工人绕行争道。每工人每白天最多集中卖一批资源，通常在建设采购前进行；背包满或无矿可采可提前用掉当日机会。混合矿连续多次 sell 属于同次访问，失败可重试，执行其他动作后不再重开访问，次日重置。
- 设定：保留建墙石料；卖后新矿和夜间采矿留到次日。夜间无临近可见威胁则恢复采矿，路径避开机器人攻击范围加两格缓冲，并根据远处来袭怪和回塔路程预留时间；白天卖后仅就地采矿并检查返程预算，夜间安全时再恢复外出采矿。
- 原因：旧的批量阈值或凑够升级费用就出售会反复打断采矿；无怪夜晚固定站岗浪费生产时间。
- 经验教训：策略必须由确定性代码和队伍会话状态执行，不依赖弱模型记忆。进程重启会丢失当日卖矿记录。合并保留不可达炮台恢复、就近顺手采矿和目标变化诊断。
- 验证：覆盖混合矿同次出售、失败重试、禁止同日二次访问、次日重置、怪清完立即采矿、重新接敌回防、无炮台避险及完整采矿路径安全。离线回放不代表完整比赛胜率。

### 2026-09-16 - 采矿日志按变化记录

- 策略：INFO 只记录工人采矿目标或模式变化；同一矿点的连续移动和采集保留在 DEBUG。矿区首次出现时记录完整快照，后续只记录新增、移除和类型变化。
- 设定：矿区 JSON 使用紧凑分隔符；增量同时携带当前矿区总数，便于从下载日志恢复变化顺序。
- 原因：实战样本中逐次采集和重复全量矿区约占日志三分之一，但绝大多数行不提供新的决策信息。
- 经验教训：保留目标切换与地图增量即可解释采矿决策，逐次 collect 更适合临时 DEBUG 复现。
- 验证：HTTP 连续采矿回归检查十回合内同一目标只产生一条 INFO，并检查矿点替换和消失的增量内容。

### 2026-09-16 - 基地升级里程碑与黄昏强制清算

- 策略：三座武器达到二级后，健康一级基地优先于武器三级和墙体升级；携带可出售矿物的工人在“商人→操作位”路线仍可完成时延后回防并立即清算。
- 设定：默认石料批次 10、出售批次 20、最大出售批次 40；正面闭合且核心升级未完成时不为侧墙启动新的采石行程，但会使用已运回的石料。
- 原因：实战第 458 回合仍携带铜 8、金币仅 22，基地未升级；对手基地 2960，且更少的墙并未妨碍其领先。
- 经验教训：金币余额、背包空间和采购交付必须形成闭环；“已经回防”不能掩盖尚未出售的有效收入。
- 验证：日经济回放保持首夜三座二级武器和正面六墙；多日回放会购买基地升级且三名操作员按时就位。新增健康基地排序回归。
