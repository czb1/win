# 经济模块设计

本文是经济模块唯一的长期设计文档。以后采矿、交易、采购、升级、资源预留与回防调度的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 建立可持续收入，并在炮塔、基地、防线、药剂和升级之间分配共享金币。
- 经济动作必须服从背包容量、商品库存、商店邻接、共享预算和黄昏回防时间。
- 防线几何归入防御模块；任务和知识复用归入自进化模块。

## 当前策略

- 矿石按可达性、实际价格和交付成本选择，不硬编码单一矿种。
- 两名工人中保留一人维持收入，另一人可承担建造或采购；初始炮塔阶段允许共同施工。
- 优先处理已持有物品和必要采购，再继续低优先级建墙；背包满时先卖矿。
- 采购顺序为生存补给、关键武器升级、基地升级、后续武器和围墙升级；受损建筑可提前插入修复。
- 为尚未建好的炮塔和下一阶段升级预留金币，失败购买设置退避，避免每回合重复无效请求。
- 根据剩余白天回合、路径长度和 `return_margin` 决定继续采集还是携带现有资源返程。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| `stone_batch` | 6 | 在运输摊销和尽快形成防线之间取平衡 |
| `sell_batch` | 12 | 减少过于频繁的往返交易，同时避免背包长期占满 |
| `return_margin` | 5 | 为未知占位、路径变化和黄昏切换保留缓冲 |
| 购买失败退避 | 5 回合 | 防止库存、资金或路径暂时不满足时持续发送同一无效动作 |
| 药剂携带 | 每名角色最多一瓶 | 保留应急能力，同时避免挤占矿石和任务用品容量 |

## 已知风险与验证

- 默认费用与合法建造区仍可能来自 demo 推导，正式环境应优先使用已确认配置。
- 固定价格、无限矿藏的回放不能代表真实随机地图、库存和对局胜率。
- 更早升级会降低短期现金和采矿时间，必须同时比较存活、输出和动作失败率。
- 回归应覆盖多工人预算竞争、满背包、断矿、价格变化、购买失败、升级闭环、黄昏返程与镜像地图。

### 2026-09-16 - 武器升级与墙体采购顺序

- 策略：武器先升到二级，再优先完成三级升级；受威胁墙体在武器升级之后获得加固优先级。
- 设定：武器升级排序为 0/1，暴露墙体为 1.25；仍有一级武器时不启用紧急墙体采购例外。物品使用与采购共用含墙体受击信息的排序。
- 原因：避免墙体升级券抢占关键火力升级资金，同时兼顾第三夜的三面防护。
- 经验教训：只考虑墙体风险会挤压火力建设；采购优先级必须结合已有武器等级与共享预算。
- 验证：PR #13 的 Python strategy checks（run 35053714092）已通过，包括武器等级 1、2、3 时采购顺序的回归以及经济进度回放；未据此推断实战胜率。
- 策略：采矿目标变化或实际采集时保留 INFO 日志，普通移动和逐回合耗时改为 DEBUG，减少诊断噪声。

### 2026-09-16 - 采矿日志按变化记录

- 策略：INFO 只记录工人采矿目标或模式变化；同一矿点的连续移动和采集保留在 DEBUG。矿区首次出现时记录完整快照，后续只记录新增、移除和类型变化。
- 设定：矿区 JSON 使用紧凑分隔符；增量同时携带当前矿区总数，便于从下载日志恢复变化顺序。
- 原因：实战样本中逐次采集和重复全量矿区约占日志三分之一，但绝大多数行不提供新的决策信息。
- 经验教训：保留目标切换与地图增量即可解释采矿决策，逐次 collect 更适合临时 DEBUG 复现。
- 验证：HTTP 连续采矿回归检查十回合内同一目标只产生一条 INFO，并检查矿点替换和消失的增量内容。
