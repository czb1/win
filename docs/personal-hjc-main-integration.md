# personal/hjc 与主分支整合验证

基准：远程默认主分支 `main`，提交 `0bd97af`（v1.0.4）。远程不存在 `master` 分支。

## 保留的主分支实现

- 工人阶段切换、固定运输目标、施工石料保留和每批 10 块石料。
- 移动失败反馈、重复绕圈退避、视野外敌方建筑记忆。
- 持续建墙、炮台与独立操控站位分配、狭窄通道协同让行。
- 现有配置、依赖清单和发布工作流。

## 补充的问题修复

- 炮台被墙等障碍隔离时，不再把工人锁定在无法完成的回防任务上；原先固定的分配也可解除。计算可达性时允许参与回防的队友让开，避免破坏协同回防。
- 当天无法完成卖矿往返时，允许利用空闲白天采集实际步行两步内的矿点。返程按照具体操控站位计算，同时遵守移动失败退避和默认 5 回合余量。
- 不在建设采购阶段切换前启动额外采矿。该约束避免改变运输先后顺序，挤占建墙或武器交付时间。
- 日志记录接口下发的矿区坐标、工人的矿区目标以及跳过采矿的原因。连续 HTTP 测试验证视野外矿区坐标驱动移动、采集、刷新换矿及无矿时停止采集。

## 验证结果

使用仓库 `.venv`（Python 3.11.5），未安装或增加依赖。

- `python -m unittest discover -s tests -q`：188 项全部通过，包括主分支的三天破墙重建、协同回防和 HTTP 测试。
- `python tools/worker_logistics_benchmark.py`：同一回放器对照上述主分支和整合版，8 组场景均无非法动作；武器等级、操控者到位数量、围墙总数与迎敌墙数量完全一致。
- 附近铁矿非镜像场景采集次数 53 → 56、夜前库存价值 7 → 10，增量为 3 块未出售石头；收入不变。其余 7 组夜前状态一致。具体数据见 [对照数据](personal-hjc-main-benchmark.json)。
- `python tools/strategy_benchmark.py`：静态 740 机器人场景三座炮台均发出攻击。
- `python tools/progression_benchmark.py`：五天受控经济回放无非法动作，三座武器与基地均达三级。

回放没有官方机器人战斗、任务收入或完整判题结算，不能用于证明实战胜率。远商店非镜像场景的迎敌墙仍为 5 段，与主分支一致；本次没有将其描述为已完成六段防线。
