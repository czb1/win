# 防御模块设计

本文是防御模块唯一的长期设计文档。以后基地布局、建墙、炮塔位置、通路、回防和应急物品的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 优先形成连续迎敌面，同时保留采矿、购物、接任务和炮塔操控所需的通路。
- 防线不能只以“墙数量”衡量，必须同时检查缺口、建成顺序、内圈连通和炮塔可操作性。
- 武器如何选择目标归入战斗模块；资源获取与采购顺序归入经济模块。

## 当前策略

- 默认按基地完整 2×2 占地定位十二格墙：迎敌面六格，两翼各三格。先从正面选定起点连续延伸，再建设两翼。
- 背侧保持开放作为运输和回防通道，不再额外建墙封后。
- 默认炮塔集中在基地后角并保留一个公共操控格；连续墙方案默认配合可越墙的火箭，避免直射武器被己方墙遮挡。
- 建造前验证基地、炮塔、商店、任务点和既有矿区的可达性；同回合新墙也进入后续工人的占位快照。
- 空闲角色会让出规划墙位；失败建造格进入退避，避免重复卡在同一位置。
- 临近夜晚优先用已有材料完成可建墙位并回防，不为了凑批次滞留远端。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| 默认外围 | 正面与短侧翼，背侧开放 | 集中材料保护迎敌方向，减少绕行 |
| 默认墙位 | 12 格（正面六格、两翼各三格） | 按共享边连续施工，禁止跳格或仅对角接触 |
| 默认炮塔 | 三座火箭 | 连续墙会遮挡直射武器；火箭越墙能消除这一直接冲突 |
| 建造失败退避 | 20 回合 | 避免非法坐标、占位或规则差异导致持续重复失败 |
| 显式布局 | 用户坐标视为完整白名单 | 已确认的官方坐标应优先于 demo 推导，不擅自平移或删改 |

## 已知风险与验证

- 默认建造区仍需与正式判题器核对；显式坐标应作为比赛环境首选。
- 三火箭不是全局最优证明，冷却期和不同机器人组合仍需实战比较。
- 运输通道可能成为绕后入口；复杂地形也可能让保守连通性检查少建墙。
- 回归应覆盖四角基地、左右镜像、矩形边界、补洞顺序、双工人建造、完整内圈可达、公共操控位、单工人轮射、死亡补位和夜间采矿。

### 2026-09-16 - 侧翼受损重建与加固

- 策略：优先重建实际观测到被摧毁的侧翼格，其他墙位维持迎敌面、补洞和连续扩建顺序。
- 设定：连续回合记录墙体掉血或消失，命中计数上限为 10；第 2 天起启用侧翼重建优先级。一级墙低于 800 血，或低于 1000 血且有受击记录时可提前加固；第 3 天起检查正面、上下侧三面的升级覆盖。
- 原因：避免侧翼反复失守，同时防止把邻格扩建和满血重建墙误判为紧急采购需求。
- 经验教训：受击历史必须与当前血量、建墙顺序一起判断；扩大紧急集合会打断原有正面扩建节奏。

### 2026-09-16 - 十二格连续施工与夜间释放工人

- 策略：默认十二格蓝图先完成迎敌面，再延伸两翼；除第一格外，每格必须与已建墙共享边。两个工人共享当回合实际建墙结果，移动中的施工目标不能作为另一段墙的起点。显式布局仍尊重配置。
- 设定：起点在迎敌面选择，后续只能从已有墙的相邻格延伸。地图边缘裁掉越界格。保留可达性、受损侧翼修复和回防站位检查。
- 原因：六格防护不足，而侧后方全面扩建增加运料距离；十二格正面和短侧翼兼顾覆盖与物流。
- 经验教训：连墙不能只靠排序，必须限制候选格；施工目标预留与真正建成的墙必须分开。临近夜晚先带回正面所需材料，不能为两翼多跑矿点而拖延正面防线。采购阶段建墙工人独立带齐正面石料，不把采购工人的库存视为已送达；由采购工人完成炮台施工，建墙不得增加通往尚未建成炮台的路程，避免连续墙迫使最后一座炮台的施工绕远。回防过程中可按实际施工格计算往返时间，完成附近缺口后按时回塔。
- 验证：新增四角十二格布局、移动目标不能另起墙段、同回合相邻建墙及逐次建墙连续性回放检查；同时复跑经济开局、三天补墙和操作员回防测试。夜间安全仅依据可见机器人，不代表视野外无怪。


### 2026-09-18 - 后角三炮与单工人轮射

- 策略：默认三炮移至后角；相对基地朝向归一后的炮位为 (-1,-1)、(0,-1)、(-1,1)，公共操作格为 (-1,0)，左右及上下镜像。原十二格墙位和连续施工规则保持不变。显式布局仍使用用户坐标，无公共站位的布局沿用原分配。
- 设定：临近夜晚先保证工人能按回防余量到位，再优先从未携带待施工石料的工人中按公共操作格实际路径选择炮手，避免把正在补墙的工人提前抽走，开始回防后固定身份。夜间每回合最多操作一炮，按布局顺序轮转；冷却未结束、炮被毁或无合法目标时检查下一炮，全部不可用则留守。以实际 cooldown 为准，不假设第四回合必能开火。急救仍优先，不将临时用药视作死亡。
- 原因：利用火箭冷却释放另一名工人夜间采矿，并将操控者移到基地背面。全部由确定性代码实现，不增加模型调用，也不修改自进化方法学习与任务时限规则。
- 经验教训：公共操作格必须从空闲队友占位中释放；夜间采矿既要绕过基地威胁召回，也要解除底层为炮台回防保留的时间预算。仍保留采矿路径、矿点和工人自身危险检查。炮手死亡后另一工人停止采矿并实际走回站位，不能瞬移；基地挡住正面不保证免受侧后攻击。
- 验证：新增四角布局可达、连续轮射、实际冷却、缺炮、死亡补位、复活不抢位、急救和夜间采矿检查；最终 Python 3.11.16 完整回归 277 项通过，0 失败、0 错误、0 跳过，保留全部多日回放，独立策略基准 PASS（64.43 秒）。旧三人同时到位指标保留作观测，验收改为同一工人可操作三炮；原炮台等级、六格正面墙和多日重建断言保留。

### 2026-09-20 - 修复存活炮手回防停滞与夜间接替

- 策略：公共炮位回防使用实际占位判断；炮手不可达或连续两次位置无进展时重新选择可达角色，夜间允许未执行任务的开拓者接替。回防时让空闲队友移出通道，并为本回合后续角色预留通道；已经邻接可用炮台时先开火。
- 设定：保留正常固定炮手、实际冷却轮射和另一个工人的夜间采矿。接替者停止采矿并实际回防；无共享可达候选时回退普通分配。保留用药和任务指令优先级，不允许角色交换位置或走入仍被占用的格子。日志区分正在移动与等待，补充三名角色位置、指令和炮手停滞计数。
- 原因：459–470 回合炮手持续停在 (29,8)，三座满级炮冷却为零却无攻击指令；原规划忽略队友占位，执行受阻后仍锁定原炮手，备用工人继续采铜。
- 经验教训：存活并被分配不等于到位。新增回归使用日志中的基地、炮台和十二格墙，构造队友占据狭窄回防通道的场景；这验证调度缺口，并不将未记录的队友坐标认定为实战事实。前角三炮在现有一格武器环和十二格墙下会封闭公共位；本次最小修复保持炮位与墙位，未将围墙移到未经确认的建造区，也未打开正面缺口。三级射程为 2147483647 的本场停火不是射程不足。
- 验证：新增狭窄通道让位、开拓者接替、工人死亡后兜底、公共位外就近射击、连续移动失败召回采矿工人的测试；保留四角布局、正常轮射、实际冷却和全部多日回放。最终结果记录于本次提交说明。

### 2026-09-21 - 白天优先补洞并恢复周边墙等级

- 策略：白天先填补蓝图内被摧毁的墙位，以及两端有现存墙的连续缺口（包括转角和多格缺口），再扩建；补洞后优先购买、使用升级券，逐级追平相邻墙的最高等级。相邻等级不一致时采用较高等级，避免留下薄弱点；周边均为一级时不额外升级。
- 设定：修复目标跨日、跨重建建筑 ID 保留，并把缺口边界的等级传递给连续缺口内各格，达到目标后清除。保留急救、受损基地抢救、预算、背包、采购往返时限、多人预留、连墙、通路与回防检查；仅处理既有蓝图，不封闭预留出入口。
- 原因：原正面优先过滤会挡住侧翼补洞，普通采购还会跳过满血的新补墙，导致修复后长期停在一级。
- 经验教训：补洞和普通扩建必须区分；历史受击不代表当前仍要无限升级。识别、目标等级与优先级均由确定性代码完成，不依赖模型推理，不增加模型调用或依赖。
- 验证：新增侧翼/转角/连续缺口、跨日补洞、两级升级至邻墙等级、购物与用券优先级、一级邻墙不额外升级回归。Python 3.11.5 快速检查 289 项通过；完整验收 297 项通过，0 失败、0 错误、0 跳过，包含全部多日回放，独立策略基准 PASS（85.95 秒）。本地 HTTP 测试对 localhost/127.0.0.1 绕过环境代理。

### 2026-09-21 - 单工人批量补洞并及时返回白天工作

- 策略：保留原有白天采矿、卖矿、建设和采购阶段，仅临时借用一名工人修补实际缺口。优先保留当前补墙工人；新分配时结合已有石料与行程选择。按缺口所需石料、背包空间和当天往返施工预算备料，准备好一批后返程连续补洞，不再补一格就回矿点。
- 设定：补洞工人与返程施工状态在本批任务中保持，缺口补齐后下一回合释放；剩余升级需求不继续占用补洞工人，交回原采购、用券流程按既有优先级执行。工人死亡、回防或无可行修复动作时允许释放或改派；容量或时间不足时缩小批次。有专人补洞时，其他工人的普通建设不重复领取这些缺口，其已有石料也不虚算为补洞工人已经拿到的材料。
- 原因：上一版补洞分支只检查是否够建一格，提前绕过批量备料；有修复目标就把所有工人推入建设阶段，打乱了其他人的白天经济工作。
- 经验教训：防御优先级应约束具体临时任务，不能全局改变所有工人的阶段。补洞结束与升级完成是两个不同条件；用有限状态的确定性调度解决往返问题，不增加模型调用和依赖。
- 验证：新增双工人连续回放，检查三格缺口只需一批三石、采集全部发生在首次施工前、另一工人持续执行有效经济动作、补墙工人完工后解除分配并继续采矿；另覆盖分工稳定、返程不补货、背包容量、升级未完成也释放、死亡/回防改派和白天时间不足。Python 3.11 虚拟环境快速检查 296 项通过；完整验收 304 项通过，0 失败、0 错误、0 跳过，保留全部多日回放，独立策略基准 PASS（78.98 秒）。

### 2026-09-21 - 核心满级后用富余金币逐步升满现有墙

- 策略：基地和配置内炮台全部达到三级后，只要升级券可负担且当天采购、送达和回防时间允许，就继续购买墙升级券，把现有墙逐级提升到三级；重建墙和受损暴露墙仍保留原有更高优先级。
- 设定：普通健康墙只有在基地三级、配置炮台全部已建成且均为三级后进入采购候选；同级墙允许按背包、金币和路线批量购买升级券。普通墙升级也计入白天未完成工作，并在准备阶段预算至少一次商店往返，避免经济阶段一直持续到入夜。升级顺序继续使用既有正面优先、血量和建筑 ID 排序。
- 原因：原逻辑在批量采购时用 `bulk and building.health >= 500` 过滤健康普通墙，同时 `work_remains` 不包含普通未满级墙，导致炮台和基地已经三级、即使持有 600+ 金币也可能始终不购买 `WallUpgradeVoucher2`。
- 经验教训：升级候选和阶段调度必须同时表达同一目标；只解除候选过滤但不把墙升级纳入白天工作，仍可能让有钱的工人持续采矿而错过购物窗口。
- 验证：新增满血一级/二级墙在核心满级后购买对应升级券、核心未满级时继续优先炮台、以及有正常采矿交易条件时进入准备阶段并购买健康二级墙升级券的回归测试。最终 CI 结果以本次 develop 提交对应 workflow 为准。
