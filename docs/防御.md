# 防御模块设计

本文是防御模块唯一的长期设计文档。以后基地布局、建墙、炮塔位置、通路、回防和应急物品的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 优先形成连续迎敌面，同时保留采矿、购物、接任务和炮塔操控所需的通路。
- 防线不能只以“墙数量”衡量，必须同时检查缺口、建成顺序、内圈连通和炮塔可操作性。
- 武器如何选择目标归入战斗模块；资源获取与采购顺序归入经济模块。

## 当前策略

- 默认恢复 main 的十二格墙：迎敌面六格，两翼各三格；炮台与基地占地距离为一格，墙为两格。共享操炮开关不改变建造位置。
- 背侧保持开放作为运输和回防通道，不再额外建墙封后。
- 默认炮塔恢复 main 的迎敌侧非连续三格，保留内圈通路；按实际公共操作范围分组，不能一人覆盖时使用多人，绝不向外扩展建造区。连续墙方案默认配合可越墙的火箭。
- 建造前验证基地、炮塔、商店、任务点和既有矿区的可达性；同回合新墙也进入后续工人的占位快照。
- 空闲角色会让出规划墙位；失败建造格进入退避，避免重复卡在同一位置。
- 临近夜晚优先用已有材料完成可建墙位并回防，不为了凑批次滞留远端。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| 默认外围 | 正面与短侧翼，背侧开放 | 集中材料保护迎敌方向，减少绕行 |
| 默认墙位 | 固定 12 格，与 main 一致 | 按共享边连续施工，禁止跳格或仅对角接触 |
| 默认炮塔 | 三座火箭 | 连续墙会遮挡直射武器；火箭越墙能消除这一直接冲突 |
| 建造失败退避 | 20 回合 | 避免非法坐标、占位或规则差异导致持续重复失败 |
| 显式布局 | 用户坐标视为完整白名单 | 已确认的官方坐标应优先于 demo 推导，不擅自平移或删改 |

## 已知风险与验证

- 默认建造区仍需与正式判题器核对；显式坐标应作为比赛环境首选。
- 三火箭不是全局最优证明，冷却期和不同机器人组合仍需实战比较。
- 运输通道可能成为绕后入口；复杂地形也可能让保守连通性检查少建墙。
- 回归应覆盖四角基地、左右镜像、矩形边界、补洞顺序、双工人建造、共同操作位与独立基地通路、分散炮塔回退和夜间回防。

## 变更记录

### 2026-09-17 - 正面三塔公共站位

- 策略：以基地局部坐标为准，三塔位于迎敌方向第 3 列的连续三格，工人位于第 2 列中间格；正面墙移至第 4 列。按基地位置镜像，尝试两个纵向偏移，不采用旧个人分支的背侧三塔方案。
- 设定：规划墙位 14 格，先建正面 6 格。选择前检查边界、已有建筑、矿点/中立点、完整围墙后的公共位可达性，以及操作员站定后独立的基地访问通路。
- 原因：相邻三塔需要共同操作范围，仍应面向敌人；工人不能因独占公共格而堵住基地采购和物流。每局固定所选蓝图，防止建设一半时因临时状态改变整体布局。
- 经验教训：已建炮塔不属于新布局、受障碍限制或无公共通路时保留旧布局，用多人覆盖；显式坐标始终优先，不拆改既有炮塔。新的建造区依旧是本地推导，实际合法性需正式环境确认。
- 验证：四角公共操作位、独立访问通路、边界回退、已有塔与显式布局测试，以及镜像首日施工、三日补墙和五日升级回放。旧几何断言按新墙位调整，原经济门槛、非法动作与多日长度保留。

### 2026-09-16 - 建立四模块文档基线

- 策略：把既有建墙顺序、连续迎敌面、炮塔布局、连通性和回防策略归并到本文件。
- 设定：本文件成为防御设计的唯一维护入口，后续不再新建防御设计文档。
- 原因：墙数、缺口、通路和火力是同一个系统，分散记录会隐藏互相冲突的取舍。
- 经验教训：墙更多不代表防线更好；必须用迎敌面完成时间、缺格、通路和炮塔输出共同验收。

### 2026-09-16 - 侧翼受损重建与加固

- 策略：优先重建实际观测到被摧毁的侧翼格，其他墙位维持迎敌面、补洞和连续扩建顺序。
- 设定：连续回合记录墙体掉血或消失，命中计数上限为 10；第 2 天起启用侧翼重建优先级。一级墙低于 800 血，或低于 1000 血且有受击记录时可提前加固；第 3 天起检查正面、上下侧三面的升级覆盖。
- 原因：避免侧翼反复失守，同时防止把邻格扩建和满血重建墙误判为紧急采购需求。
- 经验教训：受击历史必须与当前血量、建墙顺序一起判断；扩大紧急集合会打断原有正面扩建节奏。
- 验证：PR #13 的 Python strategy checks（run 35053714092）已通过，包含 tests/test_defence_risk.py 的侧翼重建、跨日记忆和升级顺序用例；真实对局效果仍需实战验证。

### 2026-09-16 - 十二格连续施工与夜间释放工人

- 策略：默认十二格蓝图先完成迎敌面，再延伸两翼；除第一格外，每格必须与已建墙共享边。两个工人共享当回合实际建墙结果，移动中的施工目标不能作为另一段墙的起点。显式布局仍尊重配置。
- 设定：起点在迎敌面选择，后续只能从已有墙的相邻格延伸。地图边缘裁掉越界格。保留可达性、受损侧翼修复和回防站位检查。
- 原因：六格防护不足，而侧后方全面扩建增加运料距离；十二格正面和短侧翼兼顾覆盖与物流。
- 经验教训：连墙不能只靠排序，必须限制候选格；施工目标预留与真正建成的墙必须分开。临近夜晚先带回正面所需材料，不能为两翼多跑矿点而拖延正面防线。采购阶段建墙工人独立带齐正面石料，不把采购工人的库存视为已送达；由采购工人完成炮台施工，建墙不得增加通往尚未建成炮台的路程，避免连续墙迫使最后一座炮台的施工绕远。回防过程中可按实际施工格计算往返时间，完成附近缺口后按时回塔。
- 验证：新增四角十二格布局、移动目标不能另起墙段、同回合相邻建墙及逐次建墙连续性回放检查；同时复跑经济开局、三天补墙和操作员回防测试。夜间安全仅依据可见机器人，不代表视野外无怪。

### 2026-09-18 - 提前换班与真实移动交接

- 策略：沿用三塔公共操作位、十四格外围和独立运输通道。主炮手需要换班时提前召回健康替补，原炮手在可继续守炮时保持输出；仅有一个公共位时按撤离、进位、到位后开火逐回合交接。
- 设定：原 165 血预警保留；高于阈值时也按替补实际路程 + 两回合交接 + return_margin 估计潜在损血，结合上一连续回合的实际掉血决定提前量。替补须比原炮手更健康、超过 165 血，且下一步和接管位不致命；退出位置也必须满足非致命约束。同等条件优先保持已选替补，每人只能承担一组替补。
- 原因：仅到低血量才找人可能来不及，等血量轮换则只会浪费生产与火力。致命站位上的炮手可先执行真实撤离，再重新分配可覆盖的炮台。
- 经验教训：不能把两个角色同回合交换格子当作合法交接；唯一站位会有两回合移动停火。人员死亡、目标格被建筑占用、炮台消失或交接超过 20 回合时清理旧交接记录，避免工人被永久排除。
- 验证：连续三回合交接检查实际攻击数为 0/0/3，并覆盖替补路途中原炮手开火、失效交接清理、低血量撤离、镜像施工及原有多日回归。日志新增操作员人数、当前覆盖塔数、实际开火塔数和交接阶段。
- 最终验收结果：Python 3.11 下统一完整检查通过，242 项测试、0 失败、0 错误，独立策略基准通过；设计文档门禁通过。与 6c9562a 的同场景比较中，健康炮手场景两版均有三塔开火，致命站位场景新版先撤离并重新接管，原版继续原位开火。该比较只验证决策差异，不模拟真实基地掉血或胜率。


### 2026-09-18 - 恢复 main 建造位置，撤销外扩假设

- 策略：撤销共享操炮布局对炮台和正面墙的外移，完整恢复 main 的默认建造位置与顺序。保留一人多塔、危险判断、替补交接及显式布局白名单；多人覆盖由现有调度器按真实几何决定。
- 设定：基地 (9,22) 时炮台为 (11,22)、(11,23)、(11,20)，正面墙为 x=12、y=19..24，外围共十二格。两侧镜像与地图边缘裁剪均沿用 main。
- 原因：实战日志中 x=12 的三次造炮台、x=13 的六次建墙均失败，首夜墙和炮台为空；新位置未经官方建造区确认。此前“正面三塔公共站位”的外扩默认方案由本次恢复取代。
- 经验教训：多塔操控权限不能扩大建造权限；同步放宽模拟器建造区会掩盖真实失败。本次删除两个回放器的共享布局特例，始终按原武器一格、墙两格的独立范围校验。
- 验证：新增实战坐标回归及越区指令拒绝检查，四角检验十二格墙、炮台范围、三塔可分组覆盖和基地通路；保留左右镜像首日、三日重建、五日升级完整验收。此变更恢复 main 坐标，不宣称已获得官方引擎验证，也不包含任务路径和基地升级失败的修复。
- 衔接修复：恢复紧凑布局后，白天分配操作位时优先让携带最多石料的工人靠近尚未建成的迎敌墙，避免其提前绕往另一端而留下缺口。仍优先选择能在夜前到位的方案；施工动作继续按真实寻路与原有施工返程余量校验，未缩短安全余量。回放中的三塔覆盖需要两名到位操作者，相关断言按恢复后的几何更新，完整建墙、零非法动作和多日时长要求保留。
