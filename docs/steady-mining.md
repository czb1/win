# 持续采矿与第 70 回合备战

基线为上一版主分支 `dbebe47e9e3d7caa84cc8415444586d03c4d5fc9`。目标是提高实际采集时间比例，在首夜前把收入转化为可操作的火力。

## 修复的问题

- 旧版每回合重新选矿，又把每十块矿都计入一次卖矿运输成本，会漏掉基地旁边适合连续采集的矿区。新版把卖矿成本摊到整批库存，去下一处矿的路程则由这处矿承担。相近收益时保持当前目标，矿消失、不可达、实际价格大跌、采集失败或来不及回防时重新选择。
- 旧版近商店回放中，两人各卖 14 块后又折返各挖 2 块再卖。默认批量由 12 提高到 40，远途可增至 80，始终受背包容量约束。满包、关键建设缺钱、最后可采矿耗尽或准备截止时可以提前卖；一旦开始卖矿，就把这次可售库存清完。
- 估算卖矿动作时逐种计数；新采矿路线必须留出出售和返程时间。多个小贩不会用最远小贩的返程时间压缩本地采矿窗口。
- 根据已确认的采集动作估算每个矿的剩余量，两人共享信息。同等矿区优先分开；只有一处好矿时仍可一起挖。预计另一人到达前就会挖空的残矿，不再吸引远处工人。
- 采购员在购买、交付期间保持身份。另一名工人在返回建设区时先收集一批墙料，让采购员可以并行造炮；空闲角色让出蓝图格。临近回防时，只有核对建墙后的可达路径仍有余量，才补最后一面邻接墙或使用本地升级券。
- 当计划中的建设、升级全部完成，工人不再因固定第 40 回合的准备阶段提前中断采矿。

矿量只是估计：接口没有剩余量字段，敌方采集可能不可见。矿消失或类型变化时清除记录，失败采集退避五回合后重试；不会把模型的一句话变成永久禁采。

## 首夜时间和弱模型

默认 `round_origin: 0`，第 0—69 回合为白天，第 70 回合可直接开火，第 130 回合进入次日。准备时间仍从实际卖矿、购物、建造、交付、回防路线倒推，`economy_rounds: 40` 是有待办工作时的上限，远商店会提前开始。开拓者在第一次进攻前按返程距离停止未完成任务，不再等看见怪物才动身。

首夜的经济、建设、采购、回防、选敌全部使用代码规则、接口价格与动作反馈。新闻模型推测的停矿不再降低矿区评分，避免弱模型误判造成附近矿被跳过；真实采集失败仍会触发退避。任务解题继续使用现有短指令与沙盒反馈机制，不要求模型做经济规划。后续夜晚仍允许安全的任务继续进行。

旧的外部配置需要同步改 `round_origin`、`sell_batch`、`sell_batch_max`，否则会覆盖新默认值。只在平台明确以第 71 回合作为首夜时保留 `round_origin: 1`。

以上每个场景均有三名操控者到位、没有未交付升级券，回放中无非法动作。近商店移动减少约 20%，收入增加 12.5%。增加本地铁矿后，旧版采铁为 0，新版为 19；现金略降，但采矿次数、墙段完整性提高，武器等级保持。远商店收入下降 8—10 金币，首夜火力不变。这些结果不是所有地图上收入都增加的证明。

近商店三天有限矿回放：采集 123→134，移动 235→209，卖矿动作 14→8；第 329 回合现金 160→161，三级武器均为三座、操控者均到位。未售矿石价值为 1→101，尚未计入现金，不把库存当成已经实现的收入。

原有五天无限矿回放：双方武器和基地均升满，现金 3390→3503，采集 447→474，移动 139→134，卖矿动作 45→16。该场景从已有三座武器开始，不能当作从零建设的首日成绩。

## 验证和复现

151 项测试覆盖协议、战斗、任务解题、连续防线，以及新增的持续采矿、残矿分工、混合矿出售时间、多个小贩、弱模型误判、第 70 回合立即开火和首夜任务召回。采矿规模测试含 100×100 地图和 225 处附加矿点。无第三方依赖。

```bash
python -m unittest discover -s tests -v
python tools/day_economy_benchmark.py --case near
python tools/day_economy_benchmark.py --case local_ore --mirror
python tools/day_economy_benchmark.py --case far_shop
python tools/day_economy_benchmark.py --case remote_ore
python tools/day_economy_benchmark.py --days 3
python tools/day_economy_benchmark.py --trace
python tools/day_economy_benchmark.py --agent-root /path/to/baseline --case local_ore
python tools/progression_benchmark.py
```

完整结果见 [回放数据](steady-mining-benchmark.json) 和 [测试输出](steady-mining-test-output.txt)。这些回放没有官方地图生成、怪物战斗结算、对手和任务收入，无法证明胜率或保证任意随机地图都能达到相同火力。实际建造范围和费用仍沿用原项目可配置规则，需在官方引擎实战验收。
