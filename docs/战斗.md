# 战斗模块设计

本文是战斗模块唯一的长期设计文档。以后战斗策略、武器选择、目标筛选、弹道与伤害估算的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 首要目标是只攻击威胁我方基地的机器人，并在合法动作、响应时限和存活之间取平衡。
- 战斗结算、隐藏信息与机器人行为由官方引擎负责；本模块只基于当回合可见状态生成动作。
- 经济、建墙和任务求解分别由其他模块负责，战斗模块只消费它们产生的建筑、角色与资源状态。

## 当前策略

- 通过 `targetTeam` 识别威胁我方的机器人；字段缺失时才以双方基地距离做兼容推断。
- 在最多三名角色、三座武器间枚举共同操作位与分组，优先保持当前火力和完整覆盖，再减少操作员；默认优先工人，无法共同覆盖时使用两人或三人。
- 加特林使用直射弹道和锥形目标约束；电磁炮沿射线按剩余能量估算穿透收益；火箭按中心与邻格溅射估算收益。
- 炮塔、角色和范围物品都执行阵营隔离，避免攻击对方一路的机器人；没有安全弹道时宁可少开火。
- 攻击前统一经过指令账本校验：昼夜、射程、冷却、操控者、目标数量、坐标与单角色单动作约束。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| 武器数量 | 最多三座 | 遵守规则上限，也使角色与武器分配可小规模穷举 |
| 加特林夹角 | 任意两目标方向点积不小于 0 | 保证输出目标落在不超过 90° 的锥形范围 |
| 火箭伤害估算 | 中心 20、邻格 10 | 延续当前协议与实现假设；仍需官方引擎校准 |
| 电磁收益 | 沿线按距离与剩余生命分配能量 | 避免把穿透伤害重复计算到已被计划击杀的目标 |
| 不安全弹道 | 放弃攻击 | 避免帮助对手清理其来敌，优先保证阵营隔离 |

## 已知风险与验证

- 火箭只评估当前机器人格，可能遗漏更优空格落点。
- 多武器同回合的过杀、穿透和实际结算顺序仍是近似。
- 缺失 `targetTeam` 时的距离推断只是兼容路径，不应替代正式字段。
- 回归应覆盖三类武器、各等级目标数、遮挡、冷却、镜像地图、两路混合机器人与大波次耗时。

## 变更记录

### 2026-09-17 - 重新实现单工人多塔与稳定换岗

- 策略：以 `personal/cyf-develop@3cbdc41` 为基线重新实现，允许范围内三座炮塔共用一个工人。每塔仍独立检查冷却、射程、目标与阵营；只有成功加入账本的攻击才计入跨塔预估伤害。
- 设定：`shared_operators=true` 默认开启，设为 `false` 恢复一人一塔。控制锁与个人动作锁区分，同一人可控制多个不同炮塔，但不能同时移动、采集或使用物品，每塔每回合至多一条指令。
- 原因：原来三人守三塔会占用经济和任务人力。按“人、站位、覆盖塔集合”调度，移动只发一次，冷却时不因升级物品离岗，夜间优先保持已有岗位；分组变化才新增日志。
- 经验教训：公共站位被占不能瞬移换岗。工人血量不高于 165 时先引导健康替补靠近；替补就绪后才让原工人离岗。唯一站位交换仍有实际移动造成的火力间隙；不高于 70 血且持药时优先急救并重算覆盖。空闲工人阻塞回防时，在不增加近敌风险的前提下让路。
- 验证：`test_shared_operators.py` 覆盖三塔同控、重复指令、双向动作互斥、冷却/射程/过杀、阵亡、堵路、换岗、兼容开关及“开火、采矿、任务并行”。本地协议测试不代表官方引擎结算确认，仍需实战核对三条同控制者攻击的反馈。

### 2026-09-16 - 夜间战斗诊断

- 策略：逐夜间回合记录基地、敌人、墙体和炮塔状态，并关联上一回合攻击结果与防御动作反馈。
- 设定：夜间及 tick 0、69 输出 battle_state；记录炮塔等级、火力、射程、冷却、操控者、目标和未开火原因，近基地敌人明细最多 12 个。
- 原因：区分缺乏操控者、正在赶路、冷却、射程不足和无安全目标等不同火力问题。
- 经验教训：只记录指令数量无法解释基地受损；必须把实际攻击与可观察障碍联系起来。
- 验证：PR #13 的 Python strategy checks（run 35053714092）已通过，其中第三夜诊断用例检查基地血量、墙体等级、冷却原因和操控者；日志不等于官方结算结果。
