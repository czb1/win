# 按夜晚截止时间安排经济和升级

> 本文保留上一版的策略与测试记录。当前默认已改为第 70 回合首夜，批量与采矿规则也已更新，见 [持续采矿与第 70 回合备战](steady-mining.md)。

对比基线：`3ecee1c4d6f4b4733700a849bb463e2b52c521cf`。本次修改经济调度，战斗选敌和自进化解题逻辑保持原有实现。

## 目标与取舍

目标是夜晚开始时拥有尽可能强、已经升级且有角色操控的武器，同时保留持续收入。剩余金币本身不是胜负目标；矿石仍在背包里、升级券尚未使用，都不等同于当晚可用的火力。

默认编号下，第 1—70 回合是白天，第 71 回合开始首夜。提前建造不会在白天产生收入，因此有正常矿区和小贩时，默认让两名工人先挣钱。第 40 回合是经济窗口的上限，而非无条件等待的闹钟：远商店需要提前准备。

按当前配置中沿用 demo 的每座武器 25 金币，以及任务书中 100/150 金币的两级升级券计算：

| 目标 | 累计投入 | 扣除初始 75 金币后需要收入 |
|---|---:|---:|
| 三座一级武器 | 75 | 0 |
| 三座武器全部二级 | 375 | 300 |
| 三座武器全部三级 | 825 | 750 |

武器建造费用和默认合法区域仍是原项目的推导值，正式规则需由官方判题器或配置确认。不能把上述投入估算当作官方建造参数的独立验证。

## 当前策略

1. **双工人经济开局。** 无紧急治疗需求时，经济窗口内两人都采矿和出售。没有固定的“建筑工”或“采购工”。矿区评分包括工人到矿区、矿区到小贩的可达路线，并按每个矿最多十次采集摊销运输时间；使用当前回收价。
2. **倒推准备时间。** 每回合估算卖矿、到店、批量购买、回基地、使用升级券及回防所需时间。建造与采购可并行，按较长的工作链保留时间和 `return_margin`。准备起点至多是当日第 40 个经济回合；路线变长可以提前，同一天不会反复退回经济阶段。
3. **先兑现最后一批矿石。** 接近准备时间或回防时间时，不足普通出售批量也会卖。已经开始的卖矿行程会持续到背包中可售矿石卖完，避免因为附近刷新矿区而折返。进入准备阶段时，两人的经济库存都先兑现，减少公共金币尚未到账导致的拆单采购。
4. **按位置临时分工。** 选择当前能完成购物交付、路程较短的工人采购，其他工人按现有材料和距离接建造任务；没有待办任务就继续挣钱。允许一个工人买升级券、另一个同时建炮台。买券时为仍待建的炮台保留金币。
5. **批量买券、顺路交付。** 一次买入本次资金、背包和剩余时间容许的多张同级券。在已持有一级券足以覆盖相应武器时，可在同一次购物行程继续买二级券。依据全队背包扣除已有券，避免重复购买；配送同级券时优先较近的目标。
6. **武器优先。** 三座武器的一级升二级在前，二级升三级随后，健康基地升级再后。重伤基地升级回血、受伤角色治疗保留优先级；不再让满血工人专程买备用药，不自动给健康围墙逐座买升级券。
7. **围墙按资金和工时安排。** 武器尚未全部升满时，经济地图只安排迎敌侧墙段，后侧墙延后。临近夜晚仍有缺口时，两名空闲工人可一起补墙；按剩余运输和建造时间计算石料批量，避免反复单块运输。墙位蓝图仍是原来的 18 格，但不承诺首日全部完成。没有可达交易机会的地图继续使用完整建墙策略，以免工人空等。

`economy_rounds: 40` 可调整经济窗口上限；`sell_batch: 12` 是普通出售批量下限，`sell_batch_max: 40` 是根据卖矿路程增大批量后的上限。截止时间、满背包或关键资金需求可以触发更小批量出售。未加入新字段的旧配置会使用这些默认值。

这是基于可见状态、运输成本和截止时间的可执行策略，不是对所有随机地图、矿价、对手行为和任务奖励的全局最优证明。

## 验证范围

新增 `tools/day_economy_benchmark.py` 从 **75 金币、两名工人、一名开拓者、没有武器** 的状态开始，独立应用移动、每矿十次采集后刷新、买卖、建造与升级规则。记录第 40 和第 70 回合的现金、累计收入、实际武器等级、操控者到位情况、围墙和未使用升级券。提供近商店、远商店、远铜矿和左右镜像场景。

它不模拟机器人战斗、任务奖励、官方随机地图或对手，不用于计算胜率。三座武器就绪也不能证明一定能扛住某一波怪物。原五天回放则使用初始三座一级武器、固定价格和无限矿藏，与新增开局场景分别记录。

近商店、有限矿藏开局的最终对比：

| 指标 | 旧版 | 本次修改 |
|---|---:|---:|
| 第 40 回合累计卖矿收入 | 120 | 320 |
| 首夜武器等级 | 1 / 2 / 2 | 2 / 2 / 2 |
| 首夜操控者到位 | 3 | 3 |
| 首夜迎敌侧围墙 | 6 | 5 |
| 第二夜武器等级 | 1 / 2 / 3 | 2 / 3 / 3 |
| 第三夜武器等级 | 1 / 3 / 3 | 3 / 3 / 3 |
| 第三夜操控者到位 | 2 | 3 |
| 三天累计卖矿收入 | 840 | 1160 |

远商店场景中，动态准备的首夜武器为 `1 / 1 / 2`；同一实现强制第 40 回合才准备，则为 `1 / 1 / 1`，并剩余 320 金币。说明现金未转化为火力是实际风险。远铜矿场景改为主要采近处铁矿，首夜等级维持 `1 / 1 / 2`，现金由 24 增至 86，但迎敌侧墙由 6 减至 5；不能据此宣称生存能力全面优于旧版。

原五天无限矿藏回放中，两版最终三座武器与基地都达到三级：剩余金币 `1190 → 3390`、采矿动作 `271 → 447`、移动动作 `318 → 139`。新版本购买一次药剂、八张武器/基地升级券，不购买健康墙的升级券。该回放不是上述从零建设的首日场景。

本地 Python 3.12.14，132 项测试通过，完整输出见 [deadline-economy-test-output.txt](deadline-economy-test-output.txt)。CI 仍使用比赛指定的 Python 3.11.10。输出开头的无效请求异常来自 HTTP 错误处理测试，该测试预期返回兼容协议的空响应。

完整数据见 [deadline-economy-benchmark.json](deadline-economy-benchmark.json)。测试保留协议、寻路、战斗、自进化和无交易地图的连续防线回归，并新增经济开局、资金预留、批量券、已有库存去重、紧急治疗、部分矿石变现、跨日重置、单工人串行工作和首夜可用火力验证。

复现：

```bash
python3 -m unittest discover -s tests -v
python3 tools/day_economy_benchmark.py --days 3
python3 tools/day_economy_benchmark.py --mirror
python3 tools/day_economy_benchmark.py --case far_shop
python3 tools/day_economy_benchmark.py --case far_shop --fixed-40
python3 tools/day_economy_benchmark.py --case remote_ore
python3 tools/progression_benchmark.py
```

加上 `--agent-root /path/to/baseline` 可用同一个回放器比较旧代码。`--fixed-40` 仅在该回放进程中关闭动态提前准备，作为固定时间策略的对照，不修改比赛代码。
