## 样例修复

`request.txt` 的 `teamEnemy.roles` 最后一个元素后有末尾逗号。`examples/request.json` 仅删除这一非法逗号并重新格式化，没有擅自填入未知的 `targetTeam` 或其它字段。

`response.txt` 包含重复角色键，且召唤宝藏样例的 `targetPos` 和 `item` 之间缺逗号；接口文档已说明它用于罗列多种动作，不是单回合可直接发送的响应。本项目的 `examples/response.json` 由程序真实运行生成。

样例中的 `medicine` 与商店的 `Medicine` 大小写不同。项目按商品及物品原名精确匹配，不擅自把大小写不同的未知物品当成同一种。若平台存在正式别名，应由接入层增加有依据的别名映射。

## 相比上游 demo 的主要变化

- 补齐独立根目录启动脚本、图片指定入口和完整响应三字段。
- 敌方单位占地与基地完整四格进入移动障碍集合。
- 正确处理起终点相同、无可达邻格和本回合目标格冲突。
- 用统一账本管理共享金币、建造数量、购买预留及操控者占用。
- 按武器等级生成多个落点，加入锥形限制、穿透／溅射估算和冷却检查。
- 增加资源交易、升级券、日落返防、任务多轮交互、新闻记忆和宝藏流程。
- 增加指令失败退避、重复请求缓存、错误请求恢复与自动化测试。

## 未确认规则与处理方式

|---|---|---|
| 精确建造区域 | 任务书只给内网图片；默认根据基地生成内外圈，非已确认坐标 | 提供图或引擎定义，配置显式白名单 |

| 弹道起点与边界 | 任务书示意图文字可能指角色位置；demo 以武器位置计算范围 | 与判题器对齐，必要时调整 `line_cells` 调用 |

| 任务成功判据 | 无显式成功布尔值或稳定任务 ID | 提示缓存标记未验证，不依据任务消失宣称成功 |
