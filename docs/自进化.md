# 自进化模块设计

本文是自进化模块唯一的长期设计文档。以后任务状态机、模型交互、沙盒执行、经验复用、新闻与记忆策略的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 把模型限制在提出单步查询、代码或答案，确定性的时限、格式校验、执行结果判断、提交和记忆管理由程序负责。
- 只保存有可观察证据的经验，不把一次合法动作或相似题猜测包装成已验证能力。
- 官方沙盒执行模型代码；HTTP 宿主不使用 `eval`、`exec` 或本地子进程执行模型输出。

## 当前策略

- 流程为：领取任务、读取题目、请求单步模型输出、校验并发送沙盒、检查结果、提交答案、观察下一回合反馈。
- 明确给出本地文档路径时先让官方沙盒读取；否则允许模型用受限的 `LIST`、`READ` 步骤发现资料。
- 题目只给相对文件名时（包括“请阅读task_1_alpha.md”这种中文紧贴文件名的原文），程序在任务沙盒根目录内进行有界唯一匹配并直接读取；模型发起的相对 `READ` 优先使用本任务已经解析出的目录。跨任务不复用 `/tmp` 绝对路径。
- 固定保留任务入口文档，从其“提交规则／提交格式／提交形式／答案格式／答案输出格式”提取 JSON 示例（支持列表内缩进代码块），区分任务要求与 API 返回数据；不把 API 文档中泛称的“输出格式”用作提交约束。字段结构确定时拦截规范正文、多余包装键和错误类型，允许先提交已求得的部分字段。
- 入口文档明确引用的辅助文档自动读取至多两份；模型 Python 每次自动切换到本题入口目录（部署题为明确工作区），不依赖进程默认目录或上次 chdir。
- 对文档明确要求 `spec.md → 修复文件 → ./check → {"token": ...}` 的部署题，先运行确定性 SOP：按当前规范建目录、修改指定配置行、设置权限，再运行检查器。遇到未知要求时交给模型修复，并由独立的固定命令再次执行检查器；模型猜测或自行打印的 token 不直接提交。
- 支持结构化答案、Python 代码和弱模型常见包装，但拒绝冲突对象、非法 Python、截断输出与来源不明的跳回合结果。
- 只有退出码为 0、输出完整且带最终答案标记时才可从沙盒结果自动提交。
- 模型查询由沙盒内包装器记录 requests/urllib 的 HTTP 错误及 requests JSON 解析／明确业务失败，即使模型捕获异常或自行打印最终答案，本次仍失败。失败状态跨回合保留，阻止随后由模型复述错误统计；成功重新查询后才解除。独立部署检查器通过也可解除与其无关的查询失败。
- 成功经验的保存需要提交后题目消失、没有错误、角色仍处于可信状态等联合证据。精确复述当前成功沙盒 JSON/标量的模型答案可继承执行证据；无依据答案不生成 Skill。
- 模型用 `skill + inputs` 提出参数化 Python 方法并在本题执行，完成后保存未绑定参数的程序、参数类型、接口调用方式和验证步骤；不保存旧任务原文、旧输出、绑定后的程序或参数值。后续用 `use_skill + inputs` 重新绑定本题全部参数，官方沙盒执行同一方法。
- 普通 Python 解题也会留下已成功调用的接口地址、HTTP 方法、认证方式和参数名（不记录请求值或响应）；没有参数化程序的记录仅作方法提示，不能当可执行 Skill。部署题继续按当前规范使用确定性 SOP，检查程序本身不冒充通用修复程序。
- Skill 按任务点及答案字段类型匹配，仍由模型对照当前文档选择。执行失败或判错后停用，被修正的方法必须再次执行并完成任务才可恢复；最多保存 8 条、提示最近 2 条，合并重复方法的成功次数及最近 3 次耗时。
- Skill 存在当前比赛会话的 Memory 中，跨本局任务和游戏日复用；不跨队伍、进程重启或比赛持久化。参数化/结构检查是质量门禁，不是任意 Python 的语义正确性证明。
- 新闻、提示、输出和历史条目都有数量与长度上限；跨日重置普通模型配额，任务交互按规则豁免。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| `daily_llm_limit` | 3 | 遵守普通模型调用上限，任务交互按规则单独处理 |
| `task_min_rounds` | 12 | 避免在剩余时间过短时领取无法完成且会影响回防的任务 |
| `task_max_rounds` | 1300 或任务点超时 | 不用本地固定短上限提前终止长任务，同时服从真实期限 |
| `task_danger_radius` | 6 | 在没有完整机器人路径预测时提供最低回防预警 |
| 重复提案 | 同一答案或代码最多采纳两次 | 限制无进展循环，但格式失败不会直接让角色离场终止任务 |
| 截止降级 | 同时使用任务超时与首夜回防期限；余 7 回合提示停止探索，余 4 回合拒绝 `READ/LIST`，余 2 回合只向普通题模型索取答案，余 1 回合不启动新交互 | 模型与沙盒结果都在下一回合返回，必须为实际提交保留回合；部署题另计独立检查的往返 |
| 部署 SOP | 完整解析规范后才修改；只支持明确的目录／指定行／权限要求；检查器限 8 秒、输出限 16000 字节，退出 0 且恰好一个 `TOKEN:` 才提交 | 用确定性步骤解决实战已知题型，未知规范保留给模型，避免写死应用名、端口或 token |
| 已学会题型排序 | 同任务点最近至多三次部署 SOP 的最长完成观察时长 + 2 回合，仅用于候选价值排序 | 不再把已快速完成的题型一律按官方最坏超时计价；不缩短实际任务上限或回防余量 |
| 历史证据 | 成功执行并观察到任务正常消失 | 合法提交不代表答案正确，必须等下一回合状态确认 |

## 已知风险与验证

- 没有请求 ID 时无法可靠归属跨多回合迟到结果，跳回合结果必须丢弃。
- 相似题经验只能作为候选步骤，不能直接复制旧参数或旧答案。
- 固定模型回复的回放只能验证状态机，不能代表弱模型理解任意题目的成功率。
- HTTP 包装器用于发现常用客户端的明确失败，不是任意模型代码的安全隔离或正确性证明；不覆盖子进程、自定义客户端和所有业务错误结构。成功响应仍需模型验证字段、分页完整性和统计逻辑，不能证明实际数据正确。
- `task_outcome` 记录完成观察、交互次数、提交次数、拒绝次数、耗时和队伍金币／积分变化；队伍增量同时受采矿、采购、战斗等影响，不能直接视为本任务收益。
- 确定性部署 SOP 只覆盖已读规范中明确支持的语法；未知条款、缺失且内容未定义的脚本、越出当前任务目录的工作区不会被自动猜测修复。未知规范退回模型，纯检查步骤不会被保存成已经学会的修复流程。
- 回归应覆盖格式恢复、重复输出、沙盒失败/超时/截断、分页读文档、提交反馈、死亡/离场/超时、跨日配额和经验污染防护。

### 2026-09-22 - 弱模型宝藏分项线索记忆

- 策略：保持每次一轮新闻调用和现有配额，在原有 JSON 中增加可选 treasureClues，分别提取用品、地点、时间。完整宝藏计划仍走原校验和原执行流程；部分线索不触发购买、移动或召唤，也不改变防守、自进化优先级。
- 设定：提示中补齐任务书六种祭品的中文名称、外观与英文商品名，仅展示当前商店存在的条目，保留协议拼写 AcientTablet。提示要求逐字引用来源天数的民间传闻，并区分原文与候选解读；有冲突或缺坐标/时间时保留线索、treasure 为 null。官方新闻相对日期按来源 day 解释，删除易被照抄的固定停产日期示例。
- 设定：每条线索 kind/day/quote/meaning，引用 4–500 字、解读 1–300 字；程序核对引用确实存在于对应天数的民间传闻或已验证引用中，每类至多6条、每次最多处理18条。相同来源更新，不同来源保留供比较；null/空列表不清除积累。仅本局内存保存，自进化切题不清空，队伍和新局仍按原会话隔离。
- 原因：实战前五天累计输入仅约1954字符，新闻调用正常但缺少坐标和时间，旧输出只能为 null，无法观察或利用部分理解。商品描述已经在任务书中，先提供这份确定知识，降低弱模型仅凭英文名猜祭品的难度。
- 经验教训：原文引用通过校验只证明出处，不证明模型解读正确；候选线索不能视为已验证的执行计划。缺少关键情报时不能承诺五天内开宝藏，不以提前采购占用防守资金。新日志 event=treasure_clues 沿用 [TREASURE_TRACE]，明确标为 hints_only_not_actionable。
- 验证：增加五天含噪声/空结论/切题回放、伪造引用和错误类型拒绝、有界去重与冲突保留、部分线索对动作及配额无影响、完整旧协议兼容测试。固定模型回复仅验证状态机与边界，不等于实战模型成功率；完整检查结果记录在提交说明。

### 2026-09-20 - 弱模型 A 类连续查询与完整分页

- 原因：本次三份实战日志中，A-2/A-3 只说明接口与前题相同，没有再给 API_DOCS.md 文件名；每题清空 documents，而首题没有完成确认，previousSolutions 为空，模型重新猜路径直到超时。A-1 已观察到 data.records 和 pagination 的 offset/limit，却继续用 page/size，最终只统计了总计 15 条中的前 10 条。
- 策略：增加窄范围的文化遗产查询 SOP，匹配当前题目语义与五个提交字段才启用。接口、城市和凭据均绑定当前已读文档；从 curl 示例提取配置而不执行 shell。保持 B 类工程修复 SOP 与未知任务的模型求解入口。
- 设定：后续题明确说明 API 相同、同一任务点且当前入口与历史辅助文档在同一目录时，只复用文档位置并重新 READ。即使前题没有完成也能找回接口说明；不复制旧正文、城市或凭据作为本题输入，不跨工作区盲用旧路径。
- 设定：查询在官方沙盒内一次完成，最多 12 秒、200 页、单响应 1 MB。仅按 401 明确要求改为 Bearer、400 明确要求改为 location，修正后重新成功请求；其他错误直接失败。按真实 offset/limit 分页，核对 total_count 稳定、offset 前进、记录 ID 不重复、字段齐全与最终记录数；中途出错不输出 FINAL_ANSWER。已处理的认证协商不豁免后续查询失败，也不改变普通模型代码的 HTTP 失败拦截。
- 设定：年代按已知历史时期排序，复合年代取最早时期；不认识的年代或空集合不编造 oldest_era，只提交有依据的字段。SOP 每题最多自动尝试一次，未知 schema 或失败交回模型并阻止未重查的答案；模型上下文中的旧探索只保留最近两条有界输出摘要，不再重复堆叠旧脚本和当前 lastAttempt。
- 经验教训：不能依赖弱模型主动生成参数化 Skill 才保留接口入口；成功方法与文件位置证据可以分开。API 分页必须以服务实际元数据为准，不能把短页或默认第一页当成完整结果。自动化应收窄到能验证的协议，不猜任意接口，不写死北京数量或密钥。
- 验证：新增独立 HTTP 服务与三题连续回放，服务端限制每页两条，三题更换城市及凭据、不提供模型回复、不提供前题完成信号，仍应每题三次沙盒调用后提交。覆盖认证/参数纠正、重复页/ID、总数变化、缺字段、错误结构、后页失败、空页、空集合、未知年代、跨点/目录隔离、服务变化和失败后回退。仓库 .venv 为 Python 3.11.16；快速检查 266 项通过，完整检查 274 项通过，0 失败、0 错误、0 跳过，8 项多日回放全部保留，独立策略基准 PASS（74.81 秒），日志为 artifacts/validation/full.log。git diff --check 通过；没有新增依赖。
- 验证边界：HTTP 服务使用独立测试数据，不是比赛真实 localhost:8899；不承诺未知接口或任意模型的实战成功率。文档格式、响应结构或年代超出 SOP 支持范围时仍需模型处理，跨进程重启不保留本局文件位置。

### 2026-09-16 - 任务文件自动定位与截止降级

- 策略：相对题目文件由确定性沙盒代码在 `/tmp/selfEvolutionTask` 下有界定位并读取；不再把同一任务点上一次执行的绝对临时路径注入新任务。根据剩余回合逐步收窄到可直接产生最终答案的动作。

### 2026-09-20 - 用运行时结构证据打断 200 后解析循环

- 策略：成功 HTTP JSON 响应由沙盒包装器自动提取无值的结构摘要；解析异常时将该摘要绑定到 `lastAttempt`。对异常类型、归一化消息和接口调用元数据生成失败指纹，识别“代码表面变化但失败假设相同”的重复循环。
- 设定：`jsonShapes` 最多记录 4 个响应；字典最多 20 个键、递归深度 4，列表记录长度、最多 8 个样本的类型集合与首项结构；不记录标量响应值、请求参数值、认证凭据或响应正文。重复两次相同语义失败后，只允许按已观察结构修正 records 路径和类型守卫，禁止继续猜 `data/results` 包装。
- 原因：A-1 实战已经完成 401→Bearer、400→`location` 的纠正并取得 HTTP 200，但随后把包装对象当作记录列表，最终在记录访问时连续出现 `AttributeError: 'str' object has no attribute 'keys'`。模型多轮生成相似的大型聚合脚本，却没有先取得响应结构事实。
- 经验教训：HTTP 200 只证明传输成功，不证明 response schema 假设正确。未知接口的结构事实应由运行时自动采集，而不是依赖弱模型主动打印；仅按代码哈希也不足以发现表面改写后的重复失败，应按异常语义和接口调用形成指纹。
- 验证：新增回归覆盖 `jsonShapes` 传递、HTTP 成功后的解析异常、不同代码文本的同语义失败计数，以及重复失败后的 schema-guided 提示。最终完整验证使用本分支 GitHub Actions 的 `Python strategy checks`。
