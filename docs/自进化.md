# 自进化模块设计

本文是自进化模块唯一的长期设计文档。以后任务状态机、模型交互、沙盒执行、经验复用、新闻与记忆策略的变更都直接更新本文，不新建设计文档。

## 目标与边界

- 把模型限制在提出单步查询、代码或答案，确定性的时限、格式校验、执行结果判断、提交和记忆管理由程序负责。
- 只保存有可观察证据的经验，不把一次合法动作或相似题猜测包装成已验证能力。
- 官方沙盒执行模型代码；HTTP 宿主不使用 `eval`、`exec` 或本地子进程执行模型输出。

## 当前策略

- 流程为：领取任务、读取题目、请求单步模型输出、校验并发送沙盒、检查结果、提交答案、观察下一回合反馈。
- 明确给出本地文档路径时先让官方沙盒读取；否则允许模型用受限的 `LIST`、`READ` 步骤发现资料。
- 题目只给相对文件名时（包括“请阅读task_1_alpha.md”这种中文紧贴文件名的原文），程序在任务沙盒根目录内进行有界唯一匹配并直接读取；模型发起的相对 `READ` 优先使用本任务已经解析出的目录。跨任务不复用 `/tmp` 绝对路径。
- 固定保留任务入口文档，从其“提交规则／提交格式／答案格式／答案输出格式”提取 JSON 示例，区分任务要求与 API 返回数据；不把 API 文档中泛称的“输出格式”用作提交约束。字段结构确定时拦截规范正文、多余包装键和错误类型，允许先提交已求得的部分字段。
- 对文档明确要求 `spec.md → 修复文件 → ./check → {"token": ...}` 的部署题，先运行确定性 SOP：按当前规范建目录、修改指定配置行、设置权限，再运行检查器。遇到未知要求时交给模型修复，并由独立的固定命令再次执行检查器；模型猜测或自行打印的 token 不直接提交。
- 支持结构化答案、Python 代码和弱模型常见包装，但拒绝冲突对象、非法 Python、截断输出与来源不明的跳回合结果。
- 只有退出码为 0、输出完整且带最终答案标记时才可从沙盒结果自动提交。
- 成功经验的保存需要提交后题目消失、没有错误、角色仍处于可信状态等联合证据，而且程序必须与本次提交的最终输出绑定；只运行检查器不算可复用的修复程序。保存时仍标记证据和未证明边界。
- 新闻、提示、输出和历史条目都有数量与长度上限；跨日重置普通模型配额，任务交互按规则豁免。

## 关键设定与原因

| 设定 | 当前值或规则 | 原因 |
|---|---|---|
| `daily_llm_limit` | 3 | 遵守普通模型调用上限，任务交互按规则单独处理 |
| `task_min_rounds` | 12 | 避免在剩余时间过短时领取无法完成且会影响回防的任务 |
| `task_max_rounds` | 1300 或任务点超时 | 不用本地固定短上限提前终止长任务，同时服从真实期限 |
| `task_danger_radius` | 6 | 在没有完整机器人路径预测时提供最低回防预警 |
| 重复提案 | 同一答案或代码最多采纳两次 | 限制无进展循环，但格式失败不会直接让角色离场终止任务 |
| 截止降级 | 同时使用任务超时与首夜回防期限；余 7 回合提示停止探索，余 4 回合拒绝 `READ/LIST`，余 2 回合只向普通题模型索取答案，余 1 回合不启动新交互 | 模型与沙盒结果都在下一回合返回，必须为实际提交保留回合；部署题另计独立检查的往返 |
| 部署 SOP | 完整解析规范后才修改；只支持明确的目录／指定行／权限要求；检查器限 8 秒、输出限 16000 字节，退出 0 且恰好一个 `TOKEN:` 才提交 | 用确定性步骤解决实战已知题型，未知规范保留给模型，避免写死应用名、端口或 token |
| 已学会题型排序 | 同任务点最近至多三次部署 SOP 的最长完成观察时长 + 2 回合，仅用于候选价值排序 | 不再把已快速完成的题型一律按官方最坏超时计价；不缩短实际任务上限或回防余量 |
| 历史证据 | 成功执行并观察到任务正常消失 | 合法提交不代表答案正确，必须等下一回合状态确认 |

## 已知风险与验证

- 没有请求 ID 时无法可靠归属跨多回合迟到结果，跳回合结果必须丢弃。
- 相似题经验只能作为候选步骤，不能直接复制旧参数或旧答案。
- 固定模型回复的回放只能验证状态机，不能代表弱模型理解任意题目的成功率。
- `task_outcome` 记录完成观察、交互次数、提交次数、拒绝次数、耗时和队伍金币／积分变化；队伍增量同时受采矿、采购、战斗等影响，不能直接视为本任务收益。
- 确定性部署 SOP 只覆盖已读规范中明确支持的语法；未知条款、缺失且内容未定义的脚本、越出当前任务目录的工作区不会被自动猜测修复。未知规范退回模型，纯检查步骤不会被保存成已经学会的修复流程。
- 回归应覆盖格式恢复、重复输出、沙盒失败/超时/截断、分页读文档、提交反馈、死亡/离场/超时、跨日配额和经验污染防护。

## 变更记录

### 2026-09-16 - 建立四模块文档基线

- 策略：把既有任务状态机、弱模型协议、沙盒校验、新闻记忆和经验复用归并到本文件。
- 设定：本文件成为自进化设计的唯一维护入口，后续不再新建自进化设计文档。
- 原因：让模型协议、可信证据和失败处理在同一处维护，避免临时修复文档互相覆盖。
- 经验教训：一次执行成功或一次合法提交都不足以证明答案正确；经验必须绑定下一回合的可观察结果。
- 验证：本次为文档与门禁变更；由 `design-governance` 检查文档结构和更新纪律。

### 2026-09-16 - 任务全链路诊断日志

- 策略：任务开始时记录完整题目，并记录模型回复、沙盒结果、答案提交、拒绝原因和后续反馈。
- 设定：模型回复日志截取 16000 字符，沙盒输出 12000，提交答案 4000，拒绝原因 1000；完整题目仅在任务开始时记录。
- 原因：下载运行日志后能还原任务失败阶段，而不是只能看到重试计数。
- 经验教训：提交成功和任务完成是不同事件，必须保留下一回合反馈与任务是否仍活跃的证据。
- 验证：PR #13 的 Python strategy checks（run 35053714092）已通过；本次补记现有日志行为，不改变任务状态机，不把日志完备性视为解题能力提升。

### 2026-09-16 - 保留完整题目的紧凑任务日志

- 策略：每个自进化任务开始时仍在 INFO 原样记录完整题目；模型回复、沙盒结果、提交答案和重复拒绝改为有界摘要，完整正文只在 DEBUG 保留。
- 设定：模型回复和答案摘要最多 256 字符，沙盒失败保留最多 512 字符的输出尾部；所有大字段同时记录字符数和 12 位 SHA-256 摘要。成功沙盒只记录状态、工具、路径、长度和是否产生最终答案。
- 原因：题目是分析任务成败不可替代的上下文，必须保留；模型代码、成功文档回显和重复答案可用类型、长度、哈希及短摘录定位，无需全量复制。
- 经验教训：压缩不能删除问题本身，也不能截掉 traceback 尾部；对运行中间产物设置边界才可兼顾可分析性和下载体积。
- 验证：新增回归使用长题目、长模型回复和长沙盒错误，确认题目全文存在，同时 INFO 尝试行保持长度上限并保留错误尾部。

### 2026-09-16 - 任务文件自动定位与截止降级

- 策略：相对题目文件由确定性沙盒代码在 `/tmp/selfEvolutionTask` 下有界定位并读取；不再把同一任务点上一次执行的绝对临时路径注入新任务。根据剩余回合逐步收窄到可直接产生最终答案的动作。
- 设定：目录遍历最多观察 2000 个条目、匹配最多 20 个且最终必须唯一；剩余 7 回合只允许答案或最终 Python，剩余 4 回合禁止 `READ/LIST`，剩余 1 回合只允许 `ANSWER`。
- 原因：实战 6 个任务全部失败，主要表现为相对路径读取失败、复用已删除的 `ws_2` 路径，以及连续探索直到任务截止。
- 经验教训：任务点相同不代表沙盒目录稳定；有正确文档也不代表有足够时间继续多步查询。
- 验证：新增旋转沙盒目录、旧路径隔离和临近截止格式回归；现有读取、查询、提交和反馈回归继续通过。

### 2026-09-17 - 修通实战任务入口并建立部署题完成流程

- 策略：先恢复任务资料与提交要求的完整链路，再将已知部署题收敛为固定 SOP。新分支为 `codex/evolution-task-completion`，从 `codex/night-shared-operators` 的 `c1b267a` 创建。本次核对任务书第 5 章、第 6 章以及接口的 `phaseTask`、`lastCmdResult`、`timeoutRounds`、`errors`、`submitAnswer` 约定。
- 设定：修正文件名提取的 Unicode 边界；所有相对 `READ` 共用有界定位并优先解析当前任务目录；最多读取 6000 字符一页，搜索达到限制直接报告不完整，不能把被裁剪搜索中的一个匹配误认为唯一文件。入口文档和独立的提交格式在后续翻页、格式重试时继续保留。
- 原因：直接核对 `docs/log091601.txt` 中两段任务后，确认以下失败链条：
  1. 第 10 回合的“请阅读task_1_beijing.md”与第 30 回合的“请阅读task_1_alpha.md”中，中文紧贴文件名。旧正则使用 `\w` 边界，而中文也是 Unicode word 字符，因此返回 `None`，之前增加的自动定位实际上没有触发。
  2. 模型返回 `READ task_1_*.md` 后仍调用只读取当前目录的旧工具。沙盒当前目录为 `/`，文件实际位于 `/tmp/selfEvolutionTask/...`；随后模型从根目录递归搜索，出现两次 15 秒超时，天气题在第 24 回合停止且未提交答案。
  3. 部署题在第 34 回合由模型自写 Python 找到了入口文档。旧记忆只把固定 `READ/LIST` 的输出保存为文档，随后读取 `spec.md` 时入口中的提交规则被覆盖。第 37 回合开始把规范正文当答案，继而提交额外的 `task/result` 包装和编造的 `alpha-2023-v1`。日志明确返回“答案不是合法 JSON”“缺少 token”“多余 task”等错误；没有实际修复文件或运行 `./check`，第 44 回合停止。
  4. 现有“剩余回合”只告诉模型任务超时，未把首夜回防截止带入交互预算；最后一个可用回合仍可能启动模型调用，回复抵达时已经不能提交。任务书明确允许部分完成按正确字段比例获得金币／积分，接口明确超时保留历次提交的最高通过率，因此应尽早提交已有证据的字段并继续补齐。
- 设定：部署 SOP 每次从本题入口重新绑定工作区，并读取本次 `spec.md`。支持建目录、修改配置指定行、设置脚本权限，保留其他配置行和脚本内容；不修改 `spec.md` 或 `check`。规范全部识别、文件检查通过后才执行修改，检查器退出 0、输出完整且唯一 `TOKEN:` 才组装只含 `token` 的 JSON。模型后续修复的结果也必须经过固定检查命令确认。
- 策略：从题目明确的提交章节识别字段结构，拦截读文档回显与额外包装键；允许非空的正确字段子集立即提交，收到错误 2 后继续求解，不将合法动作误当成答案正确。领取任务时优先考虑已观察到快速完成的部署 SOP，用最近三次最长耗时加 2 回合作为排序估计，保持原有领取余量、真实超时和防守规则。
- 经验教训：修复函数存在不代表实战入口能走到它，回归必须包含原始中文题目和真实的异步往返。工具返回 0 只证明执行成功；任务资料、检查器 token、答案提交、任务完成观察是四种不同证据。保存经验时绑定本次最终输出的程序，不再用任意一次成功读文件或旧代码冒充解题经验。纯检查程序不具有修复能力，不保存为修复 SOP，也不会给该任务点增加“已学会快速修复”的排序依据。
- 验证：新增 `tests/test_task_completion.py` 的 19 项回归覆盖原文入口、当前目录绑定、多文件歧义与搜索裁剪、独立检查器、两套应用／端口／工作区、未知规范恢复、伪造 token、失败／重复／过长 token 输出、部分答案补交、任务排序、文档翻页和首夜回防截止，以及 API 输出格式不会误作答案格式。受控部署回放在第 1 回合领取、第 2 回合读题、第 3 回合修复并检查、第 4 回合提交、第 5 回合观察完成，共 0 次模型调用、2 次沙盒调用、1 次提交；第二套参数得到新的 token。
