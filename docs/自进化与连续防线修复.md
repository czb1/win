# 自进化与连续防线修复

本次以 `767b72d494fd5772eccd61d4df27bb4f17de1909` 为基线。没有收到实际失败对局请求、LLM 回复或沙盒日志，因而这里只报告从源码和协议可以确定的问题，以及离线复现结果，不宣称已解决所有线上任务或提高实战胜率。

## 确认的问题与修正

| 问题 | 原因 | 当前处理 |
|---|---|---|
| 建墙顺序不朝向来敌方向 | `build()` 先按步行距离排序，覆盖蓝图顺序 | 基地在地图左侧先右墙，在右侧先左墙；同侧先补两段墙之间的缺口，再按连续蓝图延伸。显式坐标也遵守方向优先级 |
| 迎敌面中间总有洞 | 为加特林、电磁炮主动删除射击口 | 不再删除任何迎敌面射击口，默认三座火箭台越墙射击 |
| 即使去掉射击口仍补不齐 | 原炮台散布切断内圈通路；角色可能一直站在墙位上 | 炮台集中到迎敌侧，特意留出操控通路；验证内圈全部可达及三个不同操控位；空闲角色让出规划格 |
| 自进化多次输出格式错误后直接失败 | 三次无效提案就让开拓者离开任务点，按规则任务立即结束 | 同内容仍最多采纳两次，但无效格式触发最小步骤修复提示，不再直接离场 |
| 长任务提前结束 | 本地默认上限固定 40 回合，且从看到题目而非领取动作开始计时 | 默认政策上限为整局 1300 回合，优先使用该任务点 `timeoutRounds`；记录真实领取回合；仍为夜间回防预留时间 |
| 沙盒已经算对，模型转述又出错 | 执行结果必须再发给 LLM 才能形成答案 | 支持显式 `FINAL_ANSWER` 标记；仅退出码为 0、输出完整时直接提交 |
| 弱模型重复犯错、旧信息丢失 | 提交反馈只存在当回合，长输出只截取头部；成功解法未自动记录 | 保留拒绝反馈和输出头尾；记录已成功执行、且合法提交后任务正常消失的历史代码及输出，供同任务点相似题参考 |

自进化的经济调度、任务期限、代码语法校验、退出码检查、提交和记忆管理都由程序负责。模型只需查询给定 API/文件、修改本题参数、产生最终答案；不让模型规划墙坐标，也不要求它额外撰写 skill。

## 防线取舍

默认外围仍沿用 demo 推导的“距基地完整 2×2 占地两格”的矩形，20 个外围格仅保留背敌侧两格运输通道，共 18 个墙位。先从迎敌侧中心向两端铺满六格，再从前向后延伸上下侧翼，最后补背侧。地图边界放不下背侧通道时，选侧翼靠后位置，不在迎敌侧竖墙开口。

**运输通道是明确保留的入口，并不是完全封闭城墙。** 完全封死会同时阻断采矿、购物、接任务和工人回防；这里修复的是迎敌面与侧翼的射击缺口、布局导致的额外缺口。复杂地形或显式坐标若会封死必要路线，连通性保护仍会拒绝该格。

炮台采用基地局部坐标 `(2, 0)`、`(2, -1)`、`(2, 2)`，坐标轴朝向地图中心并随基地镜像。保留 `(2, 1)` 作为操控/通行格；不能把三座炮台排在 `(2, 0..2)`，否则中间炮台会失去独立可用的操控位置。新布局通过完整内圈可达性和三个不同操控位的回归检查。

默认火箭台不受墙阻挡，但有三回合冷却。这个选择解决连续墙与直射武器的明确冲突，并未证明三火箭在所有机器人组合上最优。仍支持配置其他武器；使用直射武器时，应通过显式合法坐标配置相应弹道和通路。已有建筑不会被擅自拆除或移位，新布局主要用于新对局和后续建造。

## 自进化交互

典型流程：领取任务 → 题目进入 `phaseTask` → 请求模型 → 校验并发送沙盒代码 → 检查执行结果 → 提交答案 → 观察下一回合反馈。

模型示例输出：

```text
PYTHON
# 使用任务文档中真实存在的 API 或文件算出 answer
print('FINAL_ANSWER')
print(answer)
```

`answer` 在真实代码中必须先由任务结果计算出来。标记只能用于最终答案，探索文档和调试输出不要使用它。若任务要求 JSON，代码自行序列化正确的 JSON。

只有 `[exitCode:0]` 且没有 `[TRUNCATED]` 时才允许自动提交标记后的正文。普通 stdout、非零退出码、超时、判题器异常以及跳回合后的旧结果不会自动提交；它们会作为下一步修复的上下文。兼容原 JSON 包装、Python 代码块、`ANSWER: ...`、直接 JSON 答案等弱模型常见格式，仍拒绝冲突的多个对象和非法 Python。代码仅发往官方沙盒；HTTP 宿主不会执行模型代码。

合法动作并不表示答案正确，因此只有“上一回合提交合法、当前题目消失、没有错误、开拓者仍活着且仍在原任务点、未到超时”等条件同时满足，才保存有完成迹象的历史解法。记录保留 `verified: false` 和实际观察依据。下一道相似题得到该解法供修改参数，不自动重跑旧代码或复制旧答案。死亡、离场、超时、错误提交和跳回合不能污染经验库。

新增日志只记录任务开始/结束、重试次数、沙盒状态和提交事件，不打印完整任务或代码。日志可区分格式解析失败、沙盒失败和提交后仍未完成，便于后续对照真实对局定位问题。
